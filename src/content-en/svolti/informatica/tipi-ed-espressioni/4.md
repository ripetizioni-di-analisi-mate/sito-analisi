## Exercise 1

Determine `result` in terms of the maximum `unsigned int` value, `UINT_MAX`.
```c
unsigned int result = 4u - 11u;
```

Let $M=\mathrm{UINT\_MAX}+1$ be the mathematical number of values of the type. We obtain
$$
\begin{aligned}
4-11 &=-7,\\[6pt]
\mathrm{result} &= M-7=\mathrm{UINT\_MAX}-6 .
\end{aligned}
$$

<div class="spiegazione">

The suffix `u` gives both constants type `unsigned int`. Subtraction is performed in that type, so we seek the representative of the mathematical result in the interval from $0$ to $M-1$. The value $-7$ is negative. Adding the number of values $M$ yields $M-7$, which is in range because `UINT_MAX` is at least $65535$. Assignment preserves this result because the object has the same type as the expression.

To check, perform the inverse operation in `unsigned int` and add `11u` to the result. The mathematical total is $M-7+11=M+4$. Reduction modulo $M$ gives $4$, the first operand. This check requires neither fixing the width of the type nor evaluating the mathematical expression $M$ in C.

</div>

## Exercise 2

Determine the type of the expression on the right of the last declaration and the value of `total`.
```c
int change = -5;
unsigned int capacity = 14u;
unsigned int total = change + capacity;
```

$$
\begin{aligned}
-5 &\longmapsto M-5,\\[6pt]
(M-5)+14 &= M+9\equiv 9\pmod M .
\end{aligned}
$$
The type is `unsigned int` and `total` is $9$.

<div class="spiegazione">

`int` and `unsigned int` have the same rank. The arithmetic conversion therefore converts `change` to `unsigned int` before addition. Let $M$ be the mathematical number of values of that type. The representative of $-5$ is $M-5$. Adding $14$ gives $M+9$, greater than the maximum $M-1$. Reduction modulo $M$ gives $9$. `total` is initialized once `+` has already produced that value in the common type.

As a check, subtract five units from $14$ directly within the unsigned range. This gives $9$ without crossing below the minimum, and $9+5=14$ confirms the result. Both methods give the same representative because $M-5$ and $-5$ differ by exactly $M$.

</div>

## Exercise 3

The fragment must decide whether the balance `balance` is less than the limit `limit` and compute the distance between them. Find `below`, `below_fixed` and `gap` and determine which of the two comparisons gives the expected answer. Assume a 32-bit `unsigned int`.
```c
int balance = -3;
unsigned int limit = 5u;
int below = balance < limit;
int below_fixed = balance < (int)limit;
unsigned int gap = limit - balance;
```

Let $M=\mathrm{UINT\_MAX}+1=2^{32}$. Then
$$
\begin{aligned}
-3 &\longmapsto M-3=4294967293,\\[6pt]
5-(M-3) &= 8-M\equiv 8\pmod M .
\end{aligned}
$$
Hence `below` is $0$, `below_fixed` is $1$ and `gap` is $8$.

<div class="spiegazione">

In the comparison `balance < limit` the operands are `int` and `unsigned int`, which have the same rank. The **usual arithmetic conversions** therefore convert `balance` to `unsigned int`, and the value $-3$ becomes $M-3$. This number is greater than $5$, so the comparison is false and `below` is $0$. With `-Wall -Wextra` GCC flags the line with the warning "comparison of integer expressions of different signedness".

In the second comparison the cast converts `limit` to `int`. The value $5$ is representable in `int`, so the conversion preserves it and the comparison takes place between two `int` values. Since $-3<5$, `below_fixed` is $1$, which is the expected answer. The correction works for limits up to `INT_MAX`, because a larger value would not be representable in `int`.

The subtraction `limit - balance` applies the same conversion to `balance`. The mathematical result $8-M$ is negative and reduction modulo $M$ gives $8$. The value equals the distance $5-(-3)=8$, because this distance lies between $0$ and $M-1$.

</div>
