## Exercise 1

The program must print the mean of `sum` and `count` with two fractional digits, that is `4.25`. Find the two errors, classify them and write the corrected program. Assume a C17 Annex F implementation in round-to-nearest mode, the C numeric locale and successful output.
```c
#include <stdio.h>

int main(void)
{
    int sum = 17;
    int count = 4;
    double mean = sum / count;
    printf("%d\n", mean);
    return 0;
}
```

GCC with `-Wall` flags the eighth line with the following message.

```text
warning: format '%d' expects argument of type 'int', but argument 2 has type 'double' [-Wformat=]
```

Two lines change in the corrected program.

```c
    double mean = (double)sum / count;
    printf("%.2f\n", mean);
```

The output of the corrected program is `4.25`, followed by a newline.

<div class="spiegazione">

On the seventh line both operands of `/` are `int`, so the division gives the truncated quotient $4$. The initialization then converts $4$ to `double`, so `mean` is $4.0$. The behaviour of this line is defined, and the computed value differs from the one required by the specification.

On the eighth line `%d` requires an argument of type `int` and `mean` is a `double`. A conversion specification whose type does not match the argument produces **undefined behaviour**, so no output is guaranteed. The compiler warning points to exactly this mismatch.

In the correction the cast converts `sum` before the division, and the usual arithmetic conversions also convert `count` to `double`. The ratio $\dfrac{17}{4}=4.25$ has a power-of-two denominator and is represented exactly. The specification `%.2f` matches a `double` and writes two fractional digits, so the output is `4.25`.

</div>

## Exercise 2

The program must read a real unit price and an integer quantity and print the product with one fractional digit. Find the errors, write the corrected version and give its output for the input `2.5 4` and for the input `2.5 x`. Assume a C17 Annex F implementation in round-to-nearest mode, the C numeric locale and successful input and output.
```c
#include <stdio.h>

int main(void)
{
    double rate;
    int count;
    scanf("%f %d", &rate, count);
    printf("%.1f\n", rate * count);
    return 0;
}
```

The corrected body is as follows.

```c
    double rate = 0.0;
    int count = 0;
    int read = scanf("%lf %d", &rate, &count);
    printf("%d %.1f\n", read, rate * count);
```

| Input | Output |
|---|---|
| `2.5 4` | `2 10.0` |
| `2.5 x` | `1 0.0` |

<div class="spiegazione">

In `scanf` the specification `%f` requires a pointer to `float` and `&rate` points to a `double`, for which the specification is `%lf`. The third argument is `count`, that is the value of an uninitialized object, whereas `%d` requires the address of an `int`. Both mismatches produce **undefined behaviour**. GCC with `-Wall` reports them as format warnings and also reports the use of the uninitialized `count`.

The original program also uses `rate` and `count` without keeping the outcome of the read, so after a partial read the product uses an indeterminate value. In the corrected version both objects start from zero and `read` keeps the value returned by `scanf`.

With the input `2.5 4` both conversions succeed, so `read` is $2$ and the product $2.5\cdot4=10$ is written as `10.0`. With the input `2.5 x` the second conversion stops at the letter `x`. Then `read` is $1$ and `count` keeps $0$, so the output is `1 0.0`.

</div>

## Exercise 3

The program converts a duration of `hours` hours into milliseconds and must print `2160000000` for $600$ hours. Find the error, classify it and correct it. Assume a 32-bit `int`, so `INT_MAX` is $2147483647$.
```c
#include <stdio.h>

int main(void)
{
    int hours = 600;
    long long ms = hours * 3600 * 1000;
    printf("%lld\n", ms);
    return 0;
}
```

$$
\begin{aligned}
600\cdot 3600 &= 2160000,\\[6pt]
2160000\cdot 1000 &= 2160000000>2147483647 .
\end{aligned}
$$

In the corrected program the sixth line changes.

```c
    long long ms = hours * 3600LL * 1000;
```

The output of the corrected program is `2160000000`.

<div class="spiegazione">

The type of `ms` matters only in the conversion to the destination, after the expression on the right has been computed. The expression groups as `(hours * 3600) * 1000` and every operand is `int`, so both multiplications are performed in `int`. The first product $2160000$ is representable. The second has mathematical result $2160000000$, greater than `INT_MAX`, so the operation has **undefined behaviour**. Compiled with `-fsanitize=undefined`, the program reports "signed integer overflow" at run time and prints a negative number.

In the correction the constant `3600LL` has type `long long`. In the first product the arithmetic conversions convert `hours` to `long long`, the type of higher rank, and the result is a `long long`. For the same reason the multiplication by `1000` is also performed in `long long`. Since `LLONG_MAX` is at least $9223372036854775807$, the product is representable. The `printf` specification for a `long long` is `%lld`.

The suffix on the first factor makes both products `long long`. With `hours * 3600 * 1000LL` the first product would stay in `int`, representable for $600$ hours and out of range for `hours` greater than $596523$.

</div>
