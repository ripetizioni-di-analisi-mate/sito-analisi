## Exercise 1

Write the exact output and the return value. Assume successful output. The fragment uses `<stdio.h>`.
```c
int written = printf("[%5d][%3d]", -42, 1823);
```

```text
[  -42][1823]
```

The value of `written` is $5+4+4=13$.

<div class="spiegazione">

Decimal conversion of the first argument produces three characters, the sign and two digits. Since the minimum width is $5$, two spaces are placed before them. In the second field the conversion produces four digits. The specified width is $3$, so the content takes the four positions it needs. Each pair of square brackets is written by the literal part of the format.

To check the count, separate the characters by role. The output contains six digits, one sign, two spaces and four square brackets. The sum $6+1+2+4=13$ verifies `written`. This reading also confirms that the sign counts towards the width and that the second conversion retains all digits.

</div>

## Exercise 2

Determine the characters written and the return value. Assume a C17 Annex F implementation in round-to-nearest mode, the C numeric locale and successful output. The fragment uses `<stdio.h>`.
```c
int written = printf("[%7.2f][%.4u]%%", 2.5, 13u);
```

```text
[   2.50][0013]%
```

The value of `written` is $7+4+4+1=16$.

<div class="spiegazione">

In the first field, `.2f` requires two fractional digits. The value $2.5$ is therefore formatted as `2.50`, four characters in the C locale. The width $7$ adds three spaces to the left. For the integer conversion `.4u`, precision specifies at least four digits. The value $13$ has two, so two leading zeros are inserted. Finally, `%%` transmits one percent character.

To verify, count the characters in the result directly. There are seven digits, one point, three spaces, four square brackets and the percent character. The total is $7+1+3+4+1=16$. Reconstructing the first two fields from their digits recovers $2.5$ and $13$, so formatting has preserved the original values.

</div>

## Exercise 3

Write the exact output and the value of `written`. Assume a 4-byte `int`, a C17 Annex F implementation in round-to-nearest mode, the C numeric locale and successful output. The fragment uses `<stdio.h>`.
```c
int written = printf("%6.3d|%.2f|%3zu|%%%d\n", -7, 9.8765, sizeof(int), 5);
```

```text
  -007|9.88|  4|%5
```

The output ends with the newline character. The value of `written` is $6+4+3+3+1+1+1=19$.

<div class="spiegazione">

For `%6.3d` the precision $3$ requires at least three digits, so the value $-7$ becomes `007` preceded by the sign. The sign is part of the field, so `-007` takes four characters and the width $6$ adds two spaces to the left. The specification `%.2f` has no width, so the field is as long as the conversion. The `double` stored for `9.8765` differs from $9.8765$ by less than $10^{-15}$ and is far from the midpoint between $9.87$ and $9.88$, so conversion with two fractional digits gives `9.88`.

The expression `sizeof(int)` has type `size_t`, which matches `%zu`, and equals $4$ by assumption. The width $3$ places two spaces before the digit. In the sequence `%%%d`, read from the left, `%%` writes one percent character and `%d` converts the last argument $5$. The escape sequence `\n` in the string literal is a single character.

The count adds the three fields of width $6$, $4$ and $3$, the three vertical bars, the percent character, the digit $5$ and the newline. The total is $19$, which is the value returned by `printf`.

</div>
