## Exercise 1

Determine the type and value of `units + 3` in models A and B. In both models `USHRT_MAX` is $65535$. In model A, `INT_MAX` is $32767$, and in model B it is $2147483647$.
```c
unsigned short units = 12;
```

| Model | Promotion of `units` | Type of sum | Value |
|---|---|---|---|
| A | `unsigned int` | `unsigned int` | $15$ |
| B | `int` | `int` | $15$ |

<div class="spiegazione">

The promotion depends on all values of the source type. In model A, the maximum `unsigned short` value is $65535$ and exceeds the `int` maximum. The promoted type is therefore `unsigned int`. The other operand is the constant `3`, which has type `int`. Since `int` and `unsigned int` have equal rank, the operand `3` is also converted to `unsigned int`. In model B, `int` covers the interval from $0$ to $65535$, so both operands of the sum have type `int` after promotions.

To check the type, test the bounds of the full source range. The value $0$ is in the range of `int` in both models. The value $65535$ is in that range only in model B. To check the value, $15-3=12$ recovers the initial quantity, and $15$ lies in the range of each resulting type. The numerical values therefore agree even though the types differ.

</div>

## Exercise 2

Let `value` have type `int`. Find the greatest value for which `value + 7` has a representable result. Classify the operation at the next value.

$$
\begin{aligned}
\mathrm{value}+7 &\leq \mathrm{INT\_MAX},\\[6pt]
\mathrm{value} &\leq \mathrm{INT\_MAX}-7 .
\end{aligned}
$$
The maximum is `INT_MAX - 7`. At the next value the addition has undefined behaviour.

<div class="spiegazione">

The constant `7` has type `int`, so the expression is evaluated in `int`. Since the added number is positive, the mathematical result is at least the operand and hence at least `INT_MIN`. The only bound that can be exceeded is `INT_MAX`. Subtracting $7$ from both sides gives the threshold. The subtraction used to form the threshold has a representable result.

Check the two boundary values. For `INT_MAX - 7`, the mathematical expression equals `INT_MAX` and is valid. Increasing the input by $1$ gives `INT_MAX - 6`, still representable, but the mathematical sum is $\mathrm{INT\_MAX}+1$. That value is outside the range. The classification follows from the limits and is determined before executing the addition.

</div>

## Exercise 3

Find `sum`, `wrapped`, `diff` and `back` and classify the initialization of `s`. Assume `CHAR_BIT` equals $8$, so `UCHAR_MAX` is $255$ and `SCHAR_MAX` is $127$.
```c
unsigned char a = 200;
unsigned char b = 100;
int sum = a + b;
unsigned char wrapped = a + b;
int diff = b - a;
unsigned char back = b - a;
signed char s = a + b;
```

| Object | Value |
|---|---|
| `sum` | $300$ |
| `wrapped` | $300-256=44$ |
| `diff` | $-100$ |
| `back` | $-100+256=156$ |
| `s` | implementation-defined |

<div class="spiegazione">

The type `int` represents every value from $0$ to $255$, because `INT_MAX` is at least $32767$. The **integer promotions** therefore convert `a` and `b` to `int` before every operation. The sum is $300$ and the difference `b - a` is $-100$, so `sum` and `diff` receive the mathematical values.

The other initializations convert the result to the type of the destination. The type `unsigned char` has $M=256$ values, and conversion to an unsigned type yields the representative modulo $M$ in $[0,M-1]$. From $300-256=44$ it follows that `wrapped` is $44$. For the difference $M$ is added, so `back` is $-100+256=156$. The operations take place in `int` and stay in range, so the reduction happens only in the conversion to the destination.

The last line converts $300$ to `signed char`, which cannot represent it because $300>127$. For the conversion of an integer to a signed type that cannot represent it, C17 specifies an **implementation-defined** result or an implementation-defined signal. GCC documents reduction modulo $256$, so with GCC `s` is $44$. Another implementation may document a different choice.

</div>
