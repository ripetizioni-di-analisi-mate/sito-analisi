## Exercise 1

The input contains the line `14 crate`. Find `read`, `crates` and `items`. Assume no read errors. The fragment uses `<stdio.h>`.
```c
int crates = -1, items = -1;
int read = scanf("%d %d", &crates, &items);
```

| Object | Final value |
|---|---|
| `read` | $1$ |
| `crates` | $14$ |
| `items` | $-1$ |

<div class="spiegazione">

The first `%d` recognises the digits `14` and converts them to a representable `int`. Since the first specification corresponds to `&crates`, the result is stored in `crates`. The following space in the format then takes the read to the letter `c`. The second `%d` encounters a matching failure because the field starts with a letter that cannot begin the required decimal integer.

To check, count assignments separately from the input directives. The first destination received $14$. The second still has its initial value $-1$, and the space in the format has no destination. There is one assignment, so the return value is $1$. This is a partial scan and identifies which object has received a new value.

</div>

## Exercise 2

The input contains the line `0.75 11.5`. Determine the assignment count and the output. Assume a C17 Annex F implementation in round-to-nearest mode, the C numeric locale and successful input and output. The fragment uses `<stdio.h>`.
```c
float rate = 0.0f;
double length = 0.0;
int read = scanf("%f%lf", &rate, &length);
printf("%.2f %.1f", rate, length);
```

There are $2$ assignments. The output is as follows.

```text
0.75 11.5
```

<div class="spiegazione">

The first specification has `rate` as its destination, a `float`. The format therefore requires `%f`. The second must store into `length`, which is a `double`, so it uses `%lf`. Although the specifications are adjacent in the format, the second numeric conversion skips leading whitespace. Both values are exactly representable in their respective destinations and there are two assignments.

In `printf` the variadic argument of type `float` is promoted to `double`. The second numeric argument already has this type. The requested precision is two fractional digits for `rate` and one for `length`. As an independent check, express the scanned values as exact binary fractions. They are $\dfrac{3}{4}$ and $\dfrac{23}{2}$. Converting the two output fields recovers those fractions, and only the literal space appears between the fields.

</div>
