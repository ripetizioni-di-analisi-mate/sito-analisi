## Exercise 1

For `score(3)`, give the arguments in launch order and calculate the final result. Assume $0\leq n\leq8$.
```c
unsigned score(unsigned n)
{
    if (n <= 1u) {
        return n + 1u;
    }
    unsigned first = score(n - 2u);
    unsigned second = score(n - 1u);
    return first + second;
}
```

The order is $3$, $1$, $2$, $0$, $1$. The two results received by the root are $2$ and $3$, so the initial call returns $5$.

<div class="spiegazione">

The initializer for `first` starts the call with argument $1$ and completes it before the next initializer. The call with $2$ in turn starts the base cases $0$ and $1$, in that order. The base values are $1$ for argument zero and $2$ for argument one. The call with $2$ therefore returns $3$, and the root adds the $2$ that its record retained.

To check, add only the leaf values. The leaf arguments in order are $1$, $0$, $1$, and each inner node adds its children’s results. The leaf total is $2+1+2=5$.

</div>

## Exercise 2

For `split(3)`, find the permitted arguments for the first call started by the root and compute the result. The domain is $0\leq n\leq8$.
```c
unsigned split(unsigned n)
{
    if (n <= 1u) {
        return 1u;
    }
    return split(n - 1u) + split(n - 2u);
}
```

The first child may have argument $2$ or $1$. In either case the result is $3$.

<div class="spiegazione">

The two operands of `+` correspond to the call with argument $2$ and the one with argument $1$. C17 permits either to be evaluated first. The call with $1$ returns one. The call with $2$ adds the results of its two base cases and returns two. The two subtrees are independent, so both orders give the sum $2+1$.

To check, count the leaves. The child with argument $2$ has two leaves, and the child with argument $1$ is a leaf. Every leaf contributes one, so the result is the total leaf count.

</div>

## Exercise 3

For `tri(4)`, give the arguments in launch order, count the invocations with argument $2$ and compute the result. The domain is $0\leq n\leq10$.
```c
unsigned tri(unsigned n)
{
    if (n <= 1u) {
        return 1u;
    }
    unsigned a = tri(n - 1u);
    unsigned b = tri(n / 2u);
    unsigned c = tri(n - 2u);
    return a + b + c;
}
```

The launch order is $4$, $3$, $2$, $1$, $1$, $0$, $1$, $1$, $2$, $1$, $1$, $0$, $2$, $1$, $1$, $0$.

| Argument | `a` | `b` | `c` | Return value |
|---:|---:|---:|---:|---:|
| $2$ | $1$ | $1$ | $1$ | $3$ |
| $3$ | $3$ | $1$ | $1$ | $5$ |
| $4$ | $5$ | $3$ | $3$ | $11$ |

There are sixteen launches, three of them with argument $2$. The call `tri(4)` returns $11$.

<div class="spiegazione">

Each declaration with an initializer ends with a full expression, and there is a sequence point at the end of a full expression. The call that initializes `a` therefore completes before the call that initializes `b` starts, and that one before the call for `c`. The root thus launches the whole subtree of `tri(3)`, namely $3$, $2$, $1$, $1$, $0$, $1$, $1$. It then launches `tri(2)` for $\lfloor\dfrac{4}{2}\rfloor=2$ and finally `tri(2)` for $4-2=2$.

An invocation with argument $2$ launches $1$, $1$ and $0$ in that order, because $\lfloor\dfrac{2}{2}\rfloor=1$. There are three invocations with argument $2$, one inside `tri(3)` and two direct children of the root. Since every leaf returns $1$, each of them returns $3$. The invocation with argument $3$ returns $3+1+1=5$ and the root returns $5+3+3=11$.

With the three calls written as operands of the same `+`, the value would still be $11$. The launch order would instead be unspecified, because the `+` operator leaves the order of evaluation of its operands unspecified. As a check, there are $11$ leaves and five inner nodes, for a total of $16$ invocations.

</div>
