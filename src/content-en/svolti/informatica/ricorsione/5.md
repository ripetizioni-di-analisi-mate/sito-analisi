## Exercise 1

The array `a` contains $-2$, $4$, $0$, $7$, $-1$. Find every intermediate result and the final value of `count_positive(a, 5)`.
```c
#include <stddef.h>

size_t count_positive(const int a[], size_t n)
{
    if (n == 0) {
        return 0;
    }
    return count_positive(a, n - 1) + (a[n - 1] > 0);
}
```

| Prefix length | Positive count |
|---:|---:|
| $0$ | $0$ |
| $1$ | $0$ |
| $2$ | $1$ |
| $3$ | $1$ |
| $4$ | $2$ |
| $5$ | $2$ |

<div class="spiegazione">

The empty case returns zero before any access. With a positive prefix length, add the comparison result for position $n-1$. The comparison gives one only for a strictly positive element. The count rises when the prefix reaches $4$ and when it reaches $7$. It stays unchanged in the other three steps. Conversion of the comparison result to `size_t` preserves zero or one, so every sum up to five is representable.

A direct scan finds the only positive values at indices $1$ and $3$. Counting those two indices confirms the result.

</div>

## Exercise 2

Compute the result of `nondecreasing(a, 5)` for the array $(-3,1,1,0,2)$. Find the first prefix to return zero and explain whether the last two positions are compared.
```c
#include <stddef.h>

int nondecreasing(const int a[], size_t n)
{
    if (n < 2) {
        return 1;
    }
    return nondecreasing(a, n - 1) && (a[n - 2] <= a[n - 1]);
}
```

The prefixes of lengths one, two and three return $1$. Those of lengths four and five return $0$. The comparison between $0$ and $2$ is skipped.

<div class="spiegazione">

The property holds for a one-element prefix because it contains no adjacent pair to order. The comparisons $-3\leq1$ and $1\leq1$ preserve the true value in the next two prefixes. At length four the comparison is $1\leq0$, which is false. In the initial call, the first operand of `&&` therefore receives zero and the operator finishes evaluation with zero.

As a check on the overall result, the pair at positions $2$ and $3$ already violates nondecreasing order. This counterexample remains in the array even though the final pair is in order.

</div>
