## Exercise 1

Trace the values of `scale` kept in the records for `odd_product(3)` and compute the returned value. Assume $0\leq n\leq5$.

```c
unsigned odd_product(unsigned n)
{
    if (n == 0u) {
        return 1u;
    }
    unsigned scale = 2u * n + 1u;
    unsigned child = odd_product(n - 1u);
    return scale * child;
}
```

| Argument | `scale` | Return value |
|---:|---:|---:|
| $3$ | $7$ | $105$ |
| $2$ | $5$ | $15$ |
| $1$ | $3$ | $3$ |
| $0$ | absent from the computation | $1$ |

<div class="spiegazione">

In the initial record, `scale` holds $7$. The inner call runs the same body on $2$ and creates a separate value $5$. A third record uses $3$. When the base returns $1$, the first multiplication on the way back is $3\cdot1$. Its result becomes `child` in the next record and is multiplied by $5$. The final multiplication uses the $7$ kept by the initial caller.

The direct product $3\cdot5\cdot7=105$ confirms the value. The maximum on the domain is $10395$, obtained by including the factors $9$ and $11$, so the computation fits in `unsigned`.

</div>

## Exercise 2

Find the parameter pairs active on the descent for `add_even(3, 4)` and the result. Use a domain with $0\leq n\leq6$ and $d+n(n+1)\leq65535$, where $d$ is the value of `done`.

```c
unsigned add_even(unsigned n, unsigned done)
{
    if (n == 0u) {
        return done;
    }
    return add_even(n - 1u, done + 2u * n);
}
```

$$
(3,4)\longrightarrow(2,10)\longrightarrow(1,14)
\longrightarrow(0,16).
$$

The result is $16$.

<div class="spiegazione">

Each call forms its new `done` before entering the next record. The first step adds $2\cdot3=6$, so the value passed is $10$. The following steps add $4$ and $2$. When `n` reaches zero, the accumulator already holds the result. The domain is preserved because the term added is the difference between $n(n+1)$ and $(n-1)n$.

As a check, the initial sum $4$ plus the even contributions gives $4+6+4+2=16$. Returns propagate that same value because no operation remains pending.

</div>

## Exercise 3

For `layer(3)`, on the domain $0\leq n\leq10$, reconstruct in each record the values of `before`, of `got` and of the parameter `n` after the assignment, then compute the result. Decide whether the assignment to `n` performed in an inner invocation changes the caller’s parameter.

```c
unsigned layer(unsigned n)
{
    if (n == 0u) {
        return 0u;
    }
    unsigned before = n * 10u;
    unsigned got = layer(n - 1u);
    n = n + got;
    return before + n;
}
```

| Argument | `before` | `got` | `n` after the assignment | Return value |
|---:|---:|---:|---:|---:|
| $3$ | $30$ | $33$ | $36$ | $66$ |
| $2$ | $20$ | $11$ | $13$ | $33$ |
| $1$ | $10$ | $0$ | $1$ | $11$ |
| $0$ | absent | absent | $0$ | $0$ |

Each assignment to `n` changes only the parameter of its own record. The call `layer(3)` returns $66$.

<div class="spiegazione">

In C, arguments are passed **by value**. The parameter `n` of each invocation is therefore a distinct automatic object, initialized with a copy of the argument. The value of `before` is computed before the call and stays in the record for the whole duration of the inner call.

The record with argument $1$ receives $0$ from the base, assigns $1+0=1$ to `n` and returns $10+1=11$. When control returns to the record with argument $2$, its `n` still holds $2$, because the assignment just executed concerned a different object. This record therefore computes $2+11=13$ and returns $20+13=33$. In the same way the initial record takes its own `n` from $3$ to $3+33=36$ and returns $30+36=66$.

As a check, each record returns $10n+n$ plus the inner result, so `layer(n)` equals $11\cdot\dfrac{n(n+1)}{2}$. For $n=3$ this gives $11\cdot6=66$. The largest value on the domain is $11\cdot55=605$, so all the computations are representable in `unsigned`.

</div>
