## Exercise 1

Sort $(8,3,7,2)$ by merge sort. Count key comparisons and writes from auxiliary storage back to the array after each merge.

| Runs to merge | Merged run | Comparisons | Copies |
|---|---|---:|---:|
| $(8)$ and $(3)$ | $(3,8)$ | 1 | 2 |
| $(7)$ and $(2)$ | $(2,7)$ | 1 | 2 |
| $(3,8)$ and $(2,7)$ | $(2,3,7,8)$ | 3 | 4 |

There are $1+1+3=5$ comparisons and $2+2+4=8$ copy-back writes.

<div class="spiegazione">

The first split gives two runs of length two. Each splits into single elements and merges with one comparison, because the first write exhausts one of the two runs. The final merge chooses $2$ by comparing it with $3$, then $3$ by comparing it with $7$. It then compares $8$ and $7$. After choosing $7$, only $8$ remains, so it is copied without a comparison.

As an independent check on copies, the first merge level touches all four elements in two disjoint groups. The final level writes every element a second time. This is two copy-back writes per element, giving eight.

</div>

## Exercise 2

Sort $(9,4,6,2,8)$, splitting a length $n$ into runs of lengths $\left\lfloor\dfrac{n}{2}\right\rfloor$ and $n-\left\lfloor\dfrac{n}{2}\right\rfloor$. Find key comparisons, copy-back writes, and the positions in the reused auxiliary array.

| Runs to merge | Output | Comparisons | Copies |
|---|---|---:|---:|
| $(9)$ and $(4)$ | $(4,9)$ | 1 | 2 |
| $(2)$ and $(8)$ | $(2,8)$ | 1 | 2 |
| $(6)$ and $(2,8)$ | $(2,6,8)$ | 2 | 3 |
| $(4,9)$ and $(2,6,8)$ | $(2,4,6,8,9)$ | 4 | 5 |

There are eight comparisons, twelve copy-back writes, and five auxiliary positions.

<div class="spiegazione">

The three-element run splits into one element and a run of two. Merging $(6)$ with $(2,8)$ selects $2$ first and then $6$. Including the earlier merge of $(2)$ and $(8)$, that branch uses three comparisons. The left branch uses one. In the largest merge, comparisons select $2,4,6,8$ in order, and $9$ comes from the tail. The total is $1+3+4=8$.

The copy-back writes sum the lengths of the four merged runs, giving $2+2+3+5=12$. To check the required storage, the final merge writes indices $0$ through $4$ before copying back. Smaller merges write only in those same positions, so the auxiliary array has five positions even though some are written several times.

</div>

## Exercise 3

The following fragment applies the `merge_sort` from the theory to seven elements. Give the merges in the order they happen, the key comparisons, and the copy-back writes. Also count the calls, including base cases, and the largest number of calls active at once.
```c
int a[] = {6, 2, 7, 3, 5, 1, 4};
int tmp[7];
merge_sort(a, tmp, 0, 7);
```

| Runs to merge | Output | Comparisons | Copies |
|---|---|---:|---:|
| $(2)$ and $(7)$ | $(2,7)$ | 1 | 2 |
| $(6)$ and $(2,7)$ | $(2,6,7)$ | 2 | 3 |
| $(3)$ and $(5)$ | $(3,5)$ | 1 | 2 |
| $(1)$ and $(4)$ | $(1,4)$ | 1 | 2 |
| $(3,5)$ and $(1,4)$ | $(1,3,4,5)$ | 3 | 4 |
| $(2,6,7)$ and $(1,3,4,5)$ | $(1,2,3,4,5,6,7)$ | 5 | 7 |

There are $13$ comparisons, $20$ copy-back writes, $13$ calls, and at most $4$ active calls.

<div class="spiegazione">

With `mid = lo + n / 2` the left half has $\left\lfloor\dfrac{n}{2}\right\rfloor$ elements. The seven-element run therefore splits into $(6,2,7)$ and $(3,5,1,4)$, and the first of these splits into $(6)$ and $(2,7)$. The second recursive call starts only after the first returns, so the left branch is sorted completely before the right one. In the final merge the comparisons write $1,2,3,4,5$. Then the tail $(6,7)$ is copied without comparisons.

The calls on a single element are the seven base cases, and each of the others performs one merge, so there are $7+6=13$ calls. The lengths along the longest path to a base case are $7$, $4$, $2$, and $1$, so at most **four calls** are active. The copy-back writes add up the lengths of the merged runs, $2+3+2+2+4+7=20$.

</div>
