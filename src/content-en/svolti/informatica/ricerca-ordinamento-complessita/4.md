## Exercise 1

Sort $(7,3,5,2)$ by insertion sort. For each pass, count the key comparisons and right shifts. Count the final key write of each pass separately.

| Key | Array after the pass | Comparisons | Shifts |
|---:|---|---:|---:|
| 3 | $3,7,5,2$ | 1 | 1 |
| 5 | $3,5,7,2$ | 2 | 1 |
| 2 | $2,3,5,7$ | 3 | 3 |

There are six comparisons, five shifts, and three writes of saved keys in total.

<div class="spiegazione">

When inserting $3$, the only earlier element is $7$, which is shifted. The test on `j` prevents another key comparison once the start is reached. To insert $5$, shift $7$ and then test against $3$, which is false. When inserting $2$, all earlier keys $7$, $5$, and $3$ are greater, so three shifts occur. Each pass finishes by writing the saved key.

Check the count by enumerating the initial inversions. Key $7$ precedes three smaller keys. Keys $3$ and $5$ each precede the smaller key $2$. This gives $3+1+1=5$ inversions. The sixth comparison is the false test against $3$ while inserting $5$.

</div>

## Exercise 2

Sort the records $(3,A),(1,B),(3,C),(1,D),(2,E)$ using insertion sort with shifts only for strictly greater keys. Give the final record order.

| Record inserted | Resulting prefix |
|---|---|
| $(1,B)$ | $(1,B),(3,A)$ |
| $(3,C)$ | $(1,B),(3,A),(3,C)$ |
| $(1,D)$ | $(1,B),(1,D),(3,A),(3,C)$ |
| $(2,E)$ | $(1,B),(1,D),(2,E),(3,A),(3,C)$ |

<div class="spiegazione">

Record $B$ with key $1$ shifts record $A$ with key $3$. When inserting $C$, the comparison with $A$'s key finds equality, so $C$ goes directly after $A$. When inserting $D$, the two key-$3$ records shift and the search stops at $B$. The last record goes between keys $1$ and $3$.

To check the result, independently group equal keys in their original order. The key-$1$ group contains $B,D$, the key-$2$ group contains $E$, and the key-$3$ group contains $A,C$. Concatenating the groups by increasing key recovers the traced result.

</div>

## Exercise 3

In the following function the two conditions of the insertion-sort guard are written in reverse order. Decide whether the call has defined behavior on the arrays $(4,6,5,8)$ and $(4,6,3,8)$, count key comparisons and shifts in the defined case, and fix the guard.
```c
void insertion_sort_wrong(int a[], size_t n)
{
    for (size_t i = 1; i < n; ++i) {
        int key = a[i];
        size_t j = i;
        while (a[j - 1] > key && j > 0) {
            a[j] = a[j - 1];
            --j;
        }
        a[j] = key;
    }
}
```

| Array | Key that brings `j` to zero | Outcome |
|---|---|---|
| $(4,6,5,8)$ | none | $(4,5,6,8)$ with $4$ comparisons and $1$ shift |
| $(4,6,3,8)$ | $3$, in pass $i=2$ | read of `a[j - 1]` with `j` equal to zero |

The correct guard tests the index before reading the element.

```c
while (j > 0 && a[j - 1] > key) {
```

<div class="spiegazione">

The `&&` operator evaluates its left operand first and evaluates the right one only if the left is true. Because of this **short-circuit** rule, the guard as written reads `a[j - 1]` before knowing whether `j` is positive. The test `j > 0` does not protect the read, because when `j` is zero the read has already happened. On the first array key $6$ needs one comparison, key $5$ needs two and shifts $6$, and key $8$ needs one. No key is smaller than all the keys before it, so `j` never reaches zero and the result matches that of the correct function.

On the second array key $3$ shifts $6$ and then $4$, so `j` becomes zero and the guard computes `j - 1`. In unsigned arithmetic the result is `SIZE_MAX`, and `a[SIZE_MAX]` denotes a position outside the array, so the read has **undefined behavior**. With `-fsanitize=address` the program stops at that access. In the correct guard, when `j` is zero the left operand is false and the element is not read.

</div>
