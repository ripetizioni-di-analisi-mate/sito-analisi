## Exercise 1

Write a function that checks the precondition of binary search. Positions `0` through `n - 1` of `a` are readable when `n` is positive; the function returns `1` if $a_i\leq a_{i+1}$ for every adjacent pair and `0` otherwise. Count the comparisons between elements on the empty array and on the arrays $(5)$, $(1,3,3,8)$, and $(1,3,2,8)$.
```c
int is_nondecreasing(const int a[], size_t n);
```

```c
int is_nondecreasing(const int a[], size_t n)
{
    for (size_t i = 1; i < n; ++i) {
        if (a[i - 1] > a[i]) {
            return 0;
        }
    }
    return 1;
}
```

| Array | `n` | Returned value | Comparisons |
|---|---:|---:|---:|
| empty | 0 | 1 | 0 |
| $(5)$ | 1 | 1 | 0 |
| $(1,3,3,8)$ | 4 | 1 | 3 |
| $(1,3,2,8)$ | 4 | 0 | 2 |

<div class="spiegazione">

An array is nondecreasing when no adjacent pair has its first element strictly greater than its second. The function therefore looks for a pair that violates the condition and returns `0` at the first one it finds. If the loop ends, the test was false on all $n-1$ pairs, so the value `1` respects the contract. With $n=0$ and $n=1$ there are no adjacent pairs, and indeed the guard `i < n` is false from the start and no element is read. On the fourth array the second comparison finds $3>2$ and the function ends with `0`.

The index starts at `1` and the comparison uses `a[i - 1]`, so the subtraction is computed only when `i` is at least $1$.

The guard `i < n - 1` with `i` starting at zero, by contrast, has a defect in the empty case. With $n=0$ the expression `n - 1` equals `SIZE_MAX` in unsigned arithmetic, so the guard is true and the function reads `a[0]` and `a[1]`, positions the contract does not guarantee. Those reads have **undefined behavior**.

</div>

## Exercise 2

On a nondecreasing array of `n` elements, write a function that counts the occurrences of `key` with two binary searches, also using the `lower_bound` from the theory. Find the result and the number of key comparisons on the array $(1,3,4,4,4,7,9)$ for keys $4$, $5$, $0$, and $9$.
```c
size_t count_equal(const int a[], size_t n, int key);
```

```c
size_t upper_bound(const int a[], size_t n, int key)
{
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] <= key) {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    return lo;
}

size_t count_equal(const int a[], size_t n, int key)
{
    return upper_bound(a, n, key) - lower_bound(a, n, key);
}
```

| Key | `lower_bound` | `upper_bound` | Occurrences | Comparisons |
|---:|---:|---:|---:|---:|
| 4 | 2 | 5 | 3 | 6 |
| 5 | 5 | 5 | 0 | 6 |
| 0 | 0 | 0 | 0 | 6 |
| 9 | 6 | 7 | 1 | 6 |

<div class="spiegazione">

The function `upper_bound` differs from `lower_bound` only in the test `<=`. With the same invariant, the indices in $[0,\mathrm{lo})$ hold elements less than or equal to the key and those in $[\mathrm{hi},n)$ hold greater elements. The result is therefore the first index whose element is strictly greater than the key. Since the array is sorted, the elements equal to `key` occupy the positions from `lower_bound` included to `upper_bound` excluded. The difference of the two bounds is therefore the **number of occurrences**, and it is zero when the bounds coincide, as for keys $5$ and $0$. The subtraction between `size_t` values never goes below zero, because an element less than the key is also less than or equal to it, so `upper_bound` is never smaller than `lower_bound`.

With $n=7$ the range goes to length $3$ in both branches, then to $1$ and to $0$, so each search performs exactly $3$ comparisons. The total is $6$ for every key, against the $7$ comparisons of a full scan. In general the cost is at most $2\left(1+\lfloor\log_2 n\rfloor\right)$, that is, $O(\log n)$.

</div>

## Exercise 3

Write a function that inserts `key` into a nondecreasing array of `n` elements with capacity `cap`, where `n <= cap` and positions `0` through `cap - 1` are writable. If `n < cap`, the function places the key after the equal elements, keeps the order, and returns `n + 1`. If `n == cap`, it leaves the array unchanged and returns `n`. You may use the function `upper_bound`, which returns the first index whose element is greater than the key. Give the output of the test program.
```c
size_t insert_sorted(int a[], size_t n, size_t cap, int key);

int main(void)
{
    int a[7] = {2, 5, 5, 9};
    size_t n = 4;
    const int keys[] = {5, 1, 10, 7};
    for (size_t k = 0; k < 4; ++k) {
        n = insert_sorted(a, n, 7, keys[k]);
        for (size_t i = 0; i < n; ++i) {
            printf("%d ", a[i]);
        }
        printf("| n = %zu\n", n);
    }
    return 0;
}
```

```c
size_t insert_sorted(int a[], size_t n, size_t cap, int key)
{
    if (n >= cap) {
        return n;
    }
    size_t p = upper_bound(a, n, key);
    for (size_t k = n; k > p; --k) {
        a[k] = a[k - 1];
    }
    a[p] = key;
    return n + 1;
}
```

```text
2 5 5 5 9 | n = 5
1 2 5 5 5 9 | n = 6
1 2 5 5 5 9 10 | n = 7
1 2 5 5 5 9 10 | n = 7
```

<div class="spiegazione">

Let `p` be the value of `upper_bound`. The elements in $[0,p)$ are less than or equal to `key` and those in $[p,n)$ are greater, so the key written at position `p` preserves the order. Since `p` follows all equal copies, the insertion is **stable** like that of insertion sort, and indeed the first $5$ inserted occupies index $3$, after the two $5$s already present.

The loop starts from the last element and moves the elements from `n - 1` down to `p` one position to the right, so each element is copied before its position is overwritten. There are $n-p$ shifts, namely one for key $5$, five for key $1$, and none for key $10$, which goes at the end. The guard `k > p` ensures that `k` is at least $1$, so `a[k - 1]` never uses the index `SIZE_MAX`. The write to `a[n]` respects the contract, because the initial check ensures `n < cap`. On the fourth call `n` is $7$, equal to the capacity, and key $7$ is not inserted.

</div>
