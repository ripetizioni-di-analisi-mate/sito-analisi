## Exercise 1

Merge runs $(3,8,12,14)$ and $(1,9)$, counting key comparisons and all output writes.

| Heads compared | Value written |
|---|---:|
| 3 and 1 | 1 |
| 3 and 9 | 3 |
| 8 and 9 | 8 |
| 12 and 9 | 9 |

Copy the tail $(12,14)$. The result is $(1,3,8,9,12,14)$, with $4$ comparisons and $6$ writes.

<div class="spiegazione">

The first value written comes from the right run, so the second comparison still has $3$ on the left. The next comparisons select $3$ and $8$, both smaller than the right head $9$. When the left head becomes $12$, the algorithm selects $9$ and exhausts the right run. The left tail then completes the output without key comparisons.

Verify that each input element occurs once in the output and that all keys are nondecreasing. The six elements split into two copied from the tail and four produced by comparisons. This gives the comparison count a second way.

</div>

## Exercise 2

Merge $(1,A),(4,B),(5,C)$ and $(1,D),(4,E),(4,F)$. Give the tag order when ties choose the left run. Trace it again when ties choose the right run.

| Tie rule | Tag order |
|---|---|
| left run comes first | $A,D,B,E,F,C$ |
| right run comes first | $D,A,E,F,B,C$ |

<div class="spiegazione">

With the first rule, comparisons of $A$ with $D$ and of $B$ with $E$ give priority to the record that had the smaller index before splitting the array. Thus $A$ precedes $D$ and $B$ precedes the pair $E,F$. With the second rule, $D$ is written first. Once both heads have key $4$, the two right-run records are written first, retaining their internal order $E,F$.

As a check, the key groups are $1$ for $A,D$, $4$ for $B,E,F$, and $5$ for $C$. Both rules give the same nondecreasing key sequence. The internal order of the first two groups shows that only the first rule preserves the relative order of the original concatenation.

</div>

## Exercise 3

In the following merge one of the two loops that copy the tail is missing. The array `tmp` holds zeros before the call. Find `tmp` on $[\mathrm{lo},\mathrm{hi})$ for the pairs of runs $(2,5,9)$ and $(3,4)$, $(1,3)$ and $(2,6,7)$, $(4,8)$ and $(1,8)$. State the condition on the runs under which the result is wrong, and fix the function.
```c
void merge_range_wrong(const int a[], int tmp[],
                       size_t lo, size_t mid, size_t hi)
{
    size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
        }
    }
    while (i < mid) {
        tmp[k++] = a[i++];
    }
}
```

| Runs | Comparisons | `tmp` after the call |
|---|---:|---|
| $(2,5,9)$ and $(3,4)$ | 3 | $2,3,4,5,9$ |
| $(1,3)$ and $(2,6,7)$ | 3 | $1,2,3,0,0$ |
| $(4,8)$ and $(1,8)$ | 3 | $1,4,8,0$ |

With two nonempty runs, the result is wrong if and only if the last left element is less than or equal to the last right element. The fix adds the right-tail loop at the end of the function.

```c
    while (j < hi) {
        tmp[k++] = a[j++];
    }
```

<div class="spiegazione">

The first loop ends as soon as one run is exhausted. In the first case the right run is exhausted after $4$ is written, so the tail $(5,9)$ belongs to the left run and the existing loop copies it. In the second case the left run is exhausted instead, and the tail $(6,7)$ is not copied. In the third case the comparison between $8$ and $8$ writes the left element, because of the `<=` test that makes the merge stable, and the right tail $(8)$ is left out of the output.

Let $L$ and $R$ be the last elements of the two runs. If $L\leq R$, every left head is less than or equal to $R$, so the first loop never writes $R$. The left run is therefore exhausted first, and the right tail, which contains at least $R$, is lost. If $L>R$, by the same argument $L$ stays in the left run and the tail that gets copied is the left one.

</div>
