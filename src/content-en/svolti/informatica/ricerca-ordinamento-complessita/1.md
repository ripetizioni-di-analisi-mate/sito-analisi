## Exercise 1

Find the first occurrence of key `11` in the array shown and count the equality comparisons between an array key and the search key.

![Array with indices 0, 1, 2, 3, 4 and values 6, 11, 3, 11, 8. The key is 11.](/immagini/informatica/ricerca-ordinamento-complessita/dati-svolto-en.png)

| Index | Element | Equal to 11 |
|---:|---:|---|
| 0 | 6 | false |
| 1 | 11 | true |

The search returns index $1$ after $2$ comparisons.

<div class="spiegazione">

The scan starts at index zero. Since $6$ differs from $11$, it rules out the first position and increases the index. The next comparison directly establishes a match at index $1$. Visit order guarantees that no match lies farther left. The function returns at that point, before any other comparison.

For an independent check, read every position with value $11$. The set is $\{1,3\}$ and its minimum is $1$. The range visited to reach that index is $[0,2)$, which contains two positions. That also verifies the requested count.

</div>

## Exercise 2

In the array $(8,2,9,5,2,3)$, search separately for keys $2$ and $3$ in $[2,5)$. Use $5$ as the absence value within that range. Give the global index and comparison count for each key.

| Key | Indices compared | Result | Comparisons |
|---:|---|---:|---:|
| 2 | 2, 3, 4 | 4 | 3 |
| 3 | 2, 3, 4 | 5 | 3 |

<div class="spiegazione">

The guard uses the exclusive bound $5$, so this range contains the values $9$, $5$, and $2$. Key $2$ matches the third observed value, at global index $4$. Every comparison is false for key $3$. The returned value $5$ then denotes absence from the range, even though `a[5]` exists in the full array.

For a check, apply `linear_first` starting at `a + 2` with length `3`. The local position of $2$ is $2$, so the global index is $2+2=4$. For $3$, the local return equals the length, and the corresponding global bound is $2+3=5$.

</div>

## Exercise 3

The following function is meant to return the first occurrence of `key` in positions `0` through `n - 1` of `a`, or `n` if the key is absent. Find the values returned for the array $(4,7,4,1,7)$ with keys $7$, $4$, and $9$, locate the error, and fix it with the smallest change.
```c
size_t find_first(const int a[], size_t n, int key)
{
    size_t result = n;
    for (size_t i = 0; i < n; ++i) {
        if (a[i] == key) {
            result = i;
        }
    }
    return result;
}
```

| Key | Indices holding the key | Returned | First occurrence | Comparisons |
|---:|---|---:|---:|---:|
| 7 | 1, 4 | 4 | 1 | 5 |
| 4 | 0, 2 | 2 | 0 | 5 |
| 9 | none | 5 | 5 | 5 |

The fix replaces the assignment with an immediate return.

```c
size_t find_first(const int a[], size_t n, int key)
{
    for (size_t i = 0; i < n; ++i) {
        if (a[i] == key) {
            return i;
        }
    }
    return n;
}
```

With this version the three calls return $1$, $0$, and $5$ after $2$, $1$, and $5$ comparisons.

<div class="spiegazione">

No statement leaves the loop after a match, so the function always examines all five positions. Every true equality overwrites `result`, hence at the end the variable holds the index of the last match. The function therefore computes the **last occurrence**. The two specifications give the same result when the key appears at most once, which is why key $9$ correctly returns $5$. Keys $7$ and $4$ appear twice and expose the error.

With `return` inside the true branch, the function stops at the first true comparison. Every earlier position gave a false comparison, so the returned index is the **first occurrence**. The final return of `n` is reached only when all $n$ comparisons are false, that is, when the key is absent. The fix also lowers the cost, because a first occurrence at index $i$ needs $i+1$ comparisons instead of $n$.

</div>
