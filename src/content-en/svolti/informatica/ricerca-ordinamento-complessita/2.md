## Exercise 1

Apply `lower_bound` to key $12$ in $(2,5,6,9,12,15,21,25)$. Give the bounds after each test and count the key comparisons, including the final check in `binary_first`.

| Initial lo, hi | mid | a[mid] | Next lo, hi |
|---|---:|---:|---|
| 0, 8 | 4 | 12 | 0, 4 |
| 0, 4 | 2 | 6 | 3, 4 |
| 3, 4 | 3 | 9 | 4, 4 |

The result is index $4$. There are $3+1=4$ comparisons.

<div class="spiegazione">

On the first test the value equals the key, and the upper bound moves down to $4$. The invariant allows the right boundary to be the lower bound even though that boundary is outside the remaining range to examine. The next values, $6$ and $9$, are below the key and move the left bound up to $4$. When the bounds coincide, `a[4] == 12` is true and gives the first occurrence.

A direct scan finds four elements smaller than $12$, followed by $12$. The boundary after the four elements is indeed $4$. This trace has three `a[mid] < key` tests, with equality contributing a separate fourth test.

</div>

## Exercise 2

In the array $(1,4,7,7,10,14)$, compute `lower_bound` and `binary_first` for keys $8$ and $16$. Determine when the final equality comparison is evaluated.

| Key | Ranges after tests | Lower bound | First occurrence |
|---:|---|---:|---:|
| 8 | $[4,6)$, $[4,5)$, $[4,4)$ | 4 | 6 |
| 16 | $[4,6)$, $[6,6)$ | 6 | 6 |

For $8$, compare $10$ with $8$. For $16$, the equality comparison is skipped.

<div class="spiegazione">

The first probe examines value $7$ at position $3$. It is smaller than both keys, so `lo` becomes $4$. The second probe examines $14$ at position $5$. For key $8$, `hi` drops to $5$ and the following comparison with $10$ reduces `hi` to $4$. The bound $4$ is readable and its equality test is false. For key $16$, the comparison with $14$ instead raises `lo` to $6$. The test `p < n` is false, and the expression `a[p] == key` is skipped.

There are four values smaller than $8$ and six smaller than $16$. These counts confirm the two boundaries. In both cases the search for a matching value returns the absence value $6$.

</div>

## Exercise 3

The following function computes the lower bound on a nondecreasing array using the closed range $[\mathrm{lo},\mathrm{hi}]$. The type `size_t` has $64$ bits. Trace the calls on the array $(3,6,6,9)$ for keys $6$, $10$, and $2$, identify the case with undefined behavior, and fix the function.
```c
size_t lower_bound_closed(const int a[], size_t n, int key)
{
    size_t lo = 0, hi = n - 1;
    while (lo <= hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < key) {
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return lo;
}
```

| Key | lo, hi before each test | mid | Result |
|---:|---|---|---|
| 6 | $(0,3)$, $(0,0)$ | 1, 0 | 1 |
| 10 | $(0,3)$, $(2,3)$, $(3,3)$ | 1, 2, 3 | 4 |
| 2 | $(0,3)$, $(0,0)$, $(0,2^{64}-1)$ | 1, 0, $2^{63}-1$ | undefined |

The fix uses the half-open range of the `lower_bound` from the theory.

```c
size_t lower_bound(const int a[], size_t n, int key)
{
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < key) {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    return lo;
}
```

<div class="spiegazione">

For key $6$ the test on $a_1=6$ is false, so `hi` becomes $0$. The test on $a_0=3$ is true and moves `lo` to $1$, which exceeds `hi`, so the loop ends with the correct result $1$. For key $10$ every test is true and `lo` reaches $n=4$. For key $2$ the second test finds $3\geq2$ with `mid` equal to zero. The assignment `hi = mid - 1` then computes $0-1$ in unsigned arithmetic, and by **reduction modulo $2^{64}$** the result is `SIZE_MAX`. The guard `lo <= hi` stays true and the midpoint $2^{63}-1$ denotes a position outside the array. The read `a[mid]` therefore has **undefined behavior**.

With $n\geq1$ the defect appears exactly when the result is $0$, because only then must `hi` drop below the first index. With $n=0$ it appears at once, because `n - 1` is already `SIZE_MAX`. The half-open range represents the empty range as `lo == hi`, so every computed index stays between $0$ and $n$.

</div>
