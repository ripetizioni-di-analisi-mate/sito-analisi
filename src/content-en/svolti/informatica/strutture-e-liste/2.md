## Exercise 1

Compute `result`. All nodes are live automatic objects. The fragment uses `<stddef.h>`.

```c
struct Node { int key; struct Node *next; };
struct Node tail = {4, NULL};
struct Node middle = {13, &tail};
struct Node first = {10, &middle};
struct Node *head = &first;
int result = head->next->key - head->next->next->key;
```

Following the chain from `head` gives the keys $10$, $13$, $4$. The first operand of the subtraction is $13$ and the second is $4$, so `result` is $9$.

<div class="spiegazione">

`head` designates `first`. The first operand follows one link, which leads from `first` to `middle`. The integer member read is therefore $13$. The second operand follows two links. The first again leads to `middle` and the second leads to `tail`, which contains $4$. Both paths end at live nodes and the subtraction is representable in `int`.

To check, start from the pointer initializers and substitute each address. This gives `head->next == &middle` and `head->next->next == &tail`. Substituting the two objects' keys recovers the difference. Adding the last key to the result gives $9+4=13$, recovering the intermediate node's key.

</div>

## Exercise 2

Determine `count` and `sum`. The fragment uses `<stddef.h>`.

```c
struct Node { int key; struct Node *next; };
struct Node d = {7, NULL};
struct Node c = {0, &d};
struct Node b = {7, &c};
struct Node a = {-2, &b};
int count = 0, sum = 0;
for (struct Node *p = &a; p != NULL; p = p->next) {
    if (p->key >= 5) {
        ++count;
        sum += p->key;
    }
}
```

| Visited node | Key | `count` | `sum` |
|---|---|---|---|
| `a` | $-2$ | $0$ | $0$ |
| `b` | $7$ | $1$ | $7$ |
| `c` | $0$ | $1$ | $7$ |
| `d` | $7$ | $2$ | $14$ |

<div class="spiegazione">

The links lead to the initial node and then to its three successors in order. The condition on the data is tested in the body for each live node. The two keys equal to $7$ are the only ones that meet the threshold. Their nodes have distinct identities, so they are counted in separate iterations. After `d`, the update sets the traversal pointer to null and ends the loop.

As a check, consider the list of keys that pass the filter. It has two occurrences of $7$, so its length is $2$ and its sum is $2\cdot7=14$. There are also two excluded visits, at `a` and `c`. Adding the two included visits gives all four visits expected.

</div>

## Exercise 3

A *descent* is a node whose key exceeds the key of its successor. Determine `drops`, `last` and `pos` at the end of the loop; `last` is the position of the last descent, counted from zero. The nodes are live automatic objects and the fragment uses `<stddef.h>`.

```c
struct Node { int key; struct Node *next; };
struct Node n5 = {6, NULL};
struct Node n4 = {1, &n5};
struct Node n3 = {4, &n4};
struct Node n2 = {4, &n3};
struct Node n1 = {9, &n2};
struct Node n0 = {5, &n1};
int drops = 0, last = -1, pos = 0;
for (const struct Node *p = &n0; p != NULL; p = p->next) {
    if (p->next != NULL && p->key > p->next->key) {
        ++drops;
        last = pos;
    }
    ++pos;
}
```

| `pos` on entry | Key | Successor's key | Descent | `drops` | `last` |
|---|---|---|---|---|---|
| $0$ | $5$ | $9$ | no | $0$ | $-1$ |
| $1$ | $9$ | $4$ | yes | $1$ | $1$ |
| $2$ | $4$ | $4$ | no | $1$ | $1$ |
| $3$ | $4$ | $1$ | yes | $2$ | $3$ |
| $4$ | $1$ | $6$ | no | $2$ | $3$ |
| $5$ | $6$ | null | no | $2$ | $3$ |

At the end `drops` is $2$, `last` is $3$ and `pos` is $6$.

<div class="spiegazione">

The loop visits the six nodes from `n0` to `n5`, and `pos` counts the visits already completed. At each iteration the condition reads the key of the current node and that of its successor. The first descent is at position $1$, where $9>4$. The two consecutive nodes with key $4$ do not form a descent, because the comparison `>` is strict. The second descent is at position $3$, from the second $4$ to the node with key $1$, so `last` receives $3$.

At the last iteration `p` designates `n5` and `p->next` is null. The first operand of `&&` is false, so by **short-circuit evaluation** the second operand is not evaluated. The expression `p->next->key` would require indirection through a null pointer, which has undefined behavior. The order of the two operands therefore excludes that access, and after six increments `pos` equals the length of the list.

</div>
