## Exercise 1

Enqueue $3$, $8$ and $11$ in an empty linked queue. Dequeue one element, enqueue $7$, and dequeue again. Every insertion succeeds. Find the removed values and the final ends.

| Stage | Keys from `front` to `rear` |
|---|---|
| After the first insertions | $\langle 3,8,11\rangle$ |
| After the first removal | $\langle 8,11\rangle$ |
| After the new insertion | $\langle 8,11,7\rangle$ |
| After the second removal | $\langle 11,7\rangle$ |

The removed values are $3$ and $8$. In the final state, `front` identifies $11$ and `rear` identifies $7$.

<div class="spiegazione">

Enqueueing adds a successor after the last node, so the three initial nodes are ordered by arrival time. The first call to `dequeue` saves $3$ and moves `front` to $8$. The next insertion links key $7$ after $11$ and updates `rear`. The second removal detaches $8$, leaving the link from $11$ to $7$. The branch that clears `rear` does not execute because a valid front remains.

To check, reconstruct the arrival list $\langle 3,8,11,7\rangle$. The two FIFO removals must remove its first prefix of length $2$. The expected suffix is therefore $\langle 11,7\rangle$. Its ends are distinct and the last node's successor is null.

</div>

## Exercise 2

An owning queue is empty and output object `out` has value $0$. Attempt a removal. Insert $9$ successfully and attempt to insert $13$ with allocation failure. Remove again. Determine the outcomes and final state.

| Operation | Outcome | Subsequent contents |
|---|---|---|
| First removal | Failure, `out` stays $0$ | Empty queue |
| Insert $9$ | Success | $\langle 9\rangle$ |
| Insert $13$ | Failure | $\langle 9\rangle$ |
| Second removal | Success, `out` is $9$ | Empty queue |

<div class="spiegazione">

The first call finds a null `front` and returns `false` before writing to `out`. The successful insertion starts with a null `rear`, so both ends identify the new node. During the second insertion the allocator returns a null pointer. The function returns before changing links, so the node with key $9$ remains the only node. The removal copies $9$, advances the front to its null successor, clears the other end and frees the node.

To check, count the nodes obtained and those freed. There is one successful allocation and one deallocation. The number of reachable nodes is therefore zero. The empty-queue invariant requires `front` and `rear` to be null, and the function restores both values on this path.

</div>

## Exercise 3

Function `dequeue_bad` is a version of `dequeue` lacking one branch. Starting from an empty queue, `enqueue(&q, 5)`, `dequeue_bad(&q, &out)` and `enqueue(&q, 8)` are executed. Identify the error, describe what happens in the third call and correct the function. `Queue`, `enqueue`, `<stdbool.h>` and `<stdlib.h>` are visible.

```c
bool dequeue_bad(Queue *q, int *out)
{
    Node *old = q->front;
    if (old == NULL) {
        return false;
    }
    *out = old->key;
    q->front = old->next;
    free(old);
    return true;
}
```

| After the call | `front` | `rear` |
|---|---|---|
| `enqueue(&q, 5)` | node $5$ | node $5$ |
| `dequeue_bad(&q, &out)` | null | address of node $5$, already freed |

The corrected function adds the branch that sets `rear` to null when the queue becomes empty.

```c
bool dequeue(Queue *q, int *out)
{
    Node *old = q->front;
    if (old == NULL) {
        return false;
    }
    *out = old->key;
    q->front = old->next;
    if (q->front == NULL) {
        q->rear = NULL;
    }
    free(old);
    return true;
}
```

<div class="spiegazione">

The empty queue is represented by `front` and `rear` both null. After the only removal `front` receives the null successor of node $5$, while `rear` keeps the address of that node, which `free` has just released. Member `rear` therefore holds a dangling pointer, and the queue invariant is not satisfied.

When the lifetime of an object ends, the value of a pointer to that object becomes indeterminate. Hence the comparison `q->rear == NULL` in the third call already has **undefined behavior**. In the observed run the comparison is false, and `enqueue` takes the branch for a nonempty queue. The assignment `q->rear->next = node` then writes into an object whose lifetime has ended. When compiled with `-fsanitize=address`, execution stops on that line with the message `heap-use-after-free` for a write. Even if the write had no visible effect, `front` would stay null and node $8$ would not be reachable from the head.

With the added branch, removing the last node restores the empty queue. The third call then takes the branch for an empty queue, assigns node $8$ to both ends, and the queue holds $\langle 8\rangle$.

</div>
