## Exercise 1

Write function `list_copy` with the following contract. `src` is the head of a linear list, possibly empty, which the function does not modify. If every allocation succeeds, the function stores in `*dst` the head of a new owning list with the same keys in the same order and returns `true`. If an allocation fails, it frees the nodes already allocated, leaves `*dst` unchanged and returns `false`. Then write the output of the test program. `Node`, function `free_list`, which frees an owning list, `<stdbool.h>`, `<stdio.h>` and `<stdlib.h>` are visible.

```c
bool list_copy(const Node *src, Node **dst);

int main(void)
{
    Node c = {4, NULL}, b = {1, &c}, a = {3, &b};
    Node *copy = NULL;
    if (!list_copy(&a, &copy)) {
        return EXIT_FAILURE;
    }
    copy->key = 8;
    printf("%d %d\n", a.key, copy->key);
    printf("%d\n", copy->next != &b);
    free_list(copy);
    return EXIT_SUCCESS;
}
```

The following function satisfies the contract.

```c
bool list_copy(const Node *src, Node **dst)
{
    Node *copy = NULL;
    Node **link = &copy;
    for (const Node *p = src; p != NULL; p = p->next) {
        Node *node = malloc(sizeof *node);
        if (node == NULL) {
            free_list(copy);
            return false;
        }
        node->key = p->key;
        node->next = NULL;
        *link = node;
        link = &node->next;
    }
    *dst = copy;
    return true;
}
```

The test program prints two lines.

```text
3 8
1
```

<div class="spiegazione">

The copy is built in the local variable `copy`, so `*dst` changes only when the new list is complete. Pointer `link` holds the address of the link where the next node must be written. Initially it is `&copy`, and after each node it becomes the address of that node's `next` member, so the keys keep the same order. Each new node receives a null successor before it is linked. Hence after every iteration the partial copy is a linear list terminated by the null pointer, and `free_list(copy)` can free it when `malloc` fails. With `src` null the loop performs no iterations and `*dst` receives the empty list.

In the test program the source nodes are automatic, while those of the copy are allocated by `list_copy`. The two lists have distinct nodes, so the assignment `copy->key = 8` leaves $3$ in `a.key`. The successor of the first copied node differs from `&b`, so the comparison `!=` evaluates to $1$. Copying only the head pointer would instead have given two names for the same nodes.

</div>

## Exercise 2

The following program is meant to print `2 1` and free the list. Identify the two errors, state what it prints and correct it with as few changes as possible.

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key;
    struct Node *next;
} Node;

void push(Node *head, int key)
{
    Node *node = malloc(sizeof *node);
    if (node == NULL) {
        return;
    }
    node->key = key;
    node->next = head;
    head = node;
}

void free_list(Node *head)
{
    for (Node *p = head; p != NULL; p = p->next) {
        free(p);
    }
}

int main(void)
{
    Node *head = NULL;
    push(head, 1);
    push(head, 2);
    for (const Node *p = head; p != NULL; p = p->next) {
        printf("%d ", p->key);
    }
    printf("\n");
    free_list(head);
    return 0;
}
```

The program prints an empty line. The two corrected functions are the following, and in `main` the calls become `push(&head, 1);` and `push(&head, 2);`.

```c
void push(Node **head, int key)
{
    Node *node = malloc(sizeof *node);
    if (node == NULL) {
        return;
    }
    node->key = key;
    node->next = *head;
    *head = node;
}

void free_list(Node *head)
{
    while (head != NULL) {
        Node *next = head->next;
        free(head);
        head = next;
    }
}
```

With the corrections the program prints `2 1 ` followed by a newline.

<div class="spiegazione">

The first error is in `push`. In C arguments are passed by value, so parameter `head` is a copy of the pointer in `main`. The assignment `head = node` changes only that copy, and the variable `head` of `main` stays null. The printing loop performs no iterations, so the output is an empty line. The two allocated nodes are not reachable from any pointer, and with `-fsanitize=address` the program terminates reporting two leaked blocks. The correction passes the address of the head variable, as in `push_front` from the chapter.

The second error is in `free_list` and does not show up while the list is empty. After `free(p)` the update `p = p->next` reads a member of an object whose lifetime has ended, which has **undefined behavior**. GCC 13 already reports it at compile time with the warning `-Wuse-after-free`, enabled by `-Wall`. After the first correction the list holds two nodes, and AddressSanitizer stops execution with `heap-use-after-free` for a read. The corrected version saves the successor before `free`, as in the **complete deallocation of a list**.

</div>

## Exercise 3

Write the exact output of the program. Assume that every allocation succeeds.

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key;
    struct Node *next;
} Node;

void free_list(Node *head)
{
    while (head != NULL) {
        Node *next = head->next;
        free(head);
        head = next;
    }
}

Node *reverse(Node *head)
{
    Node *done = NULL;
    while (head != NULL) {
        Node *rest = head->next;
        head->next = done;
        done = head;
        head = rest;
    }
    return done;
}

void print(const Node *p)
{
    for (; p != NULL; p = p->next) {
        printf("%d%s", p->key, p->next != NULL ? " -> " : "\n");
    }
}

int main(void)
{
    Node *head = NULL;
    for (int k = 1; k <= 4; ++k) {
        Node *node = malloc(sizeof *node);
        if (node == NULL) {
            free_list(head);
            return EXIT_FAILURE;
        }
        node->key = k * k;
        node->next = head;
        head = node;
    }
    print(head);
    Node *second = head->next;
    head = reverse(head);
    print(head);
    printf("%d %d\n", second->key, second->next->key);
    free_list(head);
    return EXIT_SUCCESS;
}
```

| Iteration of `reverse` | Node moved | List from `done` | List from `head` |
|---|---|---|---|
| $1$ | $16$ | $\langle 16\rangle$ | $\langle 9,4,1\rangle$ |
| $2$ | $9$ | $\langle 9,16\rangle$ | $\langle 4,1\rangle$ |
| $3$ | $4$ | $\langle 4,9,16\rangle$ | $\langle 1\rangle$ |
| $4$ | $1$ | $\langle 1,4,9,16\rangle$ | empty list |

```text
16 -> 9 -> 4 -> 1
1 -> 4 -> 9 -> 16
9 16
```

<div class="spiegazione">

The loop in `main` inserts the squares $1$, $4$, $9$ and $16$ at the head, so the list built has the reverse order, $\langle 16,9,4,1\rangle$. Function `print` writes an arrow after each key, or a newline when the successor is null, and thus produces the first line. Pointer `second` designates the node with key $9$.

Function `reverse` maintains two disjoint lists, the already reversed one starting at `done` and the one still to visit starting at `head`. At each iteration the successor is saved in `rest` before `head->next` is modified, and then the node moves to the front of `done`. Without that saved value the assignment to `head->next` would make the rest of the list unreachable. The function neither allocates nor frees nodes, so only the links change.

The node designated by `second` is therefore the same object as before. After the reversal its successor is the node with key $16$, and the last line is `9 16`. Finally `free_list` frees the four nodes starting from the new head, which reaches all of them.

</div>
