## Exercise 1

An owning list has keys $\langle 9,3,5\rangle$ from head to end. Perform two head removals using `pop_front` from the chapter. Determine the two values written into the output objects and the remaining keys.

| Operation | Removed value | Keys after the operation |
|---|---|---|
| First removal | $9$ | $\langle 3,5\rangle$ |
| Second removal | $3$ | $5$ |

<div class="spiegazione">

The first removal copies the initial node's value before deallocation. The new head is the link to the node whose key is $3$. The node $9$ is detached, and freeing it leaves the suffix intact. At the second call the head is therefore the node $3$, which is read and freed through the same sequence of operations. Its successor is node $5$, now the only live node at the head. Both operations succeed because they encounter a nonnull head.

To check, reconstruct the initial sequence by joining the removed values in order and then the remaining list. This gives $\langle 9,3,5\rangle$. Two of the three nodes have been freed, so one must remain. The observed head points to that node, and its successor is null.

</div>

## Exercise 2

An owning list has keys $\langle 4,7,4,9\rangle$ in order. `prev` points to the second occurrence of $4$, which is at the penultimate position. Give the keys reachable after the fragment. Assume `Node` is visible and the fragment uses `<stdlib.h>`.
```c
Node *old = prev->next;
prev->next = old->next;
free(old);
```

The final chain has keys $\langle 4,7,4\rangle$. The outgoing link of the node designated by `prev` is the null pointer.

<div class="spiegazione">

The position identifies `prev`, so the duplicate key does not make the object ambiguous. Its successor is the last node, holding $9$. Since the last node's successor is null, the assignment copies the null pointer into `prev->next`. The node $9$ becomes unreachable from the head, and `free` ends its lifetime. The prefix up to `prev` remains live and retains its own links.

To verify, count the visits from the head using the updated last link. The traversal visits the first $4$, then $7$, then the second $4$, and reaches a null pointer. The remaining list has three nodes, consistent with removing exactly one node from a list of four. The successor of `old` was accessed before `free`.

</div>

## Exercise 3

An owning list has keys $\langle 4,4,7,4\rangle$ and nodes obtained with `malloc`. The call `remove_all(&head, 4)` is executed. Determine the return value, the remaining keys and the link designated by `link` at each iteration. `Node`, `<stddef.h>` and `<stdlib.h>` are visible.

```c
size_t remove_all(Node **head, int key)
{
    size_t removed = 0;
    Node **link = head;
    while (*link != NULL) {
        if ((*link)->key == key) {
            Node *old = *link;
            *link = old->next;
            free(old);
            ++removed;
        } else {
            link = &(*link)->next;
        }
    }
    return removed;
}
```

| Iteration | `link` designates | Node in `*link` | Action | Keys afterwards |
|---|---|---|---|---|
| $1$ | `head` | first $4$ | removal | $\langle 4,7,4\rangle$ |
| $2$ | `head` | second $4$ | removal | $\langle 7,4\rangle$ |
| $3$ | `head` | $7$ | advance | $\langle 7,4\rangle$ |
| $4$ | `next` of node $7$ | last $4$ | removal | $\langle 7\rangle$ |

On entry to a fifth iteration `*link` is null and the loop ends. The function returns $3$ and the final list is $\langle 7\rangle$.

<div class="spiegazione">

When the key matches, the function saves the node in `old`, copies its successor into the link designated by `link` and only then frees the node. The successor is therefore read while the node is still alive. After a removal `link` stays unchanged, because the link it designates now holds the next node, which has not yet been examined. For this reason the two initial $4$s are removed in two consecutive iterations, both on link `head`.

Node $7$ does not satisfy the condition, so `link` moves to the address of its `next` member. The third removal writes the null successor of the last node into that member, and node $7$ becomes the last node of the list. If `link = &(*link)->next` were also executed after each removal, the second $4$ would be skipped without being examined. Counter `removed` grows by one for each call to `free`, and indeed $3+1=4$ recovers the initial length.

</div>
