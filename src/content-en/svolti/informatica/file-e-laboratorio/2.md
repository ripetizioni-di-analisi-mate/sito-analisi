## Exercise 1

A stream supplies `2589` followed by a newline. The program makes two successful calls to `fgets(line, 4, file)`. Give the strings in order and say which one contains the delimiter.

The first string is `"258"`. The second is `"9\n"`, which contains the delimiter.

<div class="spiegazione">

Capacity $4$ leaves exactly three positions for input characters and one for the terminator. The first call stops after `8` because of the capacity limit. The second starts at `9` and stops at the delimiter. These are two fragments of a single physical line. As a check, concatenating the fragments reconstructs the four original digits and their newline without loss or duplication.

</div>

## Exercise 2

The file supplies the sequence `A\nZ\n\n`. A loop reads with `fgetc` and separately counts letters and newlines. Find both counts and the number of successful character reads. The full read completes without errors.

The input contains the letters `A` and `Z` and three newlines. There are $2+3=5$ successful reads.

<div class="spiegazione">

Each successful call produces one character. The empty line contributes its own delimiter. Only `A` and `Z` increment the letter counter. The call after the final five characters reports end-of-file and does not count as a successful read. Check by enumerating the sequence positions. The letters occur first and third, and the delimiters second, fourth and fifth. No other characters remain to count.

</div>

## Exercise 3

The stream `file` supplies the sequence `ab\ncdef\ng\n` and all reads complete without errors. The following loop alternates `fgets` and `fgetc` on the same stream. Write the output and identify the file characters that appear in no string read.

```c
char buf[4];
for (int step = 1; step <= 3; ++step) {
    if (fgets(buf, sizeof buf, file) == NULL) {
        break;
    }
    int ch = fgetc(file);
    printf("%d %zu %d\n", step, strlen(buf), ch == '\n');
}
```

| `step` | `buf` | `ch` | Printed line |
|---:|---|---|---|
| 1 | `"ab\n"` | `'c'` | `1 3 0` |
| 2 | `"def"` | `'\n'` | `2 3 1` |
| 3 | `"g\n"` | `EOF` | `3 2 0` |

```text
1 3 0
2 3 1
3 2 0
```

The character `c` and the newline after `def` do not appear in `buf`.

<div class="spiegazione">

The two functions share the stream position, so each call resumes from the character after the last one consumed. The first `fgets` stops after the newline that follows `ab` and keeps three characters. The next `fgetc` consumes `c`, which is therefore missing from the second string. With capacity $4$ the second `fgets` reads `def` and stops at the capacity limit, before the delimiter. The delimiter is then read by `fgetc`, and the comparison `ch == '\n'` gives $1$. The third `fgets` obtains `"g\n"`, of length $2$. The file is now exhausted, so `fgetc` returns `EOF` and the comparison gives $0$. The type `int` of `ch` can represent `EOF` alongside every character read. The three strings contain $3+3+2=8$ of the $10$ characters in the file. The two missing characters are the ones consumed by the successful calls to `fgetc`. The fragment uses `<stdio.h>` and `<string.h>`.

</div>
