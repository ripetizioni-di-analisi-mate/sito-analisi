## Exercise 1

Accept lines containing exactly one integer from $-5$ to $12$. The four lines are `0`, `14`, `-5` and `13 q`. List the accepted readings in order and compute their sum.

The two accepted integers are $0$ and $-5$. Their sum is $0-5=-5$.

<div class="spiegazione">

The value $0$ satisfies the bound and occupies its whole line. The value $14$ exceeds the upper limit. The value $-5$ is accepted because the interval includes its lower endpoint. The fourth line is rejected both because the parsed value is out of range and because a character remains after the digits. Check the sum by removing the two rejected lines and adding the remaining numbers directly. The reading order is preserved.

</div>

## Exercise 2

In the C locale, a successful call executes `fprintf(file, "%d;%d\n", 7, -25)`. Reconstruct the characters emitted and the return value.

The output is `"7;-25\n"`. The count is $1+1+3+1=6$.

<div class="spiegazione">

The first specifier writes one digit, the format delimiter occupies one character, and the second specifier writes the sign and two digits. The newline is one more character. The function returns the total number of characters transmitted. For a separate check, enumerate the output characters as a digit, delimiter, minus sign, two digits and newline. Those items cover every position.

</div>

## Exercise 3

A line is accepted if it contains exactly one integer from $-20$ to $20$, with leading and trailing whitespace allowed. The lines are `7`, `-12`, `105`, `4 4`, `+5` and a line formed by a space, `-3` and another space. For each accepted line the program executes the following fragment, with `k` of type `size_t` starting from zero and `total` of type `long`. The stream `out` is open for writing and all writes succeed. Reconstruct the lines produced in the C locale and the final value of `total`, which starts from zero.

```c
++k;
int written = fprintf(out, "%2zu:%4d\n", k, value);
if (written < 0) {
    return 0;
}
total += written;
```

```text
 1:   7
 2: -12
 3:   5
 4:  -3
```

Each line contains $2+1+4+1=8$ characters, so at the end `total` is $4\cdot 8=32$.

<div class="spiegazione">

The line `105` exceeds the upper limit and the line `4 4` contains a second token after the first integer, so both are rejected. The line `+5` is accepted because `strtol` recognises the plus sign and the value $5$ lies in the interval. The line with `-3` is accepted because the spaces before and after the number are allowed. There are therefore four accepted lines, and `k` takes the values $1$ to $4$ in order. The specifier `%2zu` writes `k` right-aligned in a field of minimum width $2$, and `%4d` writes the value in a field of minimum width $4$. The minus sign occupies one position of the field, so `-12` receives one padding space and `-3` receives two. The specifier `%d` writes a sign only for negative values, so $5$ appears without `+`. Each write transmits two characters for the index, the colon, four characters for the value and the newline.

</div>
