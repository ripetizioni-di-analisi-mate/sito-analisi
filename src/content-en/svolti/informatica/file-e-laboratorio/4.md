## Exercise 1

In the C locale, the line `" -18!\n"` is passed to `strtol(line, &end, 10)`. Find the converted value and decide whether the line is valid when only one integer and whitespace are allowed.

Conversion returns $-18$. `end` points to `!`, so the line is rejected.

<div class="spiegazione">

The conversion skips leading whitespace, recognises the sign and consumes digits up to the first non-digit character. The character `!` remains in the unparsed part. Because it is not whitespace, the final check fails even though the converted value is representable. Compare with the line `" -18\n"` as a check. In that case the end pointer refers to a newline, which the whitespace check can step over to reach the terminator.

</div>

## Exercise 2

The format requires two integers separated by at least one space or tab. Compare the lines `"7-2\n"` and `"7 -2\n"`. Determine validity and give both fields for a valid line.

`"7-2\n"` is rejected. `"7 -2\n"` yields the fields $7$ and $-2$.

<div class="spiegazione">

After the first integer, the end pointer refers to `-` in the first line. The required separator is missing, so the procedure stops before trying the second conversion. In the second line the pointer refers to the space. The next conversion can skip it and then use the minus sign. The digits end before the newline allowed by the specification. To check, split the valid line at its space. The resulting tokens are exactly the two required integers.

</div>

## Exercise 3

The following loop adds the integers of a line by calling `strtol` as long as it finds digits. In the C locale `line` points to the string `"12 -3+4  7x9\n"`. Trace the conversions, and give the final values of `count` and `sum` and the character that `p` points to. Then decide whether the line is valid when the specification requires integers separated by at least one space or tab, with only whitespace after the last one.

```c
const char *p = line;
char *end;
long sum = 0;
int count = 0;
for (;;) {
    errno = 0;
    long value = strtol(p, &end, 10);
    if (end == p || errno == ERANGE) {
        break;
    }
    sum += value;
    ++count;
    p = end;
}
```

| Conversion | Text from `p` | Value | Character at `end` |
|---:|---|---:|---|
| 1 | `"12 -3+4  7x9\n"` | $12$ | space |
| 2 | `" -3+4  7x9\n"` | $-3$ | `+` |
| 3 | `"+4  7x9\n"` | $4$ | space |
| 4 | `"  7x9\n"` | $7$ | `x` |
| 5 | `"x9\n"` | $0$, no conversion | `x` |

At the end `count` is $4$, `sum` is $12-3+4+7=20$ and `p` points to `x`. The line is not valid.

<div class="spiegazione">

Each call leaves `end` on the first character that does not belong to the number. The assignment `p = end` makes the next conversion start from that character. In the third conversion the text begins with `+`, which `strtol` recognises as a sign, so `-3+4` produces two separate values. The fourth skips two spaces and stops at `x`. In the fifth the first character is `x`, so there are no digits to convert. In this case `strtol` returns zero and assigns the value of `p` to `end`, so the condition `end == p` ends the loop. Under the delimiter rule the line is **rejected**, because after the second integer `end` points to `+`, which is neither a space nor a tab. The character `x` after the fourth integer is a second reason for rejection. The fragment uses `<errno.h>` and `<stdlib.h>`.

</div>
