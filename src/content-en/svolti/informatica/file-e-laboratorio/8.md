## Exercise 1

A reader has validated and stored the `(time, level)` records `(2, 1)`, `(5, 3)`, `(9, 3)`, `(12, 1)` and `(15, 2)` in chronological order. Each value applies until the next record. Time is a nonnegative `long`. Write the core calculation on the array `records` of length `count` and find the duration at level $3$.

```c
long duration = 0;
for (size_t i = 1; i < count; ++i) {
    if (records[i - 1].level == 3) {
        duration += records[i].time - records[i - 1].time;
    }
}
```

The duration is $(9-5)+(12-9)=7$.

<div class="spiegazione">

Each iteration assigns the left-hand record’s level to the interval. The interval $[2,5)$ has level $1$, so it does not contribute. The intervals $[5,9)$ and $[9,12)$ both have level $3$ and add $4$ and $3$, respectively. The final completed interval has level $1$. For an independent check, merge the two adjacent stretches at level $3$ and measure the length of $[5,12)$, which is $7$. Every partial sum is at most the final time minus the first, which is representable. The code uses `size_t` from `<stddef.h>`.

</div>

## Exercise 2

The model permits nondecreasing times. Using the same interval rule, find the duration at level $3$ for records `(4, 3)`, `(4, 2)`, `(8, 3)` and `(11, 1)`. Also find the result if the only record is `(21, 3)`.

In the first case the duration is $(4-4)+(11-8)=3$. For a single record it is $0$.

<div class="spiegazione">

The two records at time $4$ bound an empty interval, so the first level $3$ lasts zero time. From $4$ to $8$ the level is $2$. The interval from $8$ to $11$ has level $3$ and contributes its full length. With a single record, the loop starts at index $1$ and the length is $1$, so the body does not run. Check directly from the definition by counting intervals between consecutive records. A single record gives no consecutive pairs and the empty sum is zero.

</div>

## Exercise 3

The level of a record applies from its time until the time of the next record, as in the previous exercises. The following function should return the time spent at level `level`, with nondecreasing times and representable sums. For the records `(0, 2)`, `(3, 5)`, `(8, 5)`, `(10, 2)`, `(14, 5)` and `(20, 1)` compute the function's result for levels $5$, $2$ and $1$, find the error and correct it. Finally, say whether the check on the total duration detects the error.

```c
struct sample {
    long time;
    int level;
};

static long time_at_level(const struct sample *records, size_t count, int level)
{
    long duration = 0;
    for (size_t i = 1; i < count; ++i) {
        if (records[i].level == level) {
            duration += records[i].time - records[i - 1].time;
        }
    }
    return duration;
}
```

| Level | Given function | Correct value |
|---:|---:|---:|
| 5 | $12$ | $13$ |
| 2 | $2$ | $7$ |
| 1 | $6$ | $0$ |

The correction replaces the condition with `records[i - 1].level == level`.

<div class="spiegazione">

The given function compares the level of the right-hand record, so it assigns to each interval $[t_{i-1},t_i)$ the level that starts at $t_i$. For level $5$ it counts $[0,3)$, $[3,8)$ and $[10,14)$, for a total of $3+5+4=12$. Under the correct rule the stretches at level $5$ are $[3,8)$, $[8,10)$ and $[14,20)$, of length $5+2+6=13$. Level $1$ occurs only in the last record, which closes the observation, so its correct duration is zero. The given function instead assigns it the interval $[14,20)$, of length $6$. The correct durations sum to $13+7+0=20$, and the wrong ones also sum to $12+2+6=20$. Both equal $t_5-t_0=20$, because in both versions each interval is assigned to exactly one level. The check on the total is therefore satisfied by the faulty function as well. The error concerns how intervals are assigned to levels and is detected with a level of known duration, such as level $1$ of the last record. The code uses `size_t` from `<stddef.h>`.

</div>
