## Exercise 1

Write a C17 program that receives a filename and prints the sum of valid readings in category $2$. A valid line has at most $60$ characters before its newline and contains two decimal integers, a category in $[0,2]$ and a reading in $[10,30]$. Fields are separated by spaces or tabs. Leading and trailing whitespace is allowed. All file lines end in a newline and the text contains no embedded null characters. Discard invalid lines and use a failure exit status for an I/O problem or an unrepresentable sum. Test with `2 11`, `2 23`, `0 30`, `2 31` and `2 24 5`.

```c
#include <ctype.h>
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static int parse_row(const char *line, int *category, int *reading)
{
    char *end;
    errno = 0;
    long c = strtol(line, &end, 10);
    if (end == line || errno == ERANGE || c < 0 || c > 2 ||
        (*end != ' ' && *end != '\t')) {
        return 0;
    }

    const char *start = end;
    while (*start == ' ' || *start == '\t') {
        ++start;
    }
    if (isspace((unsigned char)*start)) {
        return 0;
    }
    errno = 0;
    long v = strtol(start, &end, 10);
    if (end == start || errno == ERANGE || v < 10 || v > 30) {
        return 0;
    }
    while (isspace((unsigned char)*end)) {
        ++end;
    }
    if (*end != '\0') {
        return 0;
    }
    *category = (int)c;
    *reading = (int)v;
    return 1;
}

int main(int argc, char *argv[])
{
    if (argc != 2) {
        return EXIT_FAILURE;
    }
    FILE *input = fopen(argv[1], "r");
    if (input == NULL) {
        return EXIT_FAILURE;
    }

    char line[64];
    long total = 0;
    int ok = 1;
    while (fgets(line, sizeof line, input) != NULL) {
        char *newline = strchr(line, '\n');
        if (newline == NULL) {
            int ch;
            do {
                ch = fgetc(input);
            } while (ch != EOF && ch != '\n');
            if (ferror(input)) {
                break;
            }
            continue;
        }
        if (newline - line > 60) {
            continue;
        }

        int category, reading;
        if (parse_row(line, &category, &reading) && category == 2) {
            if (total > LONG_MAX - reading) {
                ok = 0;
                break;
            }
            total += reading;
        }
    }
    if (ferror(input)) {
        ok = 0;
    }
    if (fclose(input) != 0) {
        ok = 0;
    }
    if (!ok || printf("%ld\n", total) < 0 || fflush(stdout) == EOF) {
        return EXIT_FAILURE;
    }
    return EXIT_SUCCESS;
}
```

For this file the expected output is `34` followed by a newline.

<div class="spiegazione">

The input routine checks the full line and consumes the remaining characters of lines that do not fit in the buffer. `parse_row` checks both integers, the separator and the terminator before writing to its output parameters. The accumulator changes only after the desired category has been accepted and the `long` limit has been checked. After each line it therefore equals the sum of valid readings in that category seen so far. Check by direct enumeration. The first two lines contribute $11$ and $23$, the third is valid but in category $0$, the fourth exceeds the limit, and the fifth has an extra field. The expected total is $11+23=34$. As a second test, an empty file exits successfully and prints `0`.

</div>

## Exercise 2

To test the preceding program, construct a file with two lines. The first starts with $73$ spaces and ends with `2 25` and a newline. The second is `2 10` followed by a newline. Find the output and explain what problem this test detects.

The first line has more than $60$ characters before its delimiter and is discarded as a whole. The output is `10` followed by a newline.

<div class="spiegazione">

The first read supplies a fragment with no newline. If reading and validation resumed immediately, the last fragment might look like an independent line with reading $25$. The procedure instead consumes the remainder up to the delimiter. The next read starts on the second line and validates it. For an independent check, count the physical lines, filter out the overlong first line and sum the only remaining reading, $10$. The test distinguishes line processing from fragment processing.

</div>

## Exercise 3

The program of Exercise 1 receives a file with six lines, each ending in a newline. The first consists of a tab, `2`, a tab, `15` and another tab. The following ones are `+2 +20`, `2 0x1F`, the line with $56$ spaces followed by `2 12`, the line with $57$ spaces followed by `2 13` and finally `2 010`. Find the output and, for each line, whether it contributes to the sum.

| Line | Characters before the newline | Contribution |
|---:|---:|---:|
| 1 | $6$ | $15$ |
| 2 | $6$ | $20$ |
| 3 | $6$ | $0$ |
| 4 | $60$ | $12$ |
| 5 | $61$ | $0$ |
| 6 | $5$ | $10$ |

The output is `57` followed by a newline.

<div class="spiegazione">

In the first line `strtol` skips the leading tab and after `2` finds a tab as the delimiter. The trailing tab is also allowed whitespace, so the reading $15$ is accepted. In the second line both fields carry a plus sign, which `strtol` recognises, so the category is $2$ and the reading $20$. In the third the base-ten conversion reads only `0` and stops at `x`. The reading $0$ lies outside $[10,30]$, so `parse_row` rejects the line. The fourth line has exactly $60$ characters before the newline, so the condition `newline - line > 60` is false and the line is accepted. The fifth has $61$ and is discarded, even though it fits entirely in the $64$-character buffer. In the sixth the leading zero does not change the base, which is fixed at $10$, and the reading is $10$, the smallest value allowed. The sum is therefore $15+20+12+10=57$. Lines $4$ and $5$ test the length boundary, while lines $3$ and $6$ test the base of the conversion.

</div>
