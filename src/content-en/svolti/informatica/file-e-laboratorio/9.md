## Exercise 1

The file `misure.txt` contains the lines `4` and `9`, each ending in a newline. The following fragment, inside `main`, should print the number of lines and the sum of the readings. The stream `file` is open for reading on `misure.txt` and all reads complete without errors. Find the output, identify the error and write the correct loop.

```c
char line[32];
long sum = 0;
int rows = 0;
while (!feof(file)) {
    fgets(line, sizeof line, file);
    sum += strtol(line, NULL, 10);
    ++rows;
}
printf("%d %ld\n", rows, sum);
```

```text
3 22
```

The correct loop uses the result of the read as its guard.

```c
while (fgets(line, sizeof line, file) != NULL) {
    sum += strtol(line, NULL, 10);
    ++rows;
}
if (ferror(file)) {
    return EXIT_FAILURE;
}
printf("%d %ld\n", rows, sum);
```

With the correct loop the output is `2 13`.

<div class="spiegazione">

The guard `!feof(file)` describes the state of the stream before the read. After the second `fgets` the stream has consumed `9` and the newline, but no read has yet tried to go past the end. The end-of-file indicator is therefore clear and the body runs a third time. The third `fgets` meets the end of the file at once and returns `NULL`. Under the contract of `fgets`, when end-of-file arrives before any character is read the contents of the array remain unchanged, so `line` still holds `"9\n"`. The sum receives $9$ a second time and `rows` reaches $3$, which gives the output `3 22`. In the correct loop the body runs only after a successful read, so each line enters the sum exactly once. After the loop `ferror` distinguishes the normal end of the file from a read interrupted by an error, and in the second case `main` returns `EXIT_FAILURE` without printing. The fragment uses `<stdio.h>` and `<stdlib.h>`.

</div>

## Exercise 2

The following function should print the number of lines and the sum of the readings. The stream `file` is open for reading on a file with the lines `6`, `10` and `8`, each ending in a newline, and all reads complete without errors. Find the output, explain the error and correct it without reopening the file.

```c
static int print_rows_and_sum(FILE *file)
{
    char line[32];
    long rows = 0, sum = 0;
    while (fgets(line, sizeof line, file) != NULL) {
        ++rows;
    }
    while (fgets(line, sizeof line, file) != NULL) {
        sum += strtol(line, NULL, 10);
    }
    if (ferror(file)) {
        return 0;
    }
    return printf("%ld %ld\n", rows, sum) >= 0;
}
```

```text
3 0
```

The correction inserts the following check between the two loops.

```c
if (ferror(file) || fseek(file, 0L, SEEK_SET) != 0) {
    return 0;
}
```

With the correction the output is `3 24`.

<div class="spiegazione">

The position is part of the state of the stream. The first loop ends when `fgets` returns `NULL` at end-of-file, so the position is at the end and the end-of-file indicator is set. The second loop starts from that position, so its first call returns `NULL` at once and the body never runs. The output is `3 0`, with the correct number of lines and a zero sum. The correction moves the stream back to the beginning with `fseek(file, 0L, SEEK_SET)`, which returns zero on success and clears the end-of-file indicator. The check on `ferror` placed before the repositioning skips the second pass when the first one was interrupted by an error. With the correction the second loop reads the three lines again, and the output is `3 24` because $6+10+8=24$. The same result is obtained with a single loop that updates `rows` and `sum` for every line read.

</div>

## Exercise 3

The following function should count the lines of a file. Assume that pointers occupy $8$ bytes, that reads succeed and that the file contains the lines `temperatura` and `21`, each ending in a newline. The function is called with an array `char buffer[64]`. Find the return value, explain the compiler warning and correct the two errors.

```c
static size_t count_lines(FILE *file, char line[64])
{
    size_t lines = 0;
    while (fgets(line, sizeof line, file) != NULL) {
        ++lines;
    }
    return lines;
}
```

```text
warning: 'sizeof' on array function parameter 'line' will return size of 'char *' [-Wsizeof-array-argument]
```

The function returns $3$. The corrected version receives the capacity and counts newlines.

```c
static int count_lines(FILE *file, char *line, int capacity, size_t *lines)
{
    *lines = 0;
    while (fgets(line, capacity, file) != NULL) {
        if (strchr(line, '\n') != NULL) {
            ++*lines;
        }
    }
    return ferror(file) == 0;
}
```

The call `count_lines(file, buffer, (int)sizeof buffer, &n)` gives `n` equal to $2$ and return value $1$.

<div class="spiegazione">

A parameter declared as `char line[64]` has type `char *`, because under the adjustment rule for parameters an array type becomes a pointer to the element type. In the body `sizeof line` is therefore $8$, the size of the pointer, and the length $64$ written in the declaration has no effect. With capacity $8$ each `fgets` reads at most seven characters. The line `temperatura` has eleven letters, so it produces the fragments `"tempera"` and `"tura\n"`, followed by `"21\n"`. The function counts the successful calls and returns $3$. The second error is this very count, because one physical line can produce several fragments. The corrected version receives the capacity as a parameter and increments the counter only for a fragment that contains the newline, that is, for the end of a line. The expression `(int)sizeof buffer` is evaluated where `buffer` is still an array, so it equals $64$. Counting delimiters gives $2$ even with capacity $8$, so the result no longer depends on the capacity when every line ends in a newline. The fragment uses `<stdio.h>`, `<stddef.h>` and `<string.h>`.

</div>
