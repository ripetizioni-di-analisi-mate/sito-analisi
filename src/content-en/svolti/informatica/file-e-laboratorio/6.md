## Exercise 1

The accepted lines describe records `(A, 5)`, `(B, 7)`, `(A, -2)`, `(B, 9)` and `(A, 10)`. Start with two zero sums and update only the category just read. Find the category totals and compare them with the file total.

$$
s_A=5-2+10=13, \qquad s_B=7+9=16.
$$

The total is $13+16=29$.

<div class="spiegazione">

Each valid record enters one aggregate. The `A` readings form the first group and the `B` readings the second. After the third record, the pair of sums is $(3,7)$ because the negative reading changes only `A`. The fourth record takes `B` to $16$, then the fifth takes `A` to $13$. An independent calculation in reading order gives $5+7-2+9+10=29$. Their equality checks that each reading was counted once.

</div>

## Exercise 2

The `(id, level)` records are `(41, -5)`, `(12, -2)`, `(19, -2)` and `(51, -7)`. Find the identifier kept when selecting the first maximum and the one kept when selecting the last maximum.

The maximum is $-2$. The first identifier is $12$ and the last is $19$.

<div class="spiegazione">

The first record is the initial candidate because it is the first valid datum. The second replaces it because $-2>-5$. The third has the same level as the second. A strict comparison retains $12$, while allowing equality updates the identifier to $19$. The fourth level is lower and neither choice changes. For an independent check, identify the maximum in the list of levels and find all its positions. It occurs second and third.

</div>

## Exercise 3

The following function computes in a single pass the first maximum, the last minimum, the sum and the number of valid records. The `(id, level, valid)` records are `(31, -4, yes)`, `(17, -9, yes)`, `(12, -1, no)`, `(25, -4, yes)` and `(40, -9, yes)`. Find the fields of the result. Then state what the function returns if the only record is `(12, -1, no)` and what would happen if `max_level` were initialised to zero without using the field `found`.

```c
struct record {
    int id;
    int level;
    bool valid;
};

struct summary {
    bool found;
    int max_id, max_level;
    int min_id, min_level;
    long sum;
    size_t count;
};

static struct summary summarize(const struct record *r, size_t n)
{
    struct summary s = {false, 0, 0, 0, 0, 0, 0};
    for (size_t i = 0; i < n; ++i) {
        if (!r[i].valid) {
            continue;
        }
        if (!s.found || r[i].level > s.max_level) {
            s.max_id = r[i].id;
            s.max_level = r[i].level;
        }
        if (!s.found || r[i].level <= s.min_level) {
            s.min_id = r[i].id;
            s.min_level = r[i].level;
        }
        s.found = true;
        s.sum += r[i].level;
        ++s.count;
    }
    return s;
}
```

| `found` | `max_id` | `max_level` | `min_id` | `min_level` | `sum` | `count` |
|---|---:|---:|---:|---:|---:|---:|
| true | $31$ | $-4$ | $40$ | $-9$ | $-26$ | $4$ |

With the single record `(12, -1, no)` the result has `found` false, `count` equal to $0$ and all other fields zero.

<div class="spiegazione">

The record with identifier $12$ is not valid, so `continue` excludes it from every aggregate. The first valid record finds `found` false and initialises both candidates with $(31,-4)$. The second has level $-9$, which is less than $-4$, so it updates only the minimum. The fourth again has level $-4$. The strict comparison `>` is false, so the maximum stays associated with $31$, the first maximum. The fifth has level $-9$ and the comparison `<=` is true also in the case of equality, so the minimum moves to $40$, the last minimum. The sum is $-4-9-4-9=-26$ over $4$ records. If the only record is not valid, `found` stays false and the candidate fields are zero only because of the initialisation. With `max_level` initialised to zero and no `found`, no negative level exceeds zero. The field `max_id` would therefore stay $0$, an identifier that does not occur among the records. The fragment uses `<stdbool.h>` and `<stddef.h>`.

</div>
