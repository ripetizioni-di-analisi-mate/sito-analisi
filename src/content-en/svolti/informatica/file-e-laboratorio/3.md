## Exercise 1

The program processes three lines returned by `fgets`. A fourth call returns `NULL`. Immediately afterwards, `ferror(file)` returns a nonzero value. Find the number of lines processed and whether the input can be certified complete.

The program processed $3$ lines. An error interrupted input.

<div class="spiegazione">

The fourth call returned null, so it cannot be treated as a line read. The result from `ferror` reports a stream error. The count therefore describes the processed prefix, and the error prevents concluding that this prefix was the whole file. To check the reasoning, input with additional lines past the point of failure could produce exactly the same prefix. The observed result gives no information about those possible lines.

</div>

## Exercise 2

A file contains a single line with `65` and a delimiter. The first call to `fgets` succeeds and the next reaches end-of-file without error. Count the updates if the loop adds a reading only after a successful read, and find the sum.

There is $1$ update. The sum changes from $0$ to $65$.

<div class="spiegazione">

The loop accumulates only when `fgets` supplies a string, so it updates the sum after the first call. At end-of-file `fgets` returns a null pointer and the loop body does not run. The old string is not counted a second time. As a check, the prefix of successful reads contains one measurement. Its direct sum is $65$, which agrees with the accumulator.

</div>

## Exercise 3

The following function classifies the fragments read by `fgets` as complete lines, fragments of overlong lines and a final line without a newline. All reads complete without errors. Find the three counters for files with contents `31\n4`, `123456789\n` and `1234567`, and identify the wrong classification.

```c
static void classify(FILE *file, size_t *complete, size_t *partial, size_t *last)
{
    char line[8];
    *complete = *partial = *last = 0;
    while (fgets(line, sizeof line, file) != NULL) {
        if (strchr(line, '\n') != NULL) {
            ++*complete;
        } else if (feof(file)) {
            ++*last;
        } else {
            ++*partial;
        }
    }
}
```

| File contents | `complete` | `partial` | `last` |
|---|---:|---:|---:|
| `31\n4` | $1$ | $0$ | $1$ |
| `123456789\n` | $1$ | $1$ | $0$ |
| `1234567` | $0$ | $1$ | $0$ |

The third file contains a single line without a newline, which the function counts as a fragment of a long line.

<div class="spiegazione">

The end-of-file indicator is set only when a read tries to go past the last character. In the first file the second `fgets` reads `4` and looks for another character, so it reaches the end and sets the indicator. Therefore `feof` returns a nonzero value and the fragment goes into `last`. In the second file the first `fgets` stops after seven digits at the capacity limit, without reaching the end. The fragment `"1234567"` is then counted in `partial`, while the next read `"89\n"` is a complete line. In the third file the seven digits fill exactly the available space. Here too `fgets` stops at the capacity and does not try an eighth read, so the indicator stays clear and the final line ends up in `partial`. The next call returns `NULL` at end-of-file and the loop terminates. The edge case is therefore a final line without a delimiter that has exactly `sizeof line - 1` characters, that is $7$. The fragment uses `<stdio.h>`, `<stddef.h>` and `<string.h>`.

</div>
