## Exercise 1

The program processes three lines returned by `fgets`. A fourth call returns `NULL`. Immediately afterwards, `ferror(file)` returns a nonzero value. Find the number of lines processed and whether the input can be certified complete.

The program processed $3$ lines. An error interrupted input.

<div class="spiegazione">

The fourth call returned null, so it cannot be treated as a line read. The result from `ferror` reports a stream error. The count therefore describes the processed prefix, and the error prevents concluding that this prefix was the whole file. To check the reasoning, input with additional lines past the point of failure could produce exactly the same prefix. The observed result gives no information about those possible lines.

</div>

## Exercise 2

A file contains a single line with `65` and a delimiter. The first call to `fgets` succeeds and the next reaches end-of-file without error. Count the updates if the loop adds a reading only after a successful read, and find the sum.

There is $1$ update. The sum changes from $0$ to $65$.

<div class="spiegazione">

The loop accumulates only when `fgets` supplies a string, so it updates the sum after the first call. At end-of-file `fgets` returns a null pointer and the loop body does not run. The old string is not counted a second time. As a check, the prefix of successful reads contains one measurement. Its direct sum is $65$, which agrees with the accumulator.

</div>
