## Exercise 1

Append `"UV"` to `"largo"` within the destination array. Compare `char dst[8] = "largo";` and `char dst[7] = "largo";`. For each declaration, determine whether the append can produce a C string stored entirely in the array.

$$
\begin{aligned}
u &= 5,\qquad v=2,\\[6pt]
u+v &= 7,\\[6pt]
B_{\min} &= u+v+1=8 .
\end{aligned}
$$

```text
0   1   2   3   4   5   6   7
l   a   r   g   o   U   V   \0
```

<div class="spiegazione">

The original prefix takes five cells. The two new characters go at indices $5$ and $6$ because the added text starts where the original terminator was. The new string ends at index $7$. With a capacity of eight cells that index is valid, so the result is `"largoUV"`. With seven cells, index $7$ is the first excluded index and the terminator has no space.

An equivalent check starts from the space left for new characters after reserving the null cell. With eight cells, $8-1-5=2$ remain, exactly as required. With seven cells, $7-1-5=1$ remains, too little for both characters. Reserving one C byte for the null accounts for the two outcomes.

</div>

## Exercise 2

Write a function that appends one character different from `'\0'` to a string of known length. When there is too little space, the function must leave the array unchanged. Compare appending `'A'` to `char a[1] = "";` and `char b[2] = "";`.

```c
#include <stdbool.h>
#include <stddef.h>

bool append_char(char s[], size_t cap, size_t len, char ch)
{
    if (len >= cap || cap - len < 2 || ch == '\0') {
        return false;
    }
    s[len] = ch;
    s[len + 1] = '\0';
    return true;
}
```

| `s` | `cap` | `len` | `cap-len` | |
| --- | ---: | ---: | ---: | --- |
| `a` | $1$ | $0$ | $1$ | `false`, `""` |
| `b` | $2$ | $0$ | $2$ | `true`, `"A"` |

<div class="spiegazione">

The initial string is empty in both cases, so the terminator is at index $0$. Appending requires writing `'A'` into that cell and a new null into the next cell. The check first compares length with capacity. The subtraction is evaluated only when length is less than capacity, so it measures a positive number of available cells starting at that index. For `a` there is one cell left and the function returns before writing. For `b` the two assignments use indices $0$ and $1$.

To check, after the attempt the first element of `a` still holds `'\0'`, so its length remains $0$. In the second array `'\0'` is at index $1$, giving length $1$. In both arrays the terminator index is less than the capacity.

</div>

## Exercise 3

The following function must append the string `src` to the string `dst`, stored in an array of capacity `cap`, and return `false` without writing when there is too little space. Both arguments are valid C strings in distinct arrays, and `dst` has its terminator within the `cap` cells. Find the error in the space check by examining `char d[8] = "largo";` with `"UV"` and with `"UVW"`, and correct it.

```c
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

bool append_str(char dst[], size_t cap, const char src[])
{
    size_t u = strlen(dst);
    size_t v = strlen(src);
    if (u + v > cap) {
        return false;
    }
    for (size_t j = 0; j <= v; ++j) {
        dst[u + j] = src[j];
    }
    return true;
}
```

| `src` | $u$ | $v$ | $u+v+1$ | original function | corrected function |
| --- | ---: | ---: | ---: | --- | --- |
| `"UV"` | $5$ | $2$ | $8$ | `true`, `"largoUV"` | `true`, `"largoUV"` |
| `"UVW"` | $5$ | $3$ | $9$ | write to `d[8]` | `false`, `"largo"` |

The correction replaces only the rejection condition.

```c
    if (u >= cap || v > cap - 1 - u) {
        return false;
    }
```

<div class="spiegazione">

The loop also copies the terminator of `src`, because the condition is `j <= v`, so it writes to indices $u$ through $u+v$. By the capacity requirement for a concatenation, $u+v+1$ cells are therefore needed, that is $u+v<B$ with $B$ equal to `cap`. The original condition rejects only the cases with $u+v>B$, so it also accepts $u+v=B$. With `"UVW"` we have $u+v=8=B$, and copying the terminator writes to `d[8]`, outside the array. This write has **undefined behavior**. With `"UV"` the sum is $7$ and both versions produce `"largoUV"`. The corrected condition follows the form of the proof about capacity. By the **short-circuit** evaluation of `||`, the difference `cap - 1 - u` is evaluated only when $u<B$, and then it is representable in `size_t`. The sum $u+v$ is never formed, so the check stays exact even for lengths close to the maximum of `size_t`. With `"UVW"` we have $3>8-1-5=2$, so the function returns `false` before the loop and `d` still holds `"largo"`.

As a check, count the space after `"largo"`. The free cells are those at indices $5$, $6$ and $7$. Three characters and a terminator need four cells, while two characters and a terminator need three.

</div>
