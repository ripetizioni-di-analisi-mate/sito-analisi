## Exercise 1

In `int m[4][3];`, find the offset of `m[2][1]` from the start of the matrix. Express it in elements and in C bytes, assuming `sizeof(int) = 4`.

$$
\begin{aligned}
k &= 2\cdot3+1 = 7,\\[6pt]
b &= 7\cdot4 = 28 .
\end{aligned}
$$

<div class="spiegazione">

Each row contains three elements. The cell’s row index is $2$, so two whole rows precede its row. They account for $2\cdot3=6$ elements. Column index $1$ adds one element. The first byte of the cell is therefore after seven integers, each occupying four C bytes.

As a check, compute the offsets directly in C bytes. One row takes $3\cdot4=12$ C bytes, so the third row begins at $2\cdot12=24$. The required cell follows the first cell of that row, so its starting offset is $24+4=28$. In particular, $24\le28<36$, which is the range occupied by row $2$.

</div>

## Exercise 2

In `short m[3][5];`, on a machine where `sizeof(short) = 2`, the first byte of a cell lies at offset $26$ from the start of the object. Find the cell’s indices.

$$
\begin{aligned}
k &= \frac{26}{2}=13,\\[6pt]
13 &= 2\cdot5+3,\qquad 0\le 3<5,\\[6pt]
(r,c)&=(2,3) .
\end{aligned}
$$

<div class="spiegazione">

The offset is a multiple of the element size, so it corresponds to position $13$ in a zero-based linear count. To recover the row, divide by five, the number of elements in each row. The quotient $2$ counts whole preceding rows, while the remainder $3$ is the within-row index. Since $2<3$ and $3<5$, both indices fit the declared shape.

To check the result, start from the row boundaries in C bytes. Row $2$ starts at $2\cdot(5\cdot2)=20$ and ends before $30$. The offset within it is $26-20=6$. The first bytes of the row’s cells have local offsets $0$, $2$, $4$, $6$ and $8$, so the cell at $6$ has local index $3$.

</div>
