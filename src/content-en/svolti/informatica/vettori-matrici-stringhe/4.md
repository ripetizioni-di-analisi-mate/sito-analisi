## Exercise 1

In `int m[4][3];`, find the offset of `m[2][1]` from the start of the matrix. Express it in elements and in C bytes, assuming `sizeof(int) = 4`.

$$
\begin{aligned}
k &= 2\cdot3+1 = 7,\\[6pt]
b &= 7\cdot4 = 28 .
\end{aligned}
$$

<div class="spiegazione">

Each row contains three elements. The cell’s row index is $2$, so two whole rows precede its row. They account for $2\cdot3=6$ elements. Column index $1$ adds one element. The first byte of the cell is therefore after seven integers, each occupying four C bytes.

As a check, compute the offsets directly in C bytes. One row takes $3\cdot4=12$ C bytes, so the third row begins at $2\cdot12=24$. The required cell follows the first cell of that row, so its starting offset is $24+4=28$. In particular, $24\le28<36$, which is the range occupied by row $2$.

</div>

## Exercise 2

In `short m[3][5];`, on a machine where `sizeof(short) = 2`, the first byte of a cell lies at offset $26$ from the start of the object. Find the cell’s indices.

$$
\begin{aligned}
k &= \frac{26}{2}=13,\\[6pt]
13 &= 2\cdot5+3,\qquad 0\le 3<5,\\[6pt]
(r,c)&=(2,3) .
\end{aligned}
$$

<div class="spiegazione">

The offset is a multiple of the element size, so it corresponds to position $13$ in a zero-based linear count. To recover the row, divide by five, the number of elements in each row. The quotient $2$ counts whole preceding rows, while the remainder $3$ is the within-row index. Since $2<3$ and $3<5$, both indices fit the declared shape.

To check the result, start from the row boundaries in C bytes. Row $2$ starts at $2\cdot(5\cdot2)=20$ and ends before $30$. The offset within it is $26-20=6$. The first bytes of the row’s cells have local offsets $0$, $2$, $4$, $6$ and $8$, so the cell at $6$ has local index $3$.

</div>

## Exercise 3

In `double m[5][6];`, on a machine where `sizeof(double)` is $8$, the first byte of a cell lies at offset $200$ from the start of the matrix. Find the cell’s indices. Then find the distance in C bytes from the first byte of `m[1][4]` to the first byte of `m[3][2]`, and the output of the following program, which measures both distances with character pointers.

```c
#include <stdio.h>
#include <stddef.h>

int main(void)
{
    double m[5][6];
    ptrdiff_t b = (char *)&m[4][1] - (char *)&m[0][0];
    ptrdiff_t d = (char *)&m[3][2] - (char *)&m[1][4];
    printf("%td %td\n", b, d);
    return 0;
}
```

$$
\begin{aligned}
k &= \frac{200}{8}=25,\\[6pt]
25 &= 4\cdot6+1,\qquad 0\leq 1<6,\\[6pt]
(r,c) &= (4,1),\\[6pt]
k_2-k_1 &= (3\cdot6+2)-(1\cdot6+4)=20-10=10,\\[6pt]
d &= 10\cdot8=80 .
\end{aligned}
$$

```text
200 80
```

<div class="spiegazione">

The matrix contains $5\cdot6=30$ elements and each row occupies $6\cdot8=48$ C bytes. The offset $200$ is a multiple of $8$, so it is the start of the element at linear position $25$. Dividing $25$ by the number of columns gives quotient $4$ and remainder $1$. The quotient counts the whole rows preceding the cell, while the remainder is the column index. Since $4<5$ and $1<6$, the cell is `m[4][1]`. For the distance, the formula $rC+c$ gives the linear positions $10$ and $20$ of the two cells. There are therefore ten elements between the two starts, that is $80$ C bytes. In the program the addresses are converted to `char *`, so the difference is expressed in C bytes. The result has type `ptrdiff_t` and the matching specifier is `%td`. The program uses only the addresses of the cells, so the indeterminate contents of the automatic matrix are never read.

As a check, start from the boundary of row $4$, which begins at $4\cdot48=192$ C bytes. The difference $200-192=8$ is the size of a single element, so the cell has column index $1$. Likewise `m[1][4]` starts at $48+32=80$ and `m[3][2]` at $144+16=160$, at distance $160-80=80$.

</div>
