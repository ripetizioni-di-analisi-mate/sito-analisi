## Exercise 1

Write a `sum_range` function that adds the initialized array elements in $[lo,hi)$, where $0\le lo\le hi\le n$. Every partial sum is representable in `int`. Apply the function to `int a[5] = {6, -1, 7, 2, -4};` on the ranges $[1,4)$ and $[5,5)$.

```c
#include <stddef.h>

int sum_range(const int a[], size_t lo, size_t hi)
{
    int sum = 0;
    for (size_t i = lo; i < hi; ++i) {
        sum += a[i];
    }
    return sum;
}
```

$$
\begin{aligned}
\operatorname{sum}(a,[1,4))&=-1+7+2=8,\\[6pt]
\operatorname{sum}(a,[5,5))&=0 .
\end{aligned}
$$

<div class="spiegazione">

The signature accepts the endpoints because the function accesses the elements through a parameter adjusted to a pointer. The full object has five cells, so the endpoints in both calls meet the contract. The first range processes cells $1$, $2$ and $3$ in succession. The accumulator values are $-1$, $6$ and $8$. For the second range the first loop condition is false. The function preserves the initial value $0$ and never attempts to read `a[5]`.

The full array provides a check on the first sum. Its total is $6-1+7+2-4=10$. The elements outside the segment are $6$ and $-4$, giving $10-[6+(-4)]=8$. In the second test the range has cardinality $5-5=0$, so the empty sum is zero.

</div>

## Exercise 2

Reverse `int a[5] = {2, -4, 6, 8, 3};` in place. Use a loop that swaps two cells at a time. The procedure must also work when the caller asks to process zero elements.

```c
#include <stddef.h>

void reverse(int a[], size_t n)
{
    for (size_t i = 0; i < n / 2; ++i) {
        size_t j = n - 1 - i;
        int saved = a[i];
        a[i] = a[j];
        a[j] = saved;
    }
}
```

$$
\begin{aligned}
(2,-4,6,8,3)&\ \longmapsto\ (3,-4,6,8,2)\\[6pt]
            &\ \longmapsto\ (3,8,6,-4,2) .
\end{aligned}
$$

<div class="spiegazione">

Mirror indices satisfy $i+j=n-1$. With five elements, the first swap uses indices $0$ and $4$, and the second uses $1$ and $3$. Index $2$ is its own mirror, so that cell stays in place. The variable `saved` preserves the first value until it is written to the second cell. For $n=0$, the test `i < n / 2` is false from the start. The expression `n - 1 - i` is evaluated only when the body runs, so the empty case also avoids a subtraction outside its intended domain.

To check the order, read the input elements directly at indices $4$, $3$, $2$, $1$ and $0$. This gives $3$, $8$, $6$, $-4$ and $2$, respectively. Reading backwards produces the same sequence as the two swaps.

</div>

## Exercise 3

The following function must rotate left by one position the elements with indices in $[lo,hi)$. The first element of the segment goes to the last cell of the segment and the others move forward by one place. The contract allows $0\leq lo\leq hi\leq n$, where $n$ is the number of elements of the array, including the empty range. Determine for which allowed calls the function does not meet its specification, correct it and apply the corrected version to `int a[5] = {2, -4, 6, 8, 3};` on the ranges $[1,4)$ and $[5,5)$.

```c
#include <stddef.h>

void rotate_left(int a[], size_t lo, size_t hi)
{
    int first = a[lo];
    for (size_t i = lo; i < hi - 1; ++i) {
        a[i] = a[i + 1];
    }
    a[hi - 1] = first;
}
```

The correction adds an early return for the empty range.

```c
#include <stddef.h>

void rotate_left(int a[], size_t lo, size_t hi)
{
    if (lo == hi) {
        return;
    }
    int first = a[lo];
    for (size_t i = lo; i < hi - 1; ++i) {
        a[i] = a[i + 1];
    }
    a[hi - 1] = first;
}
```

$$
\begin{aligned}
[1,4):&\quad (2,-4,6,8,3)\ \longmapsto\ (2,6,8,-4,3),\\[6pt]
[5,5):&\quad (2,6,8,-4,3)\ \longmapsto\ (2,6,8,-4,3) .
\end{aligned}
$$

<div class="spiegazione">

For $lo<hi$ the original function uses only indices in $[lo,hi)$, so it is correct. With the empty range, however, it reads `a[lo]` and writes to `a[hi - 1]`. If $0<lo=hi<n$, the write copies `a[lo]` into `a[lo - 1]`, so it changes a cell outside the segment. If $lo=hi=n$, the read concerns index $n$, which is outside the array. If $lo=hi=0$, the expression `hi - 1` is computed in the unsigned type `size_t` and equals `SIZE_MAX`, so the loop runs past the last cell. In the last two cases the access outside the array has **undefined behavior**. The early return comes before every access, and for $hi>lo\geq0$ the subtraction `hi - 1` stays nonnegative. In the call on $[1,4)$ the value $-4$ is saved, cells $1$ and $2$ receive $6$ and $8$, and cell $3$ receives $-4$. The call on $[5,5)$ returns immediately and leaves the array unchanged.

As a check, read cells $1$, $2$ and $3$ of the result, which hold $6$, $8$ and $-4$. They are the elements of the original segment $(-4,6,8)$ read from the second one, with the first one at the end. Cells $0$ and $4$ keep $2$ and $3$.

</div>
