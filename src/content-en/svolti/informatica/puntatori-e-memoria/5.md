## Exercise 1

Evaluate `snap`, `*first` and `first == second` after the two calls. The declarations at the bottom are in a function body and run before any other call to `tick`.
```c
const unsigned *tick(void)
{
    static unsigned cell = 1;
    cell += 2;
    return &cell;
}

/* Caller body */
const unsigned *first = tick();
unsigned snap = *first;
const unsigned *second = tick();
```

The first call changes `cell` to $1+2=3$ and `snap` stores $3$. The second call changes the same object to $3+2=5$. Then `*first` is $5$ and `first == second` is true.

<div class="spiegazione">

The `static` declaration associates with the function an integer that lasts for the entire execution of the program. Its initial value is established only once. The increment on the second call therefore affects the object that already existed in the first. The copy in `snap` retains the value read on the first call and is independent of the second increment.

As a check, compare the two returned addresses and calculate the difference between the final observed value and the copy. The comparison is true because both addresses designate `cell`. The difference $5-3=2$ matches the only increment after the copy.

</div>

## Exercise 2

Find `total` and identify the object designated by `view` at the end of the fragment. Classify the behaviour of the final read if the assignment `view = &outer;` inside the inner block is omitted. The fragment is in a function body.
```c
int outer = 10;
const int *view = &outer;
int snapshot;
{
    int temporary = 21;
    view = &temporary;
    snapshot = *view;
    view = &outer;
}
int total = snapshot + *view;
```

`snapshot` is $21$ and `view` points to `outer` again before the inner block ends. The sum is $21+10=31$. Without the final assignment to `view` in the block, the final read through that pointer has undefined behaviour.

<div class="spiegazione">

During the first read, `temporary` is live, so its value can be copied into the outer object `snapshot`. The copy remains available after leaving the block. Reassigning `view` before exit makes the final read access the integer `outer`. In the alternative case the lifetime of the object once designated by the pointer has already ended when the second read is attempted.

To verify the execution shown, check the two sources of the sum separately. The value $21$ comes from a completed copy and $10$ comes from an object whose block is still active. Their lifetimes justify both reads.

</div>
