## Exercise 1

An implementation has `SIZE_MAX` equal to $65535$ and `sizeof(double)` equal to $8$. An array is to hold either $8191$ or $8192$ elements. Determine for which requests the size can be passed to `malloc` as a byte count, with `<stdint.h>` available for the bound. The question concerns representability before any actual allocation.

The check gives
$$
\left\lfloor \dfrac{65535}{8} \right\rfloor = 8191.
$$
The first element count is within the bound. Its request is $65528$ bytes. The second count exceeds the bound by one.

<div class="spiegazione">

The parameter to `malloc` is a byte count. Integer division establishes how many times the size of one element fits within the maximum value of `size_t`. The runtime multiplication follows this comparison, so a representable request keeps its value.

As a check, calculate the two products as mathematical integers. They give $8191\cdot8=65528\leq65535$ and $8192\cdot8=65536>65535$. The first satisfies the bound. The second is eight bytes greater than the first, leaving it one byte above the maximum, so it is unrepresentable.

</div>

## Exercise 2

An acquisition produces two readings at indices $1$ and $4$, with values $11$ and $6$, respectively. The five values have type `unsigned char`. Indices without a reading must have value zero. Write a fragment that allocates and initializes the block, calculates the sum and releases it. The function can return `EXIT_FAILURE` on error, and the declarations from `<stdlib.h>` are visible.

```c
unsigned char *values = calloc(5, sizeof *values);
if (values == NULL) {
    return EXIT_FAILURE;
}
values[1] = 11;
values[4] = 6;

unsigned total = 0;
for (size_t i = 0; i < 5; ++i) {
    total += values[i];
}
free(values);
```

Before release the sequence is $(0,11,0,0,6)$. The value of `total` is $17$ and remains available after release.

<div class="spiegazione">

The memory from `calloc` has all bits zero. For an `unsigned char` this is the value zero, so a read of each position is already defined after a successful request. The two assignments modify only the positions that received a reading. The variable `total` is an automatic object separate from the block that is released.

To check the result, separate the elements that were written from the others. Indices $0$, $2$ and $3$ retain zero. The two nonzero contributions give exactly $11+6=17$. The five iterations read exactly the positions in the block.

</div>

## Exercise 3

An implementation has `SIZE_MAX` equal to $65535$, `size_t` identical to `unsigned int` and `sizeof(double)` equal to $8$. The following function must obtain, in a single block, a matrix of `double` with `rows` rows and `cols` columns. Determine what happens when `rows` and `cols` are both $256$, correct the check and apply the corrected version to the pairs $(256,256)$, $(91,90)$ and $(91,91)$. The declarations from `<stdint.h>` and `<stdlib.h>` are visible.

```c
double *allocate_matrix(size_t rows, size_t cols)
{
    double *m;
    if (rows * cols > SIZE_MAX / sizeof *m) {
        return NULL;
    }
    m = malloc(rows * cols * sizeof *m);
    return m;
}
```

With $256$ rows and $256$ columns the mathematical product is $65536$, which reduced modulo $65536$ gives $0$. The check $0>8191$ is false, so the function calls `malloc(0)`. The correct check is the following.

```c
if (rows == 0 || cols == 0 || cols > SIZE_MAX / sizeof *m / rows) {
    return NULL;
}
```

We have
$$
\left\lfloor \frac{8191}{256}\right\rfloor = 31,
\qquad
\left\lfloor \frac{8191}{91}\right\rfloor = 90 .
$$
The pairs $(256,256)$ and $(91,91)$ are therefore rejected. The pair $(91,90)$ is accepted with a request of $91\cdot90\cdot8=65520$ bytes.

<div class="spiegazione">

The operands `rows` and `cols` have type `size_t`, which here is `unsigned int`, so the product does not undergo integer promotion and is computed as `unsigned int`. Unsigned arithmetic is performed modulo $\mathrm{SIZE\_MAX}+1=65536$, so the product $256\cdot256$ becomes $0$ before the comparison. The faulty check therefore compares a value that has already been reduced and accepts the request. The result of `malloc(0)` is implementation-defined and is either a null pointer or a pointer through which no object can be accessed. When the returned pointer is not null, the caller uses it as a matrix of $65536$ elements, and the writes to those elements therefore have undefined behaviour.

The corrected version performs only integer divisions, which never exceed the dividend, so no step of the check is reduced modulo $65536$. The number $\left\lfloor \dfrac{65535}{8}\right\rfloor=8191$ is the largest number of elements representable in bytes, and the division by `rows` gives the largest number of columns for that number of rows. With `rows` and `cols` nonzero, the request is therefore accepted exactly when $\mathtt{rows}\cdot\mathtt{cols}\cdot8\leq65535$. The **short-circuit** rule of `||` ensures that the division by `rows` happens only when `rows` is nonzero.

</div>
