## Exercise 1

Write `clone_int` to obtain an allocated copy of the integer designated by `source`. The argument designates a live, readable integer. The function returns the block to the caller, or `NULL` on failure. Describe the state when `int x = 19;` is the source and the caller writes $31$ to a successful copy and then releases it.

```c
#include <stdlib.h>

int *clone_int(const int *source)
{
    int *copy = malloc(sizeof *copy);
    if (copy == NULL) {
        return NULL;
    }
    *copy = *source;
    return copy;
}
```

A successful allocation yields a separate integer initially equal to $19$. Writing $31$ to the copy leaves `x` at $19$. Releasing the copy ends its lifetime while the lifetime of `x` continues.

<div class="spiegazione">

The function receives read access to `x`. The returned pointer comes from a new allocation, so the function also transfers responsibility for the new block to the caller. The assignment copies the integer value, so the allocated object can be changed independently of the source. On the null branch, the function has obtained no block to hand over.

To check ownership, count the new blocks from the call onward. Success increases the count from zero to one, while writing $31$ leaves it unchanged. Release returns it to zero. The automatic object `x` has a separate lifetime and stays unchanged.

</div>

## Exercise 2

The caller initializes `owner` with a non-null pointer returned by `malloc` and `borrow = owner` with a copy of its address. Both pointer variables are outside the block. Describe the state after two successive calls to `release_owned(&owner)`. State whether a third step can assign `NULL` to `borrow`.
```c
#include <stdlib.h>

void release_owned(int **slot)
{
    free(*slot);
    *slot = NULL;
}
```

The first call releases the block and writes `NULL` to `owner`. The second calls `free(NULL)` and leaves `owner` null. After the first release, the value of `borrow` is indeterminate. Direct assignment `borrow = NULL;` is defined.

<div class="spiegazione">

The parameter `slot` points to the owner variable, which continues to exist outside the block. The function first releases the block using the value held by that variable. It then writes the null value to the same variable. The copy `borrow` is not the target of that second operation, so it is updated only in the explicit third step.

As a check, count the effective releases. When the first call begins, one block exists and release ends its lifetime. When the second begins, the argument to `free` is null, so the count remains zero. Assigning `NULL` to `borrow` writes a new value without consulting the earlier contents.

</div>

## Exercise 3

Find the error in the function `sum_copies`, which adds two integers by way of two allocated copies, and correct it. The function `clone_int` returns an allocated block holding a copy of the designated integer, or `NULL` if the allocation fails. Count the live blocks at return in the four possible cases for the two allocations. The arguments `a` and `b` designate readable integers, `out` designates a modifiable `int` and `<stdlib.h>` is included.

```c
int sum_copies(const int *a, const int *b, int *out)
{
    int *x = clone_int(a);
    int *y = clone_int(b);
    if (x == NULL || y == NULL) {
        return 0;
    }
    *out = *x + *y;
    free(x);
    free(y);
    return 1;
}
```

| Allocation of `x` | Allocation of `y` | Live blocks at return |
|---|---|---:|
| succeeded | succeeded | 0 |
| failed | succeeded | 1 (the one of `y`) |
| succeeded | failed | 1 (the one of `x`) |
| failed | failed | 0 |

The correction adds the two releases on the error path.

```c
    if (x == NULL || y == NULL) {
        free(x);
        free(y);
        return 0;
    }
```

With the correction the count is $0$ in all four cases.

<div class="spiegazione">

Each successful call to `clone_int` transfers **ownership** of a block to `sum_copies`, so the responsibility for its release applies on every exit of the function. On the success path the two final calls to `free` bring the count to zero. On the error path of the first version the function returns without releases, so the block from the only successful allocation stays live. After the return no variable holds its address, so the block can no longer be released and constitutes a **memory leak**.

The correction releases both pointers without distinguishing the two failure cases. This is correct because `free(NULL)` has no effect, so the call for the failed allocation leaves the count unchanged. The case of two failures gives zero in the first version as well, since the function obtained no block. The error path does not write to `*out`, so the caller distinguishes the two outcomes only by the returned value.

</div>
