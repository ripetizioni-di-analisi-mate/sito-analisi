## Exercise 1

Write the exact output of the program. Assume that `int` and `unsigned int` have $32$ bits and that output succeeds. The type `uint8_t` from `<stdint.h>` is an $8$-bit unsigned integer.

```c
#include <stdint.h>
#include <stdio.h>

int main(void)
{
    uint8_t a = 0xC8u;
    uint8_t b = 0x5Au;
    uint8_t s = (uint8_t)(a + b);

    printf("%d %u %02X\n", a + b, (unsigned)s, (unsigned)s);
    return 0;
}
```

```text
290 34 22
```

$$
\begin{aligned}
(C8)_{16}+(5A)_{16} &= 200+90=290 \\[6pt]
290 &= 256+34 \\[6pt]
34 &= (0010\;0010)_2=(22)_{16} .
\end{aligned}
$$

<div class="spiegazione">

In the expression `a + b` both operands have type `uint8_t`. Since `int` represents every value from $0$ to $255$, **integer promotion** converts both operands to `int` before the addition. The sum is therefore $290$, has type `int` and matches the specifier `%d`. In the declaration of `s` the same value is converted to `uint8_t`. A conversion to an unsigned type reduces the value modulo the number of values of the type, that is $2^8$, so `s` is $290-256=34$. This is the remainder modulo $2^8$ given by addition at fixed width.

In binary, $11001000+01011010=1\,00100010$. The ninth bit is the carry out of the eighth position, and the conversion discards it. The eight retained bits form the groups $0010$ and $0010$, so `%02X` prints `22`.

</div>

## Exercise 2

Write the exact output of the program. Assume that `int` and `unsigned int` have $32$ bits and that output succeeds. The types `int8_t` and `uint16_t` from `<stdint.h>` are an $8$-bit signed integer and a $16$-bit unsigned integer.

```c
#include <stdint.h>
#include <stdio.h>

int main(void)
{
    int8_t v = -75;
    uint8_t w = (uint8_t)v;
    uint16_t h = (uint16_t)v;
    unsigned u = (unsigned)v;

    printf("%u %X\n", (unsigned)w, (unsigned)w);
    printf("%u %X\n", (unsigned)h, (unsigned)h);
    printf("%u %X\n", u, u);
    return 0;
}
```

```text
181 B5
65461 FFB5
4294967221 FFFFFFB5
```

$$
\begin{aligned}
-75+2^8 &= 181=(B5)_{16} \\[6pt]
-75+2^{16} &= 65461=(FFB5)_{16} \\[6pt]
-75+2^{32} &= 4294967221=(FFFFFFB5)_{16} .
\end{aligned}
$$

<div class="spiegazione">

All three conversions target an unsigned type with $N$ bits. The value $-75$ lies outside the destination range, so the conversion adds the number of values of the type, that is $2^N$. This gives $-75+2^8$, $-75+2^{16}$ and $-75+2^{32}$, each within the range of its type. Each result is the unsigned reading of the two's complement word of $-75$ on $N$ bits. On eight bits this word is $10110101$, that is $(B5)_{16}$.

The sixteen-bit and thirty-two-bit words are obtained by **sign extension**. The most significant bit of $10110101$ is $1$, so bits equal to $1$ are prepended and each added group of four bits is $1111$, that is the digit $F$. The last two hexadecimal digits remain $B5$ in all three lines. The arguments of `%u` and `%X` have type `unsigned int`, as both specifiers require.

</div>

## Exercise 3

The program adds three pairs of eight-bit words. The function `signed_value` returns the two's complement reading of a word, and the function `add_overflows` applies the signed overflow criterion. Write the exact output. Assume that `int` has $32$ bits and that output succeeds.

```c
#include <stdint.h>
#include <stdio.h>

static int signed_value(uint8_t word)
{
    return word >= 0x80u ? (int)word - 256 : (int)word;
}

static int add_overflows(uint8_t x, uint8_t y, uint8_t sum)
{
    int sx = x >= 0x80u;
    int sy = y >= 0x80u;
    int ss = sum >= 0x80u;

    return sx == sy && ss != sx;
}

int main(void)
{
    const uint8_t x[3] = {0x5Au, 0xA0u, 0x90u};
    const uint8_t y[3] = {0x3Cu, 0xF0u, 0x88u};

    for (int i = 0; i < 3; i++) {
        uint8_t sum = (uint8_t)(x[i] + y[i]);
        int carry = x[i] + y[i] > 0xFF;

        printf("%02X %4d %d %d\n", (unsigned)sum, signed_value(sum),
               carry, add_overflows(x[i], y[i], sum));
    }
    return 0;
}
```

```text
96 -106 0 1
90 -112 1 0
18   24 1 1
```

| Line | Unsigned sum | Signed sum | `sum` | `signed_value(sum)` |
| --- | --- | --- | --- | --- |
| $1$ | $90+60=150$ | $90+60=150$ | $(96)_{16}$ | $-106$ |
| $2$ | $160+240=400$ | $-96-16=-112$ | $(90)_{16}$ | $-112$ |
| $3$ | $144+136=280$ | $-112-120=-232$ | $(18)_{16}$ | $24$ |

<div class="spiegazione">

In `x[i] + y[i]` both words are promoted to `int`, so the unsigned sum is exact and the comparison with `0xFF` gives the carry out of the eighth position. The conversion to `uint8_t` keeps the remainder of the sum modulo $256$. The function `signed_value` subtracts $256$ when the most significant bit is $1$, as **two's complement** decoding requires. The most significant bit is $1$ exactly when the word is at least `0x80u`. Therefore `add_overflows` returns $1$ when the addends have the same sign bit and the resulting word has the opposite sign bit.

In the first line both addends are positive and the sum $150$ exceeds the maximum $127$. The word $(96)_{16}$ therefore has sign bit $1$, and overflow occurs without a carry. In the second line both addends are negative and the sum $-112$ is representable, so there is a carry without overflow. In the third line the sum $-232$ is less than $-128$, so both a carry and an overflow occur. The specifier `%4d` uses at least four characters, so two spaces precede `24`.

</div>
