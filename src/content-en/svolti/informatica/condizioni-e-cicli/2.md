## Exercise 1

Determine the bands produced by the fragment for each integer score from `0` to `100`, inclusive. Check how it behaves at the two internal boundaries.

```c
int score = 60, band = 0;
if (score >= 60) {
    band = 1;
}
if (score >= 80) {
    band = 2;
}
```

| Scores | `band` |
|---|---:|
| from 0 to 59 | 0 |
| from 60 to 79 | 1 |
| from 80 to 100 | 2 |

When `score = 60` the result is `1`. When `score = 80` the result is `2`.

<div class="spiegazione">

For a score below `60`, both comparisons are false and the initial value remains. From `60` onward, the first `if` assigns `1`. For `1` to remain, the second comparison must be false, which means the score must be below `80`. Starting at `80` both assignments execute, so the assignment of `2` takes effect because it runs last.

To check the boundaries, evaluate the state immediately before and after each transition. At `59` the result stays `0`, while at `60` the first assignment takes place. At `79` the last guard is still false, while at `80` it becomes true. The bands account for all four results.

</div>


## Exercise 2

Find the final value of `cost` with `tariff = 2`. Repeat the calculation with `tariff = 9`.

```c
int tariff = 2, cost = 8;
switch (tariff) {
case 1:
    cost += 3;
    break;
case 2:
    cost += 5;
    /* fall through */
default:
    cost *= 2;
}
```

$$
\begin{aligned}
\text{tariff 2}\quad & 8+5=13, \\
                    & 13\cdot 2=26, \\[6pt]
\text{tariff 9}\quad & 8\cdot 2=16 .
\end{aligned}
$$

<div class="spiegazione">

For tariff `2`, the entry point is `case 2`. The assignment adds `5`. Execution then reaches the multiplication through the next label, `default`. The label supplies another entry point and allows execution already in progress to continue. For tariff `9`, execution enters directly at `default` because no `case` label matches the controlling value. The initial cost is therefore doubled.

To check the difference, split the cost for tariff `2` into two components. Both cases double the initial cost of `8`. Only the first case also doubles the additional `5`. The difference must therefore equal `2 * 5`, which agrees with `26 - 16`.

</div>


## Exercise 3

Find the value returned by `code(n)` for each integer `n` from `-3` to `4`, inclusive.

```c
int code(int n)
{
    int c = 0;
    switch (n % 4) {
    default:
        c += 1;
        /* fall through */
    case 2:
        c += 10;
        break;
    case 0:
        c += 100;
        /* fall through */
    case 3:
        c *= 2;
    }
    return c;
}
```

| `n` | -3 | -2 | -1 | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `n % 4` | -3 | -2 | -1 | 0 | 1 | 2 | 3 | 0 |
| `code(n)` | 11 | 11 | 11 | 200 | 11 | 10 | 0 | 200 |

<div class="spiegazione">

In C, integer division truncates toward zero, so the remainder `n % 4` has the sign of the dividend. For `n` from `-3` to `-1` the remainder is therefore `-3`, `-2`, and `-1`, and no `case` label matches these values. Control then enters at `default`, even though that label is written first in the body. From `default`, `1` is added, then execution continues past `case 2` by **fall-through** and adds `10`. The following `break` ends the `switch` with `11`. The same path applies to `n = 1`, because the remainder `1` does not appear among the labels.

With `n = 2`, control enters at `case 2`, adds `10`, and leaves through the `break`. With remainder `0`, that is, for `n = 0` and `n = 4`, control enters at `case 0` and `c` becomes `100`. Since there is no `break` between `c += 100` and `case 3`, the multiplication under `case 3` also executes and the result is `200`. With `n = 3`, control enters at `case 3` and multiplies the initial value `0`, so the result is `0`. The `default` label is selected only when the controlling value differs from every `case` constant, wherever the label is placed. Its position determines which statements follow the entry point.

</div>
