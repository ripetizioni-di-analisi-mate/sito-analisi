## Exercise 1

Find the final value of `value` and the number of executions of the body.

```c
int value = 38, steps = 0;
while (value > 3) {
    value /= 2;
    ++steps;
}
```

| `value` at the guard | `steps` | `value > 3` |
|---:|---:|---|
| 38 | 0 | true |
| 19 | 1 | true |
| 9 | 2 | true |
| 4 | 3 | true |
| 2 | 4 | false |

<div class="spiegazione">

Integer division by `2` on a positive integer keeps the whole-number part of the quotient. The first update gives exactly `19`. The transition from `19` to `9` discards a remainder of `1`, as does the transition from `9` to `4`. Since `4 > 3`, the division that produces `2` also executes. The guard is then false. The body runs four times and the guard is evaluated five times.

To check the number of divisions, after $k$ divisions the value is $\left\lfloor \dfrac{38}{2^k}\right\rfloor$. Each division drops the least significant bit, so $k$ divisions drop $k$ bits in total. For $k=3$ the result is $4$, still above the threshold. For $k=4$ the result is $2$, which causes the exit.

</div>


## Exercise 2

Determine the final values of `x` and `events`. Trace the fragment again with `x = 2` as the initial value.

```c
int x = 24, events = 0;
do {
    ++events;
    x = (x - 1) / 2;
} while (x >= 3);
```

| Initial `x` | `x` at successive tests | Final `events` |
|---:|---|---:|
| 24 | 11, 5, 2 | 3 |
| 2 | 0 | 1 |

<div class="spiegazione">

The body updates `x` before each evaluation of the condition. Starting at `24`, the first numerator is `23` and the quotient is `11`. The next two updates give `5` and `2`, because they use numerators `10` and `4`. The check on `2` ends the loop with `events = 3`. Starting at `2`, the first body still executes. The numerator is `1`, so the integer quotient is `0` and the loop exits with `events = 1`.

Check each step by reconstructing the original integer from the new quotient. The previous value minus one must equal twice the quotient plus a remainder in $\{0,1\}$. The first trace gives `23 = 2 * 11 + 1`, `10 = 2 * 5 + 0`, and `4 = 2 * 2 + 0`. In the second trace, `1 = 2 * 0 + 1`.

</div>


## Exercise 3

Find the final values of `i` and `x` and the number of guard evaluations. Trace the fragment again with `x = 100` as the initial value.

```c
int i = 0, x = 50;
while (i++ < 6 && x > 5) {
    x -= 3 * i;
}
```

| `i` before the guard | `x` at the guard | `x > 5` | `x` after the body |
|---:|---:|---|---:|
| 0 | 50 | true | 47 |
| 1 | 47 | true | 41 |
| 2 | 41 | true | 32 |
| 3 | 32 | true | 20 |
| 4 | 20 | true | 5 |
| 5 | 5 | false | exit |

With `x = 50` the loop exits with `i = 6` and `x = 5`, after six guard evaluations and five executions of the body. With `x = 100`,

$$
x=100-3\,(1+2+3+4+5+6)=100-63=37,
$$

and the loop exits with `i = 7`, after seven guard evaluations and six executions of the body.

<div class="spiegazione">

The guard compares the value of `i` before the update with `6`, and the postfix increment increments `i` at every evaluation, including the false one. In the body, `i` therefore already holds the updated value, and the first iteration subtracts `3 * 1`. With `x = 50`, at the sixth evaluation the first comparison is true and `i` becomes `6`. Since the first operand is true, `x > 5` is evaluated, and it is false because `x` is exactly `5`.

With `x = 100` the values of `x` at the guards stay above `5`, so the body executes for `i` from `1` to `6`. At the seventh evaluation the comparison `6 < 6` is false, and the postfix increment still brings `i` to `7`. By short-circuit evaluation of `&&`, the comparison on `x` is skipped. In the two cases the exit is therefore determined by different operands, and the final value of `i` distinguishes them.

</div>
