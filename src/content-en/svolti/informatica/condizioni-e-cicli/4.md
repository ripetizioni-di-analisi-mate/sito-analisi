## Exercise 1

Find all integer values of `limit` from `0` through `30` for which `visits` equals `4`. The value in the code is a test case.
```c
int limit = 22, visits = 0;
for (int i = 4; i < limit; i += 5) {
    ++visits;
}
```

$$
\begin{aligned}
i_0&=4,\quad i_1=9,\quad i_2=14,\\
i_3&=19,\quad i_4=24. \\[6pt]
19&<\mathrm{limit}\le 24.
\end{aligned}
$$

The possible bounds are `20`, `21`, `22`, `23`, and `24`.

<div class="spiegazione">

The counter values before the checks are increasing and differ by five. Four visits require the fourth value, `19`, to satisfy the strict condition. Since all earlier values are smaller, the same condition admits them. The check on the next value, `24`, must be false. Combining the two conditions gives the required interval.

Check the two endpoints and the values immediately outside the interval. With either `20` or `24` as the bound, the last visited value is still `19`. With bound `19`, the value `19` is excluded and there are three visits. With bound `25`, the guard also admits `24` and there are five visits.

</div>


## Exercise 2

List the visited indices `i` in order, calculate `sum`, and justify the final step of the unsigned counter.
```c
unsigned sum = 0u, n = 5u;
for (unsigned left = n; left > 0u; --left) {
    unsigned i = left - 1u;
    if (i % 2u == 0u) {
        sum += i;
    }
}
```

| `left` | 5 | 4 | 3 | 2 | 1 |
|---|---:|---:|---:|---:|---:|
| `i` | 4 | 3 | 2 | 1 | 0 |

$$
\mathrm{sum}=4+2+0=6 .
$$

<div class="spiegazione">

The guard permits `left - 1u` only when `left` is positive, so the computed index remains representable. When `left` is one, the index is zero. At the end of that iteration, the update gives `left = 0u`. The next test is false and the counter stays at zero, so no update starts from that value. The selection retains indices whose remainder on division by two is zero.

To check the result, read the same set of indices in ascending order. The even indices in $[0,5)$ are $0$, $2$, and $4$. Their sum is six regardless of visit order. In the additional case `n = 0u`, the initial guard is already false and the sum stays at zero.

</div>
