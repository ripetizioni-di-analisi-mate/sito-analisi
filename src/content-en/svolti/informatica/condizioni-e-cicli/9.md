## Exercise 1

The function `digits` must return the number of decimal digits of `n` for every value of a 32-bit `unsigned`, and zero is written with one digit. Find the value for which the contract is not met, explain the cause, and correct the function.
```c
unsigned digits(unsigned n)
{
    unsigned d = 0u;
    while (n > 0u) {
        n /= 10u;
        ++d;
    }
    return d;
}
```

| `n` | 0 | 7 | 10 | 4096 |
|---|---:|---:|---:|---:|
| Value returned | 0 | 1 | 2 | 4 |
| Value required | 1 | 1 | 2 | 4 |

```c
unsigned digits(unsigned n)
{
    unsigned d = 0u;
    do {
        n /= 10u;
        ++d;
    } while (n > 0u);
    return d;
}
```

With the corrected version, `digits(0u)` is `1` and `digits(4294967295u)` is `10`.

<div class="spiegazione">

For positive `n`, each integer division by `10` removes the last decimal digit, and the loop stops when no digits remain. The counter `d` therefore counts the digits of `n`. For `n = 0` the initial guard of the `while` is false, so the body executes zero times and the function returns `0`. The decimal representation of zero has one digit, so the contract is not met exactly at the boundary value of the domain.

In the `do while` loop the body executes before the test. For `n = 0` the division gives `0`, `d` becomes `1`, and the final guard is false, so the function returns `1`. For positive `n` the first guard of the `while` was true, so the two versions perform the same sequence of divisions and return the same value. The value of `n` is a variant of the loop, because $\left\lfloor\dfrac{n}{10}\right\rfloor<n$ for $n\geq 1$. The loop therefore terminates for every input, including the maximum `4294967295`, which has ten digits.

</div>


## Exercise 2

The function `count_hits` must return how many integers `k` with $1\leq k\leq n$ have a last decimal digit between `3` and `5`, inclusive, for $0\leq n\leq 10^6$. With `n = 25` the expected value is `9`, while the function returns `25`. Find the error, explain the value `25`, and correct the function.
```c
unsigned count_hits(unsigned n)
{
    unsigned hits = 0u;
    for (unsigned k = 1u; k <= n; ++k) {
        if (3u <= k % 10u <= 5u) {
            ++hits;
        }
    }
    return hits;
}
```

Compiling with `gcc -std=c11 -Wall -Wextra -pedantic` produces, among others, the warning

```text
warning: comparisons like 'X<=Y<=Z' do not have their mathematical meaning [-Wparentheses]
```

```c
unsigned count_hits(unsigned n)
{
    unsigned hits = 0u;
    for (unsigned k = 1u; k <= n; ++k) {
        unsigned last = k % 10u;
        if (3u <= last && last <= 5u) {
            ++hits;
        }
    }
    return hits;
}
```

With the corrected version, the integers counted for `n = 25` are `3`, `4`, `5`, `13`, `14`, `15`, `23`, `24`, and `25`, so `count_hits(25u)` is `9`.

<div class="spiegazione">

Comparison operators associate from the left, so the guard is equivalent to `(3u <= k % 10u) <= 5u`. The first comparison yields an `int` equal to `0` or `1`. Both values are less than `5`, so the condition is true for every `k` and the function counts all the integers from `1` to `n`. For this reason `count_hits(25u)` returns `25`. The compiler flags the expression with the warning shown, which concerns chained comparisons.

In the corrected version the last digit is stored in `last` and the two inequalities are joined by `&&`. If `last` is less than `3`, **short-circuit evaluation** skips the second comparison, and the result does not change because the conjunction is false in any case. In each complete group of ten, the condition is true for three values of `k`. The two groups from `1` to `20` therefore give six values, and the integers from `21` to `25` add three more. The hypothesis $n\leq 10^6$ guarantees that `++k` does not exceed the maximum of `unsigned`, so the guard `k <= n` becomes false after $n$ iterations.

</div>


## Exercise 3

The function `sum_down` must return the sum $n+(n-3)+(n-6)+\dots$ of the nonnegative terms only, for a 32-bit `unsigned` and $0\leq n\leq 10^5$, so that the sum is representable. With `n = 10` the expected value is $10+7+4+1=22$, but the call does not terminate. Explain why and correct the function.
```c
unsigned sum_down(unsigned n)
{
    unsigned s = 0u;
    for (unsigned i = n; i >= 0u; i -= 3u) {
        s += i;
    }
    return s;
}
```

```text
warning: comparison of unsigned expression in '>= 0' is always true [-Wtype-limits]
```

| Iteration | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---:|---:|---:|---:|---:|---:|
| `i` | 10 | 7 | 4 | 1 | 4294967294 | 4294967291 |

```c
unsigned sum_down(unsigned n)
{
    unsigned i = n;
    unsigned s = i;
    while (i >= 3u) {
        i -= 3u;
        s += i;
    }
    return s;
}
```

With the corrected version, `sum_down(10u)` is `22`, `sum_down(9u)` is `18`, `sum_down(2u)` is `2`, and `sum_down(0u)` is `0`.

<div class="spiegazione">

A value of type `unsigned` is never negative, so the guard `i >= 0u` is true in every state. The body contains no `break`, so the loop cannot terminate. After `i = 1` the update computes `1u - 3u`. Unsigned arithmetic is modulo $2^{32}$, so the result is $2^{32}-2=4294967294$, with no undefined behavior. From that value the subtractions continue forever. The compiler flags the guard with the `-Wtype-limits` warning, enabled by `-Wextra`.

In the corrected version the first term enters the sum before the loop, and the guard `i >= 3u` allows the subtraction only when the result is nonnegative. The value of `i` is then a **variant**, because it remains nonnegative and decreases by `3` at each iteration, so the loop terminates. For $n\leq 2$ the guard is false at once and the function returns `n`, the only nonnegative term. For `n = 10` the subtractions produce `7`, `4`, and `1`, and the guard on `1` is false, so the sum is `22`. The largest admissible case, $n=10^5$, gives $1666716667$, which is less than $2^{32}$.

</div>
