## Exercise 1

Calculate `allowed` in the two cases in the figure. In case B, replace the initial value of `divisor` with `4`.

![Case A with numerator 12, divisor 0 and limit 2. Case B with numerator 12, divisor 4 and limit 2.](/immagini/informatica/condizioni-e-cicli/dati-svolto-en.png)

```c
int numerator = 12, divisor = 0, limit = 2;
int allowed = divisor != 0 && numerator / divisor > limit;
```

| Case | First comparison | Second comparison | `allowed` |
|---|---|---|---:|
| A | false | skipped | 0 |
| B | true | `3 > 2` | 1 |

<div class="spiegazione">

The conjunction evaluates `divisor != 0` first. In case A, the comparison is false. The expression already has value `0`, so the quotient is left unevaluated. In case B the first comparison is true. Since the divisor is `4`, the integer division is defined and gives `3`. The value `3` exceeds `limit`, so the conjunction is `1`.

An independent check separates the two branches. With a zero divisor, the rule assigns zero directly. With a positive divisor and a nonnegative numerator, the quotient exceeds `2` if it reaches at least `3`. The product `4 * 3` equals `12`, so case B reaches exactly the minimum value that satisfies the condition.

</div>


## Exercise 2

Find the final values of `accept` and `checks`. Identify which increments execute.

```c
int enabled = 1, checks = 0, points = 7;
int accept = (enabled && (points >= 9 || ++checks == 1))
             || ++checks == 2;
```

| Step | Outcome | `checks` |
|---|---|---:|
| `enabled` | true | 0 |
| `points >= 9` | false | 0 |
| `++checks == 1` | true | 1 |
| Final comparison | skipped | 1 |

The results are `accept = 1` and `checks = 1`.

<div class="spiegazione">

Since `enabled` is one, the conjunction requires the value of the inner disjunction. The score `7` is below `9`, so the comparison containing `++checks` is evaluated. The prefix increment stores `1` and supplies `1` as the value used in the comparison. This makes the inner disjunction true and therefore makes the conjunction true. The outer disjunction now has a true first operand. It skips the final comparison, leaving the second prefix increment outside the execution path.

To check the final state, count the assignments to `checks` along that path. After initialization, the only assignment adds one, so the final value is indeed `1`.

</div>
