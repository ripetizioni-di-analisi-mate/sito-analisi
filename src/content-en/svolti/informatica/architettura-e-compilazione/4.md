## Exercise 1

Memory starting at address zero uses blocks of $8$ bytes. A direct-mapped cache has $3$ lines. Find the block, offset and line for address $27$.

$$
\begin{aligned}
27 &= 3\cdot 8+3\\[6pt]
b &= 3,\qquad \text{offset}=3\\[6pt]
\text{line} &= 3\bmod 3=0 .
\end{aligned}
$$

<div class="spiegazione">

The block number is the quotient on division by $8$. The remainder gives the distance from the start of the block. To find the line, divide the block number by the number of lines and use the remainder from dividing $3$ by $3$.

To check, block $3$ contains the range $[24,32)$ and $27-24=3$. Among lines $0$, $1$ and $2$, line $0$ is the only one congruent to $3$ modulo $3$. This confirms both steps.

</div>

## Exercise 2

A direct-mapped cache has $3$ empty lines and blocks of $4$ bytes. The accesses are all reads, in the order $0$, $5$, $8$, $13$, $7$, $0$, $10$. Each miss loads the requested block into its line. Identify the two accesses that hit and explain why address $0$ misses again.

| Address | Block | Line | Result |
|---:|---:|---:|---|
| 0 | 0 | 0 | miss |
| 5 | 1 | 1 | miss |
| 8 | 2 | 2 | miss |
| 13 | 3 | 0 | miss |
| 7 | 1 | 1 | hit |
| 0 | 0 | 0 | miss |
| 10 | 2 | 2 | hit |

<div class="spiegazione">

The first three accesses populate lines $0$, $1$ and $2$, respectively. Address $13$ belongs to block $3$ and uses line $0$, so it displaces block $0$. Address $7$ is still in block $1$ and finds line $1$ undisturbed. On the return to address $0$, line $0$ contains block $3$, so the access is a miss. Block $2$ remains in its line, making the final access to $10$ a hit.

As a check, examine each line separately. Line $0$ receives three requests for blocks $0$, $3$ and $0$, in that order. No request repeats the preceding block on that line. Line $1$ repeats block $1$ and line $2$ repeats block $2$. This gives one hit in each of those two lines.

</div>

## Exercise 3

A direct-mapped cache has $4$ initially empty lines and blocks of $8$ bytes. A loop reads alternately the elements of two arrays `a` and `b` of four $4$-byte integers, in the order `a[0]`, `b[0]`, `a[1]`, `b[1]`, `a[2]`, `b[2]`, `a[3]`, `b[3]`. Array `a` starts at address $0$ and these reads are the only accesses. Count hits and misses with `b` at address $32$ and with `b` at address $40$.

With `b` at address $32$:

| Address | Block | Line | Result |
|---:|---:|---:|---|
| 0 | 0 | 0 | miss |
| 32 | 4 | 0 | miss |
| 4 | 0 | 0 | miss |
| 36 | 4 | 0 | miss |
| 8 | 1 | 1 | miss |
| 40 | 5 | 1 | miss |
| 12 | 1 | 1 | miss |
| 44 | 5 | 1 | miss |

With `b` at address $40$:

| Address | Block | Line | Result |
|---:|---:|---:|---|
| 0 | 0 | 0 | miss |
| 40 | 5 | 1 | miss |
| 4 | 0 | 0 | hit |
| 44 | 5 | 1 | hit |
| 8 | 1 | 1 | miss |
| 48 | 6 | 2 | miss |
| 12 | 1 | 1 | hit |
| 52 | 6 | 2 | hit |

The first case gives $0$ hits and $8$ misses, the second $4$ hits and $4$ misses.

<div class="spiegazione">

An $8$-byte block contains two consecutive integers of the same array, so the sequence has spatial locality. After the miss on `a[0]`, the read of `a[1]` requests the same block $0$.

In the first case `b[i]` is exactly $32$ bytes, that is four blocks, away from `a[i]`. Two blocks that differ by $4$ have the same remainder on division by $4$, so `a[i]` and `b[i]` always use the same line. On the return to `a[1]`, therefore, block $0$ has already been displaced by block $4$. The reads of `a[1]`, `b[1]`, `a[3]` and `b[3]` request blocks that were loaded and then replaced, so their misses are due to the **conflict** in the line, while the other four misses are the first loads of the blocks. Lines $2$ and $3$ stay empty, yet direct mapping does not allow these blocks to be placed there.

In the second case the distance is five blocks, so the block of `b[i]` occupies the line after that of `a[i]`. Line $1$ holds block $5$ first and then block $1$. When block $5$ is replaced, the reads of `b[0]` and `b[1]` have already taken place. For each block, therefore, the read of the first element is a miss and that of the second a hit. The number of misses equals the number of distinct blocks requested, namely $0$, $5$, $1$ and $6$.

</div>
