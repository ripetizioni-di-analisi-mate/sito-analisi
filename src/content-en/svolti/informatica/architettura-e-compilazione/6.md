## Exercise 1

Write the two declarations produced by preprocessing the following fragment, preserving token order.
```c
#define FACTOR 6
#define BASE 3
int result = FACTOR * BASE;
char label[] = "FACTOR";
```

```c
int result = 6 * 3;
char label[] = "FACTOR";
```

<div class="spiegazione">

`FACTOR` and `BASE` are separate tokens in the initializer for `result`, so each is replaced by its associated number. The product remains an expression. The sequence `"FACTOR"` is a single string token, so it stays unchanged.

As a check, pass the fragment to the GCC-compatible driver with `-E -P`. The first option stops translation after preprocessing and the second suppresses line markers. The two declarations it prints match the calculated declarations.

</div>

## Exercise 2

Each source produces a single object with the same base name. The system recompiles each source once if it depends directly or indirectly on a changed file. Only `common.h` and `scale.h` change. Determine which object files must be rebuilt. `app.h` includes `common.h` and `scale.h`. `log.h` includes no other project headers.
| Source | Direct inclusions |
|---|---|
| `main.c` | `app.h` |
| `metrics.c` | `common.h` and `scale.h` |
| `export.c` | `scale.h` |
| `log.c` | `log.h` |

| Changed header | Dependent objects |
|---|---|
| `common.h` | `main.o` and `metrics.o` |
| `scale.h` | `main.o`, `metrics.o` and `export.o` |

The object files to rebuild are `main.o`, `metrics.o` and `export.o`.

<div class="spiegazione">

Follow the inclusions backwards from the changed files to the sources. `app.h` makes both changes relevant to `main.c`. `metrics.c` reaches both headers in one step and `export.c` reaches only `scale.h`. An object is rebuilt once even if several changes affect it.

To check, follow the table starting from each source. Expanding `app.h` leads `main.c` to both changed files. `metrics.c` and `export.c` reach at least `scale.h`. The path from `log.c` ends at `log.h`, so its object can be reused.

</div>

## Exercise 3

Write the two declarations produced by preprocessing the following fragment and compute the values of `area` and `mode`. Then change a single directive so that `area` equals the square of the value $4$ expressed by `WIDTH`, and determine the new value of `mode`.
```c
#define WIDTH 3 + 1
#define AREA WIDTH * WIDTH
#if AREA > 10
#define MODE 2
#else
#define MODE 1
#endif
int area = AREA;
int mode = MODE;
```

```c
int area = 3 + 1 * 3 + 1;
int mode = 1;
```

$$
\text{area}=3+1\cdot3+1=7 .
$$

With the directive `#define WIDTH (3 + 1)` the preprocessor produces

```c
int area = (3 + 1) * (3 + 1);
int mode = 2;
```

and `area` equals $16$.

<div class="spiegazione">

Replacing `AREA` produces the tokens `WIDTH * WIDTH`. The preprocessor **rescans** the replacement and finds two more macro names, so it also replaces each `WIDTH` with the three tokens `3 + 1`. Replacement works on tokens regardless of C precedence, so in the resulting expression the operands of the multiplication are only the two middle `1`s. The initializer equals $3+3+1=7$.

The same expansion takes place in the `#if` condition, which becomes $3+1\cdot3+1>10$, that is, $7>10$. The condition is false, so the `#else` branch defines `MODE` as `1`.

The parentheses in the replacement of `WIDTH` make the sum a single operand of each factor. With the correction the initializer equals $4\cdot4=16$ and the `#if` condition becomes $16>10$, which is true. The first branch therefore gives `MODE` the replacement `2`. A single directive thus changes both declarations, because `#if` uses the same macro as the initializer. The GCC driver with `-E -P` prints exactly the declarations written in the two cases.

</div>
