## Exercise 1

The file `report.c` contains the following program. Use a GCC-compatible driver in a hosted POSIX-style environment. Identify the kind of file produced by each command, then give the command that builds `app` from the second output.
```c
int main(void)
{
    return 0;
}
```
```shell
cc -std=c17 -S report.c -o plan.s
cc -c plan.s -o report.o
```

File `plan.s` is an assembly listing. File `report.o` is an object file. The link command is

```shell
cc report.o -o app
```

<div class="spiegazione">

Since the first input has extension `.c`, the driver preprocesses and compiles it before stopping at `-S`. The input of the second command, with extension `.s`, is already assembly, so `-c` gives the object file produced by the assembler. The last command passes that object to the linker along with the inputs the driver supplies for a hosted executable.

Check the path by running the three commands in order. `plan.s` is readable as assembly text, `report.o` holds the definition of `main` and the executable terminates with a success status. The outputs are of different kinds even though `-o` selects their names.

</div>

## Exercise 2

A hosted project consists of four objects. The references in the table are the only project references still to be resolved. Building the executable requires `main`. All listed symbols are strong and the function declarations are compatible. Find the smallest set of object files sufficient for the link.
| Object | Defines | Requires |
|---|---|---|
| `main.o` | `main` | `scale` |
| `scale.o` | `scale` | `offset` |
| `constants.o` | `offset` | no symbol |
| `diag.o` | `diagnose` | no symbol |

The required objects are `main.o`, `scale.o` and `constants.o`.

<div class="spiegazione">

`main.o` is the only object defining `main`, so it belongs in the set. From `main.o` the dependency reaches `scale`, whose definition is in `scale.o`. Adding that object introduces a reference to `offset`, resolved by `constants.o`. The chain of dependencies ends there.

To check minimality, remove each of the three objects in turn. Removing `main.o` leaves no entry point. Removing `scale.o` or `constants.o` leaves `scale` or `offset` unresolved, respectively. No object requires `diagnose`, so `diag.o` is unnecessary.

</div>

## Exercise 3

A hosted project has five objects, already produced by separate translation. `parse.o` and `fastparse.o` contain two alternative implementations of the same function. All symbols are strong, the declarations are compatible and the references in the table are the only ones to resolve. Determine at which stage and for which symbol the following command fails. Then find the two minimal sets of objects for which the link succeeds.
```shell
cc main.o parse.o fastparse.o report.o format.o -o app
```
| Object | Defines | Requires |
|---|---|---|
| `main.o` | `main` | `parse` and `report` |
| `parse.o` | `parse` | `buffer_size` |
| `fastparse.o` | `parse` | no symbol |
| `report.o` | `report` | `format` |
| `format.o` | `format` and `buffer_size` | no symbol |

The command fails at link time, because `parse` is defined in both `parse.o` and `fastparse.o`. There are two minimal sets.

| Set | Objects |
|---|---|
| with `parse.o` | `main.o`, `parse.o`, `report.o`, `format.o` |
| with `fastparse.o` | `main.o`, `fastparse.o`, `report.o`, `format.o` |

<div class="spiegazione">

The inputs of the command are only object files, so the driver performs the link alone. Two ordinary external definitions of the same name are a **conflict**, so the presence of both objects defining `parse` prevents `app` from being built. The linker started by the driver reports a multiple definition of `parse`. Every valid set therefore contains exactly one of the two objects.

From `main.o` the references reach `parse` and `report`. The object `report.o` introduces the reference to `format`, which is defined only in `format.o`. With `parse.o`, `buffer_size` is also needed, and it is again defined in `format.o`, so the set still has four objects. With `fastparse.o` there is no reference to `buffer_size`, and `format.o` is required anyway for `format`.

To check minimality, remove one object at a time from each set. Removing `main.o` leaves no `main`, removing `report.o` leaves `report` unresolved and removing `format.o` leaves `format` unresolved. Removing the only object that defines `parse` leaves `parse` unresolved. The two sets have the same number of objects, because the object defining `buffer_size` is the same one that defines `format`.

</div>
