## Exercise 1

A machine uses eight-bit bytes. In a two-byte unsigned word, the lower address holds `0x05` and the next address holds `0xA0`. Compute the decimal value of the word if the order is big endian.

$$
\begin{aligned}
\text{value} &= 5\cdot 256+160\\[6pt]
 &= 1280+160=1440 .
\end{aligned}
$$

<div class="spiegazione">

In **big-endian** order, the byte at the lower address carries the higher weight. The byte at the following address has weight one, so it contributes its value directly. The hexadecimal digit `A` has value ten, so `0xA0` equals $10\cdot 16=160$.

As a check, divide the result $1440$ by $256$. The quotient is $5$ and the remainder is $160$. The quotient and remainder therefore recover the two original bytes in order.

</div>

## Exercise 2

Store the unsigned word `0x1234ABCD` at addresses `0x100` through `0x103` on a machine with eight-bit bytes. Give the contents of each address for both byte orders.

| Address | Big endian | Little endian |
|---|---|---|
| `0x100` | `0x12` | `0xCD` |
| `0x101` | `0x34` | `0xAB` |
| `0x102` | `0xAB` | `0x34` |
| `0x103` | `0xCD` | `0x12` |

<div class="spiegazione">

A byte holds two hexadecimal digits because two digits provide $16^2=256$ patterns. Split the representation into four groups of two digits. In big-endian order, assign the most significant byte to address `0x100`. In little-endian order, start with the least significant byte, `0xCD`. The value of each group of two digits stays the same.

To check the word, read the groups in each column from the greatest weight to the least. In the big-endian column this follows increasing addresses. In the little-endian column it follows decreasing addresses. Both readings give `12 34 AB CD` and reconstruct the same word.

</div>

## Exercise 3

A big-endian machine writes the four bytes of the unsigned word $500$ to a file, starting from the lower address. A little-endian machine reads the four bytes in the same order and copies them into an `unsigned`. Both use eight-bit bytes and $32$-bit `unsigned`. Compute the value read and check that the function `swap_bytes` returns $500$ when it receives that value.
```c
unsigned swap_bytes(unsigned x)
{
    return (x >> 24) | ((x >> 8) & 0xFF00u)
           | ((x << 8) & 0xFF0000u) | (x << 24);
}
```

$$
\begin{aligned}
500 &= 1\cdot256+244=(000001\mathrm{F}4)_{16}\\[6pt]
\text{value read} &= 0\cdot256^0+0\cdot256^1+1\cdot256^2+244\cdot256^3\\[6pt]
 &= 65536+4093640704=4093706240 .
\end{aligned}
$$

The value read is `0xF4010000`. With `x` equal to `0xF4010000u` the four terms of the function are:

| Term | Value |
|---|---|
| `x >> 24` | `0x000000F4` |
| `(x >> 8) & 0xFF00u` | `0x00000100` |
| `(x << 8) & 0xFF0000u` | `0x00000000` |
| `x << 24` | `0x00000000` |

Their bitwise OR is `0x000001F4`, that is, $500$.

<div class="spiegazione">

The big-endian machine writes the most significant byte first, so the bytes appear in the file in the order `0x00`, `0x00`, `0x01`, `0xF4`. The little-endian machine gives weight $256^j$ to the byte with index $j$, so byte `0xF4` receives the highest weight. The value read is therefore very different from $500$, even though the bytes transferred are the same.

The function moves each byte to the mirror position. Shifting right by $24$ positions brings `0xF4` to the lowest byte. Shifting right by $8$ positions brings `0x01` to the second byte, and the mask `0xFF00u` isolates that byte alone. The other two terms are zero because the two low bytes of `x` are zero. A left shift by fewer than $32$ places of an `unsigned` operand has a defined result even when some bits leave the word, because the value is reduced modulo $2^{32}$. The same function also converts in the opposite direction, since two successive swaps give back the original word.

</div>
