## Exercise 1

Calculate `score(4)`, distinguishing the two entities named `n`.

```c
int score(int n)
{
    int result = n;
    {
        int n = result + 2;
        result += n;
    }
    return result - n;
}
```

At entry `result` is $4$. In the inner block the new `n` is $4+2=6$, so `result` becomes $4+6=10$. The parameter is visible at the return, making the result $10-4=6$.

<div class="spiegazione">

The initialization of `result` comes before the nested block and reads the parameter. The inner declaration introduces an object whose scope is limited to that block. The addition therefore uses its value $6$. After the block ends, `n` again denotes the parameter with value $4$.

To check the name resolution, rename only the inner object to `local`. For an argument $q$ within the arithmetic domain, the formula becomes $q+(q+2)-q=q+2$. In particular, $q=4$ gives $6$.

</div>

## Exercise 2

In a fresh run, `stamp(1)`, `stamp(0)` and `stamp(-2)` are evaluated in order, in three separate statements. Find the results.

```c
int stamp(int step)
{
    static int total = 2;
    int local = 3;
    local += step;
    total += local;
    return total;
}
```

| `step` | Updated `local` | Returned `total` |
| --- | --- | --- |
| $1$ | $4$ | $6$ |
| $0$ | $3$ | $9$ |
| $-2$ | $1$ | $10$ |

<div class="spiegazione">

`total` has static storage duration and starts at $2$ before the first call. Each call initializes its own `local` to $3$, so the increments to `total` are $3+1$, $3+0$ and $3-2$. The second call starts from $6$ and the third from $9$, because only `total` retains its state.

A cumulative check gives $2+(4+3+1)=10$ at the end. The differences between successive results are $9-6=3$ and $10-9=1$. These agree with the final two increments, so the sequence respects automatic initialization on each call.

</div>

## Exercise 3

In a fresh run, the following program calls `next_id` three times inside a loop. Find the output and state, in each statement, which object the name `count` denotes.

```c
#include <stdio.h>

int next_id(int base)
{
    static int count = 0;
    int offset = 1;
    count += offset;
    {
        int count = base * 10;
        offset = count;
    }
    return offset + count;
}

int main(void)
{
    for (int i = 1; i <= 3; i++) {
        printf("%d\n", next_id(2 * i - 1));
    }
    return 0;
}
```

| `i` | `base` | static `count` | inner `count` | Returned value |
| --- | --- | --- | --- | --- |
| $1$ | $1$ | $1$ | $10$ | $11$ |
| $2$ | $3$ | $2$ | $30$ | $32$ |
| $3$ | $5$ | $3$ | $50$ | $53$ |

The program prints the following three lines.

```text
11
32
53
```

<div class="spiegazione">

The first `count` is declared `static`, so it has static storage duration, is initialized to $0$ only once before program startup and keeps its value between calls. The variable `offset` has automatic storage duration, so it starts again from $1$ on every call and the statement `count += offset;` increases the static counter by $1$. In the inner block the declaration `int count = base * 10;` introduces a new object, which **shadows** the static counter up to the closing brace of the block. The assignment `offset = count;` therefore reads the inner object and copies the value of `base * 10` into `offset`. After the block the name `count` again denotes the static counter, so the `return` adds `base * 10` and the sequence number of the call.

In the call with index $i$ the argument is $2i-1$ and the static counter is $i$. The returned value is therefore $10(2i-1)+i=21i-10$, which for $i=1,2,3$ gives $11$, $32$ and $53$. With the `-Wshadow` option, GCC reports that the inner declaration shadows a previous local variable.

</div>
