## Exercise 1

For `0 <= pieces <= 15`, the first step computes a subtotal and the second accepts integer amounts from $0$ to $40$. Check that the domain of the second step is satisfied and compute `bill(3)` and `bill(6)`.
```c
int subtotal(int pieces)
{
    return 2 * pieces + 3;
}

int min_charge(int amount)
{
    return amount < 11 ? 11 : amount;
}

int bill(int pieces)
{
    return min_charge(subtotal(pieces));
}
```

At the domain endpoints `subtotal` gives $3$ and $33$. The value increases with `pieces`, so every result is valid for `min_charge`. At $3$ the steps give $9$ and then $11$. At $6$ they give $15$ and then $15$.

<div class="spiegazione">

The first function computes a cost that rises by $2$ for each unit. Its minimum and maximum are therefore $2\cdot0+3=3$ and $2\cdot15+3=33$. Both satisfy the limits $0$ and $40$, so the intermediate result always meets the second contract. At $3$ the cost $9$ is below the threshold $11$, while at $6$ the cost $15$ is above it.

To check the branches, solve $2p+3<11$ for integer quantity $p$. This is equivalent to $p<4$. Thus $3$ gives the minimum and $6$ gives the ordinary cost. At the boundary $p=4$, both rules give $11$.

</div>

## Exercise 2

The first step `raw_level(x)` is valid for integers from $0$ to $10$. The second step `reduce(level)` accepts only integers from $0$ to $19$. Find the largest subset of the original domain for which `reduce(raw_level(x))` respects both contracts.
```c
int raw_level(int x)
{
    return 12 + x;
}

int reduce(int level)
{
    return level / 2;
}
```

The constraint of the second step requires $0\leq12+x\leq19$, so $-12\leq x\leq7$. Intersecting this with the domain from $0$ to $10$ gives all integers from $0$ to $7$.

<div class="spiegazione">

The first result is the actual argument of the second step, so it is substituted into the precondition on `level`. The lower bound is satisfied by every original input because the minimum intermediate result is $12$. The upper bound requires $x\leq7$. A larger input can still yield an integer with this implementation. Such a case lies outside the stated contract.

To check, evaluate the two boundary inputs. Input $7$ gives $19$, so the composition is valid and returns $9$. Input $8$ gives an intermediate value of $20$, beyond the domain of `reduce`. Since `raw_level` increases, every integer greater than $8$ allowed by the first contract violates the second.

</div>
