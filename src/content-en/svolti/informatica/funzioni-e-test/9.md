## Exercise 1

Write the function `digit_sum` with the contract given in the comment, for 32-bit `unsigned`. Then write a test `main` with assertions that covers the classes and boundaries of the specification.

```c
/* Pre: none. Post: returns the sum of the decimal digits of n,
   with digit_sum(0u) == 0u. */
unsigned digit_sum(unsigned n);
```

A function that satisfies the contract and its test program are the following.

```c
#include <assert.h>
#include <limits.h>

unsigned digit_sum(unsigned n)
{
    unsigned sum = 0u;
    while (n > 0u) {
        sum += n % 10u;
        n /= 10u;
    }
    return sum;
}

int main(void)
{
    assert(digit_sum(0u) == 0u);
    assert(digit_sum(9u) == 9u);
    assert(digit_sum(10u) == 1u);
    assert(digit_sum(4095u) == 18u);
    assert(digit_sum(UINT_MAX) == 57u);
    return 0;
}
```

| Input | Class or boundary | Expected |
| --- | --- | --- |
| `0u` | no iterations, lower endpoint | $0$ |
| `9u` | last value with one digit | $9$ |
| `10u` | first value with two digits | $1$ |
| `4095u` | several digits, one of them zero | $18$ |
| `UINT_MAX` | upper endpoint, $4294967295$ | $57$ |

With assertions enabled the program exits with status $0$.

<div class="spiegazione">

The remainder `n % 10u` is the last decimal digit of `n` and the division `n /= 10u` removes it, so each iteration adds one digit to `sum`. The loop terminates, because on each iteration a positive `n` strictly decreases and therefore reaches $0$ after finitely many iterations. For the input $0$ the loop performs no iterations, so the function returns the initial value of `sum`, as the postcondition requires. The largest `unsigned` has ten digits, so `sum` is at most $9\cdot10=90$ and every addition gives the exact mathematical value.

The oracles come from the specification. For `UINT_MAX` the sum is $4+2+9+4+9+6+7+2+9+5=57$. The classes distinguish the loop with no iterations, a single iteration and several iterations. The boundaries $9$ and $10$ are the two consecutive integers where the number of digits goes from one to two, while $0$ and `UINT_MAX` are the endpoints of the domain.

</div>

## Exercise 2

Write the function `fits_sum` with the contract given in the comment, so that no operation in the body causes overflow, even when the sum lies outside the range of `int`. Then choose the test cases at the boundaries of the two limits.

```c
/* Pre: none. Post: returns 1 if the mathematical sum a + b
   lies between INT_MIN and INT_MAX, 0 otherwise. */
int fits_sum(int a, int b);
```

The following body compares `a` with a limit computed without adding.

```c
#include <limits.h>

int fits_sum(int a, int b)
{
    if (b > 0) {
        return a <= INT_MAX - b;
    }
    return a >= INT_MIN - b;
}
```

| `a` | `b` | Expected |
| --- | --- | --- |
| `INT_MAX` | $0$ | $1$ |
| `INT_MAX - 1` | $1$ | $1$ |
| `INT_MAX` | $1$ | $0$ |
| `INT_MIN` | $0$ | $1$ |
| `INT_MIN + 1` | $-1$ | $1$ |
| `INT_MIN` | $-1$ | $0$ |
| $0$ | `INT_MIN` | $1$ |
| $-1$ | `INT_MIN` | $0$ |

<div class="spiegazione">

Let $M$ be the value of `INT_MAX` and $m$ the value of `INT_MIN`. With $b>0$ the sum can only exceed $M$, and the condition $a+b\leq M$ is equivalent to $a\leq M-b$. Since $0<b\leq M$, the difference $M-b$ lies between $0$ and $M-1$, so `INT_MAX - b` is representable. With $b\leq0$ the sum can only fall below $m$, and the condition $a+b\geq m$ is equivalent to $a\geq m-b$. Since $m\leq b\leq0$, the difference $m-b$ lies between $m$ and $0$, so `INT_MIN - b` is representable as well. The function therefore never evaluates the sum `a + b`.

Each limit has two boundary cases, the last admitted pair and the first excluded one. The last two rows put `INT_MIN` in `b`, where `INT_MIN - b` equals $0$. The test program with these eight assertions, compiled with `-fsanitize=undefined`, terminates without reports. The type `long long` has at least $64$ bits, so in that type the sum of two `int` values is always representable. The comparison with the sum computed in `long long` on all $81$ pairs formed with `INT_MIN`, `INT_MIN + 1`, `INT_MIN + 2`, $-1$, $0$, $1$, `INT_MAX - 2`, `INT_MAX - 1` and `INT_MAX` finds no differences.

</div>

## Exercise 3

Write the two functions with the contracts given in the comments, with `days_in_month` using `is_leap` for February. A year is a leap year if it is divisible by $400$, or if it is divisible by $4$ and not by $100$. Then write a test `main` and identify the assertion that fails if `is_leap` omits the rule of $400$.

```c
/* Pre: 1583 <= year <= 9999.
   Post: returns 1 if year is a leap year, 0 otherwise. */
int is_leap(int year);

/* Pre: 1 <= month <= 12 and 1583 <= year <= 9999.
   Post: returns the number of days of that month in that year. */
int days_in_month(int month, int year);
```

A solution with its test program is the following.

```c
#include <assert.h>

int is_leap(int year)
{
    return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
}

int days_in_month(int month, int year)
{
    if (month == 2) {
        return 28 + is_leap(year);
    }
    if (month == 4 || month == 6 || month == 9 || month == 11) {
        return 30;
    }
    return 31;
}

int main(void)
{
    assert(days_in_month(2, 2023) == 28);
    assert(days_in_month(2, 2024) == 29);
    assert(days_in_month(2, 1900) == 28);
    assert(days_in_month(2, 2000) == 29);
    assert(days_in_month(4, 2023) == 30);
    assert(days_in_month(1, 2023) == 31);
    assert(days_in_month(12, 2023) == 31);
    return 0;
}
```

Without `|| year % 400 == 0` the program terminates through `abort`, and the diagnostic written to `stderr` contains the following text.

```text
Assertion `days_in_month(2, 2000) == 29' failed.
```

<div class="spiegazione">

The precondition of `days_in_month` contains that of `is_leap`, so the inner call always receives an admitted year. By the postcondition of `is_leap` the result is $0$ or $1$, so the expression `28 + is_leap(year)` equals $28$ or $29$, as the contract requires for February.

The leap-year rule divides the years into four classes, namely not divisible by $4$ ($2023$), divisible by $4$ and not by $100$ ($2024$), divisible by $100$ and not by $400$ ($1900$), divisible by $400$ ($2000$). The first four assertions have one representative per class. The other three test the months with $30$ and $31$ days, with months $1$ and $12$ at the endpoints of the domain. Without the rule of $400$, the year $2000$ is divisible by $100$ and the function returns $0$, so February has $28$ days and the fourth assertion is false. The first three classes give the same results as in the correct version.

</div>
