## Exercise 1

The contract of `clamp` requires `lo <= hi`. It returns the lower endpoint below the band, the upper endpoint above the band, and `x` in the band. Check the precondition and result for `clamp(-1, 0, 4)`, `clamp(4, 0, 4)` and `clamp(3, 5, 5)`.
```c
int clamp(int x, int lo, int hi)
{
    if (x < lo) {
        return lo;
    }
    if (x > hi) {
        return hi;
    }
    return x;
}
```

The preconditions hold because $0\leq4$ and $5\leq5$. In the first case, $-1<0$, so the result is $0$. In the second, $x=4$ is in the band, so it remains $4$. In the third case $3<5$ and the result is $5$.

<div class="spiegazione">

The implementation first checks whether the value is below the band. In that case it returns `lo` immediately. In the remaining branches it checks whether the input is above `hi` and returns `x` for an input inside the band. If the band has zero width, the common endpoint is the only integer result allowed by the postcondition.

One check evaluates the formula $\min\{hi,\max\{lo,x\}\}$. The intermediate maxima are $0$, $4$, $5$. The corresponding minima with the upper endpoints $4$, $4$, $5$ give $0$, $4$, $5$, matching the branches.

</div>

## Exercise 2

On a C17 machine with `INT_MAX` equal to $32767$, find the largest non-negative `n` allowed when evaluating `charge(n)` with all operations representable in `int`.
```c
int charge(int n)
{
    return 11 + 7 * n;
}
```

The inequality $11+7n\leq32767$ gives

$$
n\leq\left\lfloor\frac{32767-11}{7}\right\rfloor=4679 .
$$

The maximum is $4679$.

<div class="spiegazione">

Since `n` is non-negative, $7n$ is also non-negative. If the sum is at most $32767$, the product, which is smaller than the sum, must be representable. The mathematical function increases with $n$, so it is enough to bound the last valid input.

As a check, $7\cdot4679=32753$ and $11+32753=32764$, within the range. For the next integer, the mathematical value is $32764+7=32771$. This exceeds the limit, so that C expression does not have a defined result for that input on the assumed machine.

</div>

## Exercise 3

Consider a C17 implementation with 32-bit `int`, so `INT_MAX` equals $2147483647$. The function computes the area of a frame of width $1$ around a square of side $w\geq0$. Find the largest `w` for which all operations are representable, then the largest for the version with body `return 4 * w + 4;`, which has the same mathematical value.

```c
int frame_area(int w)
{
    return (w + 2) * (w + 2) - w * w;
}
```

The first version requires $(w+2)^2\leq2147483647$. Since $46340^2=2147395600$ and $46341^2=2147488281$, this gives

$$
w+2\leq46340 \qquad\Longrightarrow\qquad w\leq46338 .
$$

The second version requires $4w+4\leq2147483647$, which gives

$$
w\leq\left\lfloor\frac{2147483647-4}{4}\right\rfloor=536870910 .
$$

<div class="spiegazione">

The mathematical value of both expressions is $(w+2)^2-w^2=4w+4$. The first version, however, computes the product $(w+2)(w+2)$ before the subtraction, so the domain depends on the largest intermediate result. With $w\geq0$ both products are non-negative and $w^2<(w+2)^2$, so it is enough for $(w+2)^2$ to be representable. The difference of two representable non-negative values is representable as well. At $w=46338$ the function returns $185356$, a value far from `INT_MAX`. At $w=46339$ the product $46341\cdot46341$ exceeds `INT_MAX`, so a **signed overflow** occurs, which is undefined behavior. The program compiled with `-fsanitize=undefined` reports at that input `signed integer overflow: 46341 * 46341 cannot be represented in type 'int'`.

In the second version the largest intermediate value is the result itself, because $4w\leq4w+4$. The limit therefore rises to $536870910$, where the function returns $2147483644$. At the next integer the mathematical value is $2^{31}=2147483648$, which exceeds `INT_MAX`.

</div>
