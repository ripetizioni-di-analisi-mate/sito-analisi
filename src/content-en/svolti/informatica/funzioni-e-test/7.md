## Exercise 1

For integer weights from $1$ to $12$, shipping costs $5$ for a weight of at most $7$ and $9$ otherwise. Use the two consecutive inputs that straddle the boundary and locate the defect in the function.
```c
int shipping(int weight)
{
    return weight <= 8 ? 5 : 9;
}
```

| Weight | Expected | Actual |
| --- | --- | --- |
| $7$ | $5$ | $5$ |
| $8$ | $9$ | $5$ |

The threshold must be `weight <= 7`.

<div class="spiegazione">

Weight $7$ is the last input that meets the requirement for the lower price. The next integer is $8$, so the oracle already expects $9$. The body uses an inclusive inequality with $8$ and still selects $5$ at that weight.

The uniqueness of the defect can be checked by comparing the sets that receive $5$. The specification uses the integers from $1$ to $7$ and the body uses those from $1$ to $8$. The sets differ only at $8$, so every other input in the domain receives the correct price.

</div>

## Exercise 2

The function `keep` takes integers from $0$ to $10$. If `lo > hi`, it must return $-1$. Otherwise it must return `x` clamped to the closed band from `lo` to `hi`. Use `keep(5, 4, 4)` as a boundary case, then correct the condition.
```c
int keep(int x, int lo, int hi)
{
    if (lo >= hi) {
        return -1;
    }
    if (x < lo) {
        return lo;
    }
    if (x > hi) {
        return hi;
    }
    return x;
}
```

With `lo == hi`, $4=4$, so the band contains $4$. The expected result is $4$ and the code returns $-1$. The correct condition is `lo > hi`.

<div class="spiegazione">

The band is valid because the contract excludes only strictly reversed endpoints. Since $5>4$, clamping must use the upper endpoint $4$. In the given code the initial condition also includes equality. That test returns $-1$ before the clamping branches execute.

To check the correction, compare with `keep(5, 5, 4)`. There $5>4$ for the endpoint order, so $-1$ is required. With condition `lo > hi`, the degenerate band reaches the clamping step and produces $4$.

</div>
