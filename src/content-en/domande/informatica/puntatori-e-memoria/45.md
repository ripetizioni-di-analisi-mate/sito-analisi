An initially empty dynamic array has `int *p = NULL;`. With `<stdlib.h>` included and a representable `bytes > 0`, how does `realloc(p, bytes)` behave?

- It allocates the block and always zeroes all storage.
- It first asks to release a previous zero-size block.
- It always returns `NULL` without making a request.
- It requests a first block as `malloc(bytes)` does.

## Explanation

In C17 a null pointer with a strictly positive size makes the call equivalent to `malloc` for the requested size. The returned value therefore identifies a new block if allocation succeeds, or is `NULL` if it fails. The call does not set initial values for the elements.
