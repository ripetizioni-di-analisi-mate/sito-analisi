What happens in `divide(0)` when `NDEBUG` is absent or defined at inclusion of `<assert.h>`?

```c
#include <assert.h>

int divide(int n)
{
    assert(n != 0);
    return 21 / n;
}
```

- Both builds call `abort` before the division.
- With assertions enabled, the function returns $0$. With assertions disabled, it calls `abort`.
- The function returns $0$ in both builds.
- With assertions enabled, `abort` is called. With assertions disabled, the division has undefined behavior.

## Explanation

With the assertion enabled, `n != 0` is false and the macro terminates the program abnormally through `abort` before the `return`. When `NDEBUG` is defined at inclusion, the argument of `assert` is discarded. Execution therefore reaches an integer division by zero, for which C17 defines no result.
