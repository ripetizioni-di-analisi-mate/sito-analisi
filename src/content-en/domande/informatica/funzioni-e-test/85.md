The function must return `x*x+1` for every integer from 0 through 10, including the first call. The body caches its latest result. In a fresh process, which sequence exposes the defect on its **first** comparison with the oracle?

```c
int cached(int x)
{
    static int key;
    static int value;
    if (x != key) {
        key = x;
        value = x * x + 1;
    }
    return value;
}
```

- Call with 0 and expect 1.
- Call with 1 and expect 2.
- Call with 3 and expect 10.
- Call with 2 and expect 5.

## Explanation

At startup both static variables contain 0. If the argument is also 0, the comparison skips the computation and returns the initial zero instead of 1. A nonzero first input immediately fills the cache and can hide the initialisation error.
