A file header declares two records. The specification requires exactly two valid data lines and no other line. The parser reads two valid records, followed by a third line `X`, before normal end-of-file. What should the test report?

- The outcome is indeterminate because normal end-of-file cannot be distinguished from an error.
- The file conforms if X is not a number.
- The file conforms because the number of valid records is two.
- The file is nonconforming because of the additional content.

## Explanation

Reaching two records meets only the requirement on the number of valid data items. The specification also prohibits additional lines. The third line establishes a violation regardless of its content, so the parser has to check how the file ends.
