In the C locale a line must contain a **decimal** integer and nothing else. The parser calls `strtol(s, &end, 10)` with `s` pointing to `"0x10"`. What observation justifies the decision about this line?

- The hexadecimal prefix is recognised and the line represents 16.
- No character is converted because the string contains an x.
- The function assumes base eight because the first digit is 0.
- The initial 0 is converted, but `*end` is `'x'` and the line must be rejected.

## Explanation

The requested base is 10. In this base the first character is a valid digit and x stops the digit sequence. The numeric zero is therefore the value of a prefix, and checking the rest of the line reveals disallowed characters.
