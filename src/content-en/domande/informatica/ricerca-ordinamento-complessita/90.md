A merge-based sort deliberately divides every run of $m\ge2$ entries into one singleton and a run of length $m-1$. Each merge writes all $m$ entries to the output. What is the tight order of the number of merge writes for $n$ entries?

- $\Theta(n)$
- $\Theta(n^2)$
- $\Theta(n\log n)$
- $\Theta(\log n)$

## Explanation

There is one merge at each length $2,3,\ldots,n$. The write count is therefore $2+3+\cdots+n=\dfrac{n(n+1)}{2}-1$. Depth grows by one level for every added entry because the larger child loses only a single entry.
