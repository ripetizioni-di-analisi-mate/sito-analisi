After sorting two nonempty children, a merge sort skips their merge when the last left key is at most the first right key. On eight already increasing keys, always split in half, how many boundary tests and how many actual merges does it perform?

- $0$ tests and $0$ merges
- $3$ tests and $0$ merges
- $7$ tests and $7$ merges
- $7$ tests and $0$ merges

## Explanation

There are four nodes with two entries, two with four, and the root with eight. Each of these seven nodes checks a boundary. Every boundary is already ordered, so each test allows the corresponding merge to be skipped.
