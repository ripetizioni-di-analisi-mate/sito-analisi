The caller declares `int rate(int);`. In another source file that cannot see the declaration, the definition is `double rate(double x) { return x; }`. The C17 units compile separately, and a linker that matches names only accepts the project. What can be concluded before it runs?

- The name has been resolved, but the declarations are incompatible and the call has undefined behaviour
- The return value is always the caller’s argument converted to `int`
- The linker must insert conversions between `int` and `double`
- A successful link proves the two types are compatible

## Explanation

The parameter type and the return type differ between the two declarations. Resolving a name does not check the contract the units use to pass the argument and result. Including the same prototype in the source defining `rate` makes the conflicting types visible there.
