Two different headers accidentally use the same guard `PROJ_H`. Each begins with `#ifndef PROJ_H` and `#define PROJ_H` and closes the guard at the end of the file. `left.h` declares only `left` and `right.h` only `right`. A source file includes `left.h` followed by `right.h`, with the guard initially undefined. Which correction preserves both declarations and still protects each header against its own repeated inclusion?

- Only reverse the order of the includes
- Use a different guard name for each header
- Repeat both includes in the same order
- Define `PROJ_H` before both includes

## Explanation

The first inclusion defines `PROJ_H`. When the second file is read, its guard is already set and hides its declaration. With distinct guard names each header contributes its contents on its first inclusion and can still suppress later copies of itself.
