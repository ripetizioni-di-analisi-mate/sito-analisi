Un server ha ricevuto solo parte di un file su TCP quando la connessione cade. Quale dato deve considerare l'applicazione per stabilire che il file è incompleto?

- La lunghezza prevista rispetto ai byte effettivamente ricevuti.
- L'ultimo numero di porta del server.
- Il fatto che una parte sia arrivata in ordine.
- L'indirizzo MAC del client.

## Spiegazione

TCP consegna i byte in ordine, ma una chiusura o un errore può interrompere il trasferimento prima della fine del file. L'arrivo ordinato di una parte non dice quindi se il file è completo. L'applicazione confronta perciò la lunghezza prevista, comunicata per esempio all'inizio del trasferimento, con il numero di byte ricevuti. Se i byte ricevuti sono meno della lunghezza prevista, il file è **incompleto**.
