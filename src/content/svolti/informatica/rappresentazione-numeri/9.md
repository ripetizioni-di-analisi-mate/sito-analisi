## Esercizio 1

Scrivere l’output esatto del programma. Si assumono `int` e `unsigned int` a $32$ bit e scrittura riuscita. Il tipo `uint8_t` di `<stdint.h>` è un intero senza segno di $8$ bit.

```c
#include <stdint.h>
#include <stdio.h>

int main(void)
{
    uint8_t a = 0xC8u;
    uint8_t b = 0x5Au;
    uint8_t s = (uint8_t)(a + b);

    printf("%d %u %02X\n", a + b, (unsigned)s, (unsigned)s);
    return 0;
}
```

```text
290 34 22
```

$$
\begin{aligned}
(C8)_{16}+(5A)_{16} &= 200+90=290 \\[6pt]
290 &= 256+34 \\[6pt]
34 &= (0010\;0010)_2=(22)_{16} .
\end{aligned}
$$

<div class="spiegazione">

Nell’espressione `a + b` i due operandi hanno tipo `uint8_t`. Poiché `int` rappresenta tutti i valori da $0$ a $255$, la **promozione intera** converte entrambi gli operandi in `int` prima della somma. La somma vale quindi $290$, ha tipo `int` e corrisponde allo specificatore `%d`. Nella dichiarazione di `s` lo stesso valore viene convertito in `uint8_t`. La conversione verso un tipo senza segno riduce il valore modulo il numero dei valori del tipo, cioè $2^8$, perciò `s` vale $290-256=34$. Questo è il resto modulo $2^8$ previsto dalla somma su larghezza fissa.

In binario si ha $11001000+01011010=1\,00100010$. Il nono bit è il riporto oltre l’ottava posizione e la conversione lo scarta. Gli otto bit conservati formano le quartine $0010$ e $0010$, quindi `%02X` stampa `22`.

</div>

## Esercizio 2

Scrivere l’output esatto del programma. Si assumono `int` e `unsigned int` a $32$ bit e scrittura riuscita. I tipi `int8_t` e `uint16_t` di `<stdint.h>` sono un intero con segno di $8$ bit e un intero senza segno di $16$ bit.

```c
#include <stdint.h>
#include <stdio.h>

int main(void)
{
    int8_t v = -75;
    uint8_t w = (uint8_t)v;
    uint16_t h = (uint16_t)v;
    unsigned u = (unsigned)v;

    printf("%u %X\n", (unsigned)w, (unsigned)w);
    printf("%u %X\n", (unsigned)h, (unsigned)h);
    printf("%u %X\n", u, u);
    return 0;
}
```

```text
181 B5
65461 FFB5
4294967221 FFFFFFB5
```

$$
\begin{aligned}
-75+2^8 &= 181=(B5)_{16} \\[6pt]
-75+2^{16} &= 65461=(FFB5)_{16} \\[6pt]
-75+2^{32} &= 4294967221=(FFFFFFB5)_{16} .
\end{aligned}
$$

<div class="spiegazione">

Le tre conversioni hanno come destinazione un tipo senza segno di $N$ bit. Il valore $-75$ è fuori dall’intervallo di destinazione, quindi la conversione gli aggiunge il numero dei valori del tipo, cioè $2^N$. Si ottengono così $-75+2^8$, $-75+2^{16}$ e $-75+2^{32}$, tutti nell’intervallo del rispettivo tipo. Ogni risultato è la lettura senza segno della parola di $-75$ in complemento a due su $N$ bit. Su otto bit questa parola è $10110101$, cioè $(B5)_{16}$.

Le parole di sedici e di trentadue bit si ottengono per **estensione di segno**. Il bit più significativo di $10110101$ vale $1$, perciò si antepongono bit a $1$ e ogni quartina aggiunta è $1111$, cioè la cifra $F$. Le ultime due cifre esadecimali restano $B5$ in tutte e tre le righe. Gli argomenti di `%u` e di `%X` hanno tipo `unsigned int`, come richiedono i due specificatori.

</div>

## Esercizio 3

Il programma somma tre coppie di parole di otto bit. La funzione `signed_value` restituisce la lettura in complemento a due di una parola e la funzione `add_overflows` applica il criterio di overflow con segno. Scrivere l’output esatto. Si assumono `int` a $32$ bit e scrittura riuscita.

```c
#include <stdint.h>
#include <stdio.h>

static int signed_value(uint8_t word)
{
    return word >= 0x80u ? (int)word - 256 : (int)word;
}

static int add_overflows(uint8_t x, uint8_t y, uint8_t sum)
{
    int sx = x >= 0x80u;
    int sy = y >= 0x80u;
    int ss = sum >= 0x80u;

    return sx == sy && ss != sx;
}

int main(void)
{
    const uint8_t x[3] = {0x5Au, 0xA0u, 0x90u};
    const uint8_t y[3] = {0x3Cu, 0xF0u, 0x88u};

    for (int i = 0; i < 3; i++) {
        uint8_t sum = (uint8_t)(x[i] + y[i]);
        int carry = x[i] + y[i] > 0xFF;

        printf("%02X %4d %d %d\n", (unsigned)sum, signed_value(sum),
               carry, add_overflows(x[i], y[i], sum));
    }
    return 0;
}
```

```text
96 -106 0 1
90 -112 1 0
18   24 1 1
```

| Riga | Somma senza segno | Somma con segno | `sum` | `signed_value(sum)` |
| --- | --- | --- | --- | --- |
| $1$ | $90+60=150$ | $90+60=150$ | $(96)_{16}$ | $-106$ |
| $2$ | $160+240=400$ | $-96-16=-112$ | $(90)_{16}$ | $-112$ |
| $3$ | $144+136=280$ | $-112-120=-232$ | $(18)_{16}$ | $24$ |

<div class="spiegazione">

In `x[i] + y[i]` le due parole sono promosse a `int`, quindi la somma senza segno è esatta e il confronto con `0xFF` dà il riporto oltre l’ottava posizione. La conversione in `uint8_t` conserva il resto della somma modulo $256$. La funzione `signed_value` sottrae $256$ quando il bit più significativo vale $1$, come prevede la decodifica in **complemento a due**. Il bit più significativo vale $1$ esattamente quando la parola è almeno `0x80u`. Perciò `add_overflows` restituisce $1$ quando gli addendi hanno lo stesso bit di segno e la parola ottenuta ha il bit di segno opposto.

Nella prima riga gli addendi sono positivi e la somma $150$ supera il massimo $127$. La parola $(96)_{16}$ ha quindi bit di segno $1$ e si ha overflow senza riporto. Nella seconda riga gli addendi sono negativi e la somma $-112$ è rappresentabile, perciò c’è riporto senza overflow. Nella terza riga la somma $-232$ è minore di $-128$, quindi si verificano sia il riporto sia l’overflow. Lo specificatore `%4d` occupa almeno quattro caratteri, perciò davanti a `24` compaiono due spazi.

</div>
