## Esercizio 1

Scrivere le due dichiarazioni che il preprocessore produce dal frammento seguente, conservando l’ordine dei token.
```c
#define FACTOR 6
#define BASE 3
int result = FACTOR * BASE;
char label[] = "FACTOR";
```

```c
int result = 6 * 3;
char label[] = "FACTOR";
```

<div class="spiegazione">

`FACTOR` e `BASE` sono token distinti nell’inizializzatore di `result`, quindi ciascuno è sostituito dal numero associato. Il prodotto resta scritto come espressione. La sequenza `"FACTOR"` appartiene invece a un solo token di stringa, quindi rimane identica.

Come verifica si passa il frammento al driver GCC compatibile con `-E -P`. La prima opzione ferma la traduzione dopo la preelaborazione e la seconda omette i marcatori di riga. Le due dichiarazioni stampate coincidono con quelle calcolate.

</div>

## Esercizio 2

Ogni sorgente produce un solo oggetto, con lo stesso nome di base. Il sistema ricompila una volta ogni sorgente che dipende, direttamente o indirettamente, da un file cambiato. Si modificano soltanto `common.h` e `scale.h`. Stabilire quali file oggetto vanno ricostruiti. `app.h` include `common.h` e `scale.h`. `log.h` non include altri header del progetto.
| Sorgente | Inclusioni dirette |
|---|---|
| `main.c` | `app.h` |
| `metrics.c` | `common.h` e `scale.h` |
| `export.c` | `scale.h` |
| `log.c` | `log.h` |

| Header cambiato | Oggetti che ne dipendono |
|---|---|
| `common.h` | `main.o` e `metrics.o` |
| `scale.h` | `main.o`, `metrics.o` ed `export.o` |

L’insieme degli oggetti da ricostruire è `main.o`, `metrics.o` ed `export.o`.

<div class="spiegazione">

Si seguono le inclusioni in senso inverso dai file modificati ai sorgenti. `app.h` rende entrambe le modifiche rilevanti per `main.c`. `metrics.c` raggiunge entrambi gli header in un solo passo e `export.c` raggiunge soltanto `scale.h`. Un oggetto compare una volta nella ricostruzione anche quando più modifiche lo riguardano.

Per verificare si percorre la tabella a partire da ciascun sorgente. Espandendo `app.h`, `main.c` incontra entrambi i file cambiati. `metrics.c` e `export.c` incontrano almeno `scale.h`. Da `log.c` il percorso termina a `log.h`, quindi il suo oggetto rimane utilizzabile.

</div>

## Esercizio 3

Scrivere le due dichiarazioni prodotte dal preprocessore a partire dal frammento seguente e calcolare i valori di `area` e `mode`. Modificare poi una sola direttiva in modo che `area` valga il quadrato del valore $4$ espresso da `WIDTH`, e determinare il nuovo valore di `mode`.
```c
#define WIDTH 3 + 1
#define AREA WIDTH * WIDTH
#if AREA > 10
#define MODE 2
#else
#define MODE 1
#endif
int area = AREA;
int mode = MODE;
```

```c
int area = 3 + 1 * 3 + 1;
int mode = 1;
```

$$
\text{area}=3+1\cdot3+1=7 .
$$

Con la direttiva `#define WIDTH (3 + 1)` il preprocessore produce

```c
int area = (3 + 1) * (3 + 1);
int mode = 2;
```

e `area` vale $16$.

<div class="spiegazione">

La sostituzione di `AREA` produce i token `WIDTH * WIDTH`. Il preprocessore **riesamina** la sostituzione e vi trova altri due nomi di macro, quindi sostituisce anche ciascun `WIDTH` con i tre token `3 + 1`. La sostituzione opera sui token, indipendentemente dalle precedenze del C, perciò nell’espressione risultante la moltiplicazione ha come operandi soltanto i due `1` centrali. L’inizializzatore vale $3+3+1=7$.

La stessa espansione avviene nella condizione di `#if`, che diventa $3+1\cdot3+1>10$, cioè $7>10$. La condizione è falsa, quindi il ramo `#else` definisce `MODE` come `1`.

Le parentesi nella sostituzione di `WIDTH` fanno della somma un unico operando di ciascun fattore. Con la correzione l’inizializzatore vale $4\cdot4=16$ e la condizione di `#if` diventa $16>10$, che è vera. Il primo ramo assegna quindi a `MODE` la sostituzione `2`. Una sola direttiva modifica così entrambe le dichiarazioni, perché `#if` usa la stessa macro dell’inizializzatore. Il driver GCC con `-E -P` stampa esattamente le dichiarazioni scritte nei due casi.

</div>
