## Esercizio 1

Scrivere `clone_int` per ottenere una copia allocata dell’intero designato da `source`. L’argomento designa un intero leggibile e in corso di durata. La funzione restituisce il blocco al chiamante o `NULL` in caso di fallimento. Descrivere lo stato con `int x = 19;` come sorgente, se il chiamante scrive $31$ nella copia ottenuta e poi la rilascia.

```c
#include <stdlib.h>

int *clone_int(const int *source)
{
    int *copy = malloc(sizeof *copy);
    if (copy == NULL) {
        return NULL;
    }
    *copy = *source;
    return copy;
}
```

Con allocazione riuscita si ottiene un intero distinto che vale inizialmente $19$. Scrivere $31$ nella copia lascia `x` a $19$. Il rilascio della copia termina la sua durata e lascia in corso quella di `x`.

<div class="spiegazione">

La funzione riceve un accesso in lettura a `x`. Il puntatore restituito nasce da una nuova allocazione, perciò la funzione consegna al chiamante anche la responsabilità del nuovo blocco. L’assegnamento copia il valore dell’intero, quindi l’oggetto allocato può essere modificato indipendentemente dalla sorgente. Nel ramo nullo, la funzione non ha ottenuto un blocco da consegnare.

Per verificare la proprietà si conta il numero di blocchi nuovi a partire dalla chiamata. Dopo il successo si passa da zero a uno, mentre la scrittura di $31$ non cambia il conteggio. Il rilascio lo riporta a zero. L’oggetto automatico `x` appartiene a un’altra durata e resta invariato.

</div>

## Esercizio 2

Il chiamante inizializza `owner` con un puntatore non nullo restituito da `malloc` e `borrow = owner` con una copia dell’indirizzo. Entrambe sono variabili puntatore esterne al blocco. Determinare lo stato dopo due chiamate consecutive a `release_owned(&owner)`. Indicare se una terza fase può assegnare `NULL` a `borrow`.
```c
#include <stdlib.h>

void release_owned(int **slot)
{
    free(*slot);
    *slot = NULL;
}
```

La prima chiamata rilascia il blocco e scrive `NULL` in `owner`. La seconda esegue `free(NULL)` e mantiene `owner` nullo. Dopo il primo rilascio il valore di `borrow` è indeterminato. L’assegnamento diretto `borrow = NULL;` è definito.

<div class="spiegazione">

Il parametro `slot` punta alla variabile proprietaria, che continua a esistere fuori dal blocco. La funzione rilascia prima il blocco usando il valore detenuto in quella variabile. Poi scrive il valore nullo nella stessa variabile. La copia `borrow` non è destinazione di questa seconda operazione, quindi viene aggiornata solo dalla terza fase esplicita.

Come verifica si contano i rilasci effettivi. All’ingresso della prima chiamata esiste un solo blocco e il rilascio ne conclude la durata. All’ingresso della seconda il valore nell’argomento di `free` è nullo, quindi il conteggio rimane zero. Assegnare `NULL` a `borrow` scrive un nuovo valore senza consultare quello precedente.

</div>

## Esercizio 3

Trovare l’errore nella funzione `sum_copies`, che somma due interi passando per due copie allocate, e correggerlo. La funzione `clone_int` restituisce un blocco allocato con la copia dell’intero designato, oppure `NULL` se l’allocazione fallisce. Contare i blocchi in corso di durata al ritorno nei quattro casi possibili per le due allocazioni. Gli argomenti `a` e `b` designano interi leggibili, `out` designa un `int` modificabile e `<stdlib.h>` è incluso.

```c
int sum_copies(const int *a, const int *b, int *out)
{
    int *x = clone_int(a);
    int *y = clone_int(b);
    if (x == NULL || y == NULL) {
        return 0;
    }
    *out = *x + *y;
    free(x);
    free(y);
    return 1;
}
```

| Allocazione di `x` | Allocazione di `y` | Blocchi in corso di durata al ritorno |
|---|---|---:|
| riuscita | riuscita | 0 |
| fallita | riuscita | 1 (quello di `y`) |
| riuscita | fallita | 1 (quello di `x`) |
| fallita | fallita | 0 |

La correzione aggiunge i due rilasci nel ramo di errore.

```c
    if (x == NULL || y == NULL) {
        free(x);
        free(y);
        return 0;
    }
```

Con la correzione il conteggio vale $0$ in tutti e quattro i casi.

<div class="spiegazione">

Ogni chiamata riuscita a `clone_int` trasferisce a `sum_copies` la **proprietà** di un blocco, quindi la responsabilità del rilascio vale in ogni uscita della funzione. Nel percorso di successo i due `free` finali portano il conteggio a zero. Nel ramo di errore della prima versione la funzione ritorna senza rilasci, perciò il blocco dell’unica allocazione riuscita resta in corso di durata. Dopo il ritorno nessuna variabile ne conserva l’indirizzo, quindi il blocco non si può più rilasciare e costituisce una **perdita di memoria**.

La correzione rilascia entrambi i puntatori senza distinguere i due casi di fallimento. Questo è corretto perché `free(NULL)` non ha effetti, quindi la chiamata relativa all’allocazione fallita lascia invariato il conteggio. Il caso di due fallimenti dà zero anche nella prima versione, dato che la funzione non ha ottenuto alcun blocco. Il ramo di errore non scrive in `*out`, perciò il chiamante distingue i due esiti soltanto dal valore restituito.

</div>
