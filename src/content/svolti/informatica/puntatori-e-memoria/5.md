## Esercizio 1

Valutare `snap`, `*first` e il confronto `first == second` dopo le due chiamate. Le dichiarazioni al fondo sono nel corpo di una funzione e vengono eseguite prima di ogni altra chiamata a `tick`.
```c
const unsigned *tick(void)
{
    static unsigned cell = 1;
    cell += 2;
    return &cell;
}

/* Caller body */
const unsigned *first = tick();
unsigned snap = *first;
const unsigned *second = tick();
```

La prima chiamata porta `cell` a $1+2=3$ e `snap` memorizza $3$. La seconda chiamata porta lo stesso oggetto a $3+2=5$. Si ha `*first` uguale a $5$ e `first == second` vero.

<div class="spiegazione">

La dichiarazione `static` associa alla funzione un intero che dura per tutta l’esecuzione del programma. Il valore iniziale si fissa una volta sola. L’incremento della seconda chiamata riguarda quindi l’oggetto che esisteva già nella prima. La copia in `snap` conserva il valore letto al momento della prima chiamata ed è indipendente dal secondo incremento.

Come verifica si confrontano i due indirizzi restituiti e si calcola la differenza fra il valore osservato alla fine e la copia. Il confronto è vero perché entrambi gli indirizzi designano `cell`. La differenza $5-3=2$ coincide con il solo incremento avvenuto dopo la copia.

</div>

## Esercizio 2

Determinare `total` e indicare quale oggetto è designato da `view` alla fine del frammento. Classificare il comportamento della lettura finale nell’ipotesi che l’assegnamento `view = &outer;` dentro il blocco interno sia omesso. Il frammento è nel corpo di una funzione.
```c
int outer = 10;
const int *view = &outer;
int snapshot;
{
    int temporary = 21;
    view = &temporary;
    snapshot = *view;
    view = &outer;
}
int total = snapshot + *view;
```

`snapshot` vale $21$ e `view` torna a puntare a `outer` prima della fine del blocco interno. La somma è $21+10=31$. Se manca l’ultimo assegnamento a `view` nel blocco, la lettura finale attraverso quel puntatore ha comportamento indefinito.

<div class="spiegazione">

Durante la prima lettura l’oggetto `temporary` è in corso di durata, così il suo valore si può copiare nell’oggetto esterno `snapshot`. La copia resta disponibile dopo l’uscita dal blocco. La nuova assegnazione a `view` precede l’uscita e fa sì che l’ultima lettura riguardi l’intero `outer`. Nell’ipotesi alternativa la durata dell’oggetto cui si riferiva il puntatore è già terminata quando si tenta la seconda lettura.

Per verificare l’esecuzione proposta si controllano separatamente le due sorgenti della somma. Il numero $21$ viene da una copia già completata e il numero $10$ da un oggetto il cui blocco è ancora attivo. Le due durate giustificano entrambe le letture.

</div>

## Esercizio 3

Due versioni di una funzione restituiscono l’indirizzo di una coppia di interi. Il chiamante esegue le tre righe in fondo. Calcolare `sum` e il confronto `u == v` quando il chiamante usa `pair_static`, poi classificare il comportamento dello stesso chiamante quando al posto di `pair_static` usa `pair_auto`.

```c
int *pair_auto(int a, int b)
{
    int cell[2];
    cell[0] = a;
    cell[1] = b;
    return cell;
}

int *pair_static(int a, int b)
{
    static int cell[2];
    cell[0] = a;
    cell[1] = b;
    return cell;
}

/* Caller body */
int *u = pair_static(1, 2);
int *v = pair_static(5, 8);
int sum = u[0] + u[1] + v[0] + v[1];
```

Con `pair_static` il confronto `u == v` è vero e `sum` vale $5+8+5+8=26$. Con `pair_auto` la lettura di `u[0]` ha comportamento indefinito.

<div class="spiegazione">

Il vettore `cell` di `pair_static` ha **durata statica**, quindi esiste per tutta l’esecuzione e ogni chiamata restituisce l’indirizzo del suo primo elemento. Perciò `u` e `v` designano lo stesso vettore. La seconda chiamata sostituisce i valori $1$ e $2$ con $5$ e $8$, e la somma legge due volte la coppia più recente. La somma $1+2+5+8=16$ si otterrebbe soltanto con due oggetti distinti, per esempio due blocchi ottenuti con `malloc` e rilasciati dal chiamante.

Il vettore `cell` di `pair_auto` ha invece **durata automatica**, che termina al ritorno dalla funzione. Il valore del puntatore restituito è quindi indeterminato e ogni accesso attraverso `u` ha comportamento indefinito. `gcc` segnala il caso già in compilazione con l’avviso `function returns address of local variable`. Nell’istruzione `return cell;` il vettore decade a puntatore al primo elemento, e questa conversione lascia invariata la durata del vettore.

</div>
