## Esercizio 1

Un blocco con cinque interi inizializzati contiene $(3,12,7,20,9)$ nell’ordine. Assumere che `p` possieda il blocco, che `<stdlib.h>` sia incluso e che `realloc` riesca. Calcolare la somma degli interi del blocco risultante, prima del rilascio.
```c
int *next = realloc(p, 3 * sizeof *p);
```

Si conservano i primi tre interi. Il blocco risultante contiene $(3,12,7)$, quindi la somma è $3+12+7=22$.

<div class="spiegazione">

La richiesta riduce il numero di byte. La parte garantita coincide con il prefisso della dimensione nuova, perché è la minore delle due dimensioni. Il riferimento da usare per leggere e infine rilasciare il blocco è `next`. Gli elementi di indice $3$ e $4$ erano contenuti nel blocco precedente e non appartengono a quello risultante.

Per verificare la somma si aggregano i cinque valori originari, ottenendo $51$. Gli ultimi due contribuivano $20+9=29$. Togliendo quel contributo si ottiene $51-29=22$.

</div>

## Esercizio 2

Realizzare `grow_zeroed` con due parametri di uscita, il riferimento proprietario e la capacità. All’ingresso, `*slot` è `NULL` e `*capacity` vale zero, oppure il puntatore possiede un blocco di `*capacity` interi inizializzati. Le due variabili di uscita sono modificabili e sono esterne al blocco. Se la capacità è sufficiente, la funzione restituisce `true` senza cambiarla. Se la richiesta è troppo grande o fallisce, restituisce `false` lasciando invariato lo stato. Se cresce, conserva il prefisso e inizializza a zero i nuovi interi. Calcolare il blocco alla crescita riuscita da due a cinque elementi a partire da $(4,9)$ e il valore visto dopo aver ricostruito un riferimento all’elemento di indice $1$.

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdlib.h>

bool grow_zeroed(int **slot, size_t *capacity,
                 size_t need)
{
    size_t old = *capacity;
    if (need <= old) {
        return true;
    }
    if (need > SIZE_MAX / sizeof **slot) {
        return false;
    }

    int *next = realloc(*slot, need * sizeof *next);
    if (next == NULL) {
        return false;
    }
    for (size_t i = old; i < need; ++i) {
        next[i] = 0;
    }
    *slot = next;
    *capacity = need;
    return true;
}
```

Il risultato è $(4,9,0,0,0)$. Il riferimento ricostruito dall’indirizzo proprietario aggiornato più $1$ designa il valore $9$.

<div class="spiegazione">

Se occorre crescere, `need` è strettamente positivo. Il controllo sul limite garantisce la rappresentabilità della richiesta. Il risultato è mantenuto in `next`, così un eventuale fallimento lascia intatti il riferimento precedente e la capacità. Dopo il successo il ciclo scrive ciascun nuovo elemento una volta, partendo da `old`. Le due assegnazioni finali aggiornano il proprietario e la capacità del blocco ora disponibile.

Si verifica separatamente il prefisso conservato e il tratto aggiunto. Gli indici $0$ e $1$ mantengono $4$ e $9$ per la proprietà di `realloc`. Le tre posizioni da $2$ a $4$ sono esattamente gli indici scritti dal ciclo. L’indice $1$ era stato conservato come intero, quindi resta utilizzabile per calcolare un puntatore valido dal nuovo blocco.

</div>

## Esercizio 3

La funzione `push_back` aggiunge un intero in fondo a un vettore dinamico descritto da tre variabili del chiamante, cioè il riferimento proprietario, il numero di elementi e la capacità. Quando il vettore è pieno, la capacità raddoppia, partendo da $2$ se il vettore è vuoto. Con `data = NULL`, `size = 0` e `cap = 0` si chiama `push_back(&data, &size, &cap, v)` per $v$ uguale a $4$, $9$, $1$, $7$ e $3$, in quest’ordine, e ogni `realloc` riesce. Tracciare `size`, `cap` e le chiamate a `realloc`. Classificare poi una lettura finale di `head[0]`, se `head` ha ricevuto il valore di `data` subito dopo la seconda aggiunta.

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdlib.h>

bool push_back(int **data, size_t *size, size_t *cap, int value)
{
    if (*size == *cap) {
        if (*cap > SIZE_MAX / (2 * sizeof **data)) {
            return false;
        }
        size_t wanted = (*cap == 0) ? 2 : 2 * *cap;
        int *next = realloc(*data, wanted * sizeof *next);
        if (next == NULL) {
            return false;
        }
        *data = next;
        *cap = wanted;
    }
    (*data)[*size] = value;
    ++*size;
    return true;
}
```

| Valore aggiunto | Chiamata a `realloc` | `cap` dopo | `size` dopo |
|---:|---|---:|---:|
| 4 | sì, da $0$ a $2$ elementi | 2 | 1 |
| 9 | no | 2 | 2 |
| 1 | sì, da $2$ a $4$ elementi | 4 | 3 |
| 7 | no | 4 | 4 |
| 3 | sì, da $4$ a $8$ elementi | 8 | 5 |

Le chiamate a `realloc` sono tre e il blocco finale contiene $(4,9,1,7,3)$ con capacità $8$. La lettura di `head[0]` ha comportamento indefinito.

<div class="spiegazione">

Nella prima chiamata `*data` è nullo, quindi `realloc` si comporta come `malloc` e produce il primo blocco. Una nuova richiesta avviene solo quando `size` è uguale a `cap`, cioè alla prima, alla terza e alla quinta aggiunta. Il controllo su `*cap` precede il raddoppio, perciò il prodotto `wanted * sizeof *next` è rappresentabile in `size_t`. Il risultato di `realloc` passa per `next`, quindi un fallimento lascerebbe invariati il blocco e le due variabili del chiamante.

Il puntatore `head` è stato copiato quando il blocco aveva capacità $2$. La terza aggiunta ridimensiona quel blocco con successo, quindi la durata del blocco precedente termina e il valore di `head` diventa indeterminato, anche nel caso in cui il nuovo blocco occupi la stessa posizione. In una prova con `-fsanitize=address` la lettura è segnalata come `heap-use-after-free`. Un riferimento al primo elemento che resta valido si ottiene conservando l’indice $0$ e calcolando `data + 0` dopo l’ultima aggiunta.

</div>
