## Esercizio 1

La funzione `digits` deve restituire il numero di cifre decimali di `n`, per ogni valore di tipo `unsigned` a 32 bit, e lo zero si scrive con una cifra. Trovare il valore per cui il contratto non è rispettato, spiegarne la causa e correggere la funzione.
```c
unsigned digits(unsigned n)
{
    unsigned d = 0u;
    while (n > 0u) {
        n /= 10u;
        ++d;
    }
    return d;
}
```

| `n` | 0 | 7 | 10 | 4096 |
|---|---:|---:|---:|---:|
| Valore restituito | 0 | 1 | 2 | 4 |
| Valore richiesto | 1 | 1 | 2 | 4 |

```c
unsigned digits(unsigned n)
{
    unsigned d = 0u;
    do {
        n /= 10u;
        ++d;
    } while (n > 0u);
    return d;
}
```

Con la versione corretta `digits(0u)` vale `1` e `digits(4294967295u)` vale `10`.

<div class="spiegazione">

Per `n` positivo ogni divisione intera per `10` elimina l’ultima cifra decimale, e il ciclo si arresta quando non restano cifre. Il contatore `d` conta quindi le cifre di `n`. Per `n = 0` la guardia iniziale del `while` è falsa, perciò il corpo viene eseguito zero volte e la funzione restituisce `0`. La scrittura decimale di zero ha invece una cifra, quindi il contratto non è rispettato proprio sul valore al bordo del dominio.

Nel `do while` il corpo viene eseguito prima del controllo. Per `n = 0` la divisione dà `0`, `d` passa a `1` e la guardia finale è falsa, perciò si restituisce `1`. Per `n` positivo la prima guardia del `while` era vera, quindi le due versioni eseguono la stessa sequenza di divisioni e restituiscono lo stesso valore. Il valore di `n` è una variante del ciclo, perché per $n\geq 1$ vale $\left\lfloor\dfrac{n}{10}\right\rfloor<n$. Il ciclo termina perciò per ogni dato, compreso il massimo `4294967295`, che ha dieci cifre.

</div>


## Esercizio 2

La funzione `count_hits` deve restituire quanti interi `k` con $1\leq k\leq n$ hanno l’ultima cifra decimale compresa fra `3` e `5`, estremi inclusi, per $0\leq n\leq 10^6$. Con `n = 25` il valore atteso è `9`, mentre la funzione restituisce `25`. Trovare l’errore, spiegare il valore `25` e correggere la funzione.
```c
unsigned count_hits(unsigned n)
{
    unsigned hits = 0u;
    for (unsigned k = 1u; k <= n; ++k) {
        if (3u <= k % 10u <= 5u) {
            ++hits;
        }
    }
    return hits;
}
```

Compilando con `gcc -std=c11 -Wall -Wextra -pedantic` si ottiene, fra gli altri, l’avviso

```text
warning: comparisons like 'X<=Y<=Z' do not have their mathematical meaning [-Wparentheses]
```

```c
unsigned count_hits(unsigned n)
{
    unsigned hits = 0u;
    for (unsigned k = 1u; k <= n; ++k) {
        unsigned last = k % 10u;
        if (3u <= last && last <= 5u) {
            ++hits;
        }
    }
    return hits;
}
```

Con la versione corretta gli interi contati per `n = 25` sono `3`, `4`, `5`, `13`, `14`, `15`, `23`, `24` e `25`, quindi `count_hits(25u)` vale `9`.

<div class="spiegazione">

Gli operatori di confronto si associano da sinistra, perciò la guardia equivale a `(3u <= k % 10u) <= 5u`. Il primo confronto produce un `int` che vale `0` oppure `1`. Entrambi i valori sono minori di `5`, quindi la condizione è vera per ogni `k` e la funzione conta tutti gli interi da `1` a `n`. Per questo motivo `count_hits(25u)` restituisce `25`. Il compilatore segnala l’espressione con l’avviso riportato, che riguarda proprio i confronti concatenati.

Nella versione corretta l’ultima cifra viene salvata in `last` e le due disuguaglianze sono unite da `&&`. Se `last` è minore di `3`, il **corto circuito** salta il secondo confronto, e il risultato non cambia perché la congiunzione è comunque falsa. Su ogni decina completa la condizione è vera per tre valori di `k`. Le due decine da `1` a `20` danno quindi sei valori, e gli interi da `21` a `25` ne aggiungono tre. L’ipotesi $n\leq 10^6$ garantisce che `++k` non superi il massimo di `unsigned`, perciò la guardia `k <= n` diventa falsa dopo $n$ iterazioni.

</div>


## Esercizio 3

La funzione `sum_down` deve restituire la somma $n+(n-3)+(n-6)+\dots$ dei soli termini non negativi, per `unsigned` a 32 bit e $0\leq n\leq 10^5$, così che la somma sia rappresentabile. Con `n = 10` il valore atteso è $10+7+4+1=22$, ma la chiamata non termina. Spiegare perché e correggere la funzione.
```c
unsigned sum_down(unsigned n)
{
    unsigned s = 0u;
    for (unsigned i = n; i >= 0u; i -= 3u) {
        s += i;
    }
    return s;
}
```

```text
warning: comparison of unsigned expression in '>= 0' is always true [-Wtype-limits]
```

| Iterazione | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---:|---:|---:|---:|---:|---:|
| `i` | 10 | 7 | 4 | 1 | 4294967294 | 4294967291 |

```c
unsigned sum_down(unsigned n)
{
    unsigned i = n;
    unsigned s = i;
    while (i >= 3u) {
        i -= 3u;
        s += i;
    }
    return s;
}
```

Con la versione corretta `sum_down(10u)` vale `22`, `sum_down(9u)` vale `18`, `sum_down(2u)` vale `2` e `sum_down(0u)` vale `0`.

<div class="spiegazione">

Un valore di tipo `unsigned` non è mai negativo, quindi la guardia `i >= 0u` è vera in ogni stato. Il corpo non contiene un `break`, perciò il ciclo non può terminare. Dopo `i = 1` l’aggiornamento calcola `1u - 3u`. L’aritmetica degli interi senza segno è modulo $2^{32}$, quindi il risultato è $2^{32}-2=4294967294$, senza comportamento indefinito. Da quel valore le sottrazioni proseguono per sempre. Il compilatore segnala la guardia con l’avviso `-Wtype-limits`, attivato da `-Wextra`.

Nella versione corretta il primo termine entra nella somma prima del ciclo, e la guardia `i >= 3u` permette la sottrazione solo quando il risultato è non negativo. Il valore di `i` è allora una **variante**, perché resta non negativo e diminuisce di `3` a ogni iterazione, quindi il ciclo termina. Per $n\leq 2$ la guardia è subito falsa e la funzione restituisce `n`, l’unico termine non negativo. Per `n = 10` le sottrazioni producono `7`, `4` e `1`, e la guardia su `1` è falsa, perciò la somma vale `22`. Il caso più grande ammesso, $n=10^5$, dà $1666716667$, che è minore di $2^{32}$.

</div>
