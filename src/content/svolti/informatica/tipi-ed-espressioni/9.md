## Esercizio 1

Il programma deve stampare la media di `sum` e `count` con due cifre frazionarie, cioè `4.25`. Trovare i due errori, classificarli e scrivere il programma corretto. Si assumono una realizzazione conforme all’allegato F di C17 in arrotondamento al più vicino, il locale numerico C e scrittura riuscita.
```c
#include <stdio.h>

int main(void)
{
    int sum = 17;
    int count = 4;
    double mean = sum / count;
    printf("%d\n", mean);
    return 0;
}
```

GCC con `-Wall` segnala l’ottava riga con il messaggio seguente.

```text
warning: format '%d' expects argument of type 'int', but argument 2 has type 'double' [-Wformat=]
```

Nel programma corretto cambiano due righe.

```c
    double mean = (double)sum / count;
    printf("%.2f\n", mean);
```

L’output del programma corretto è `4.25`, seguito dal fine riga.

<div class="spiegazione">

Nella settima riga entrambi gli operandi di `/` sono `int`, quindi la divisione dà il quoziente troncato $4$. L’inizializzazione converte poi $4$ in `double`, perciò `mean` vale $4{,}0$. Il comportamento di questa riga è definito e il valore calcolato è diverso da quello richiesto dalla specifica.

Nell’ottava riga `%d` richiede un argomento di tipo `int` e `mean` è un `double`. Una specifica di conversione con tipo incompatibile con l’argomento produce **comportamento indefinito**, quindi nessuna uscita è garantita. L’avviso del compilatore indica proprio questa incompatibilità.

Nella correzione il cast converte `sum` prima della divisione e le conversioni aritmetiche usuali portano anche `count` a `double`. Il rapporto $\dfrac{17}{4}=4{,}25$ ha denominatore potenza di due ed è rappresentato esattamente. La specifica `%.2f` corrisponde a un `double` e scrive due cifre frazionarie, perciò l’output è `4.25`.

</div>

## Esercizio 2

Il programma deve leggere un prezzo unitario reale e una quantità intera e stampare il prodotto con una cifra frazionaria. Trovare gli errori, scrivere la versione corretta e indicarne l’output con l’ingresso `2.5 4` e con l’ingresso `2.5 x`. Si assumono una realizzazione conforme all’allegato F di C17 in arrotondamento al più vicino, il locale numerico C e ingresso-uscita riuscito.
```c
#include <stdio.h>

int main(void)
{
    double rate;
    int count;
    scanf("%f %d", &rate, count);
    printf("%.1f\n", rate * count);
    return 0;
}
```

Il corpo corretto è il seguente.

```c
    double rate = 0.0;
    int count = 0;
    int read = scanf("%lf %d", &rate, &count);
    printf("%d %.1f\n", read, rate * count);
```

| Ingresso | Output |
|---|---|
| `2.5 4` | `2 10.0` |
| `2.5 x` | `1 0.0` |

<div class="spiegazione">

In `scanf` la specifica `%f` richiede un puntatore a `float` e `&rate` punta a un `double`, per il quale la specifica è `%lf`. Il terzo argomento è `count`, cioè il valore di un oggetto non inizializzato, mentre `%d` richiede l’indirizzo di un `int`. Entrambe le incompatibilità producono **comportamento indefinito**. GCC con `-Wall` le segnala come avvisi di formato e segnala anche l’uso di `count` non inizializzato.

Il programma originale usa inoltre `rate` e `count` senza conservare l’esito della lettura, quindi dopo una lettura parziale il prodotto usa un valore indeterminato. Nella versione corretta i due oggetti partono da zero e `read` conserva il valore restituito da `scanf`.

Con l’ingresso `2.5 4` le due conversioni riescono, quindi `read` vale $2$ e il prodotto $2{,}5\cdot4=10$ si scrive `10.0`. Con l’ingresso `2.5 x` la seconda conversione si arresta sulla lettera `x`. Allora `read` vale $1$ e `count` conserva $0$, perciò l’output è `1 0.0`.

</div>

## Esercizio 3

Il programma converte in millisecondi una durata di `hours` ore e deve stampare `2160000000` per $600$ ore. Trovare l’errore, classificarlo e correggerlo. Si assume `int` a $32$ bit, quindi `INT_MAX` vale $2147483647$.
```c
#include <stdio.h>

int main(void)
{
    int hours = 600;
    long long ms = hours * 3600 * 1000;
    printf("%lld\n", ms);
    return 0;
}
```

$$
\begin{aligned}
600\cdot 3600 &= 2160000,\\[6pt]
2160000\cdot 1000 &= 2160000000>2147483647 .
\end{aligned}
$$

Nel programma corretto cambia la sesta riga.

```c
    long long ms = hours * 3600LL * 1000;
```

L’output del programma corretto è `2160000000`.

<div class="spiegazione">

Il tipo di `ms` interviene soltanto nella conversione di destinazione, dopo il calcolo dell’espressione a destra. L’espressione si raggruppa come `(hours * 3600) * 1000` e tutti gli operandi sono `int`, quindi entrambe le moltiplicazioni si svolgono in `int`. Il primo prodotto $2160000$ è rappresentabile. Il secondo ha risultato matematico $2160000000$, maggiore di `INT_MAX`, perciò l’operazione ha **comportamento indefinito**. Compilato con `-fsanitize=undefined`, il programma segnala in esecuzione «signed integer overflow» e stampa un numero negativo.

Nella correzione la costante `3600LL` ha tipo `long long`. Nel primo prodotto le conversioni aritmetiche portano `hours` a `long long`, il tipo di rango maggiore, e il risultato è un `long long`. Per lo stesso motivo anche la moltiplicazione per `1000` si svolge in `long long`. Poiché `LLONG_MAX` è almeno $9223372036854775807$, il prodotto è rappresentabile. La specifica di `printf` per un `long long` è `%lld`.

Il suffisso sul primo fattore rende `long long` entrambi i prodotti. Con `hours * 3600 * 1000LL` il primo prodotto resterebbe in `int`, rappresentabile per $600$ ore e fuori intervallo per `hours` maggiore di $596523$.

</div>
