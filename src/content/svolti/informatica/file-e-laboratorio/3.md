## Esercizio 1

Si elaborano tre righe restituite da `fgets`. Una quarta chiamata restituisce `NULL`. Subito dopo, `ferror(file)` dà un valore diverso da zero. Determinare quante righe sono state elaborate e se si può certificare la completezza dell’ingresso.

Il programma ha elaborato $3$ righe. L’ingresso è stato interrotto da un errore.

<div class="spiegazione">

L’esito nullo della quarta chiamata impedisce di trattarla come una riga letta. Il valore di `ferror` indica un problema sullo stream. Il conteggio rimane quindi quello del prefisso elaborato e l’errore impedisce di concludere che il prefisso sia tutto il file. Come verifica del ragionamento, un ingresso con altre righe dopo il punto dell’errore produrrebbe proprio lo stesso prefisso. Il risultato osservato non dà informazioni su quelle eventuali righe.

</div>

## Esercizio 2

Un file contiene una sola riga con `65` e un separatore. La prima `fgets` ha successo, il tentativo successivo raggiunge la fine senza errori. Contare gli aggiornamenti se un ciclo somma soltanto dopo una lettura riuscita e determinare la somma.

Il numero di aggiornamenti è $1$. La somma passa da $0$ a $65$.

<div class="spiegazione">

Il ciclo esegue l’accumulazione soltanto se `fgets` fornisce la stringa, quindi aggiorna dopo la prima chiamata. Quando `fgets` raggiunge la fine restituisce un puntatore nullo e il corpo non viene eseguito. La vecchia stringa non entra una seconda volta nel calcolo. Come verifica, il prefisso di letture riuscite contiene una sola misura. La somma diretta di quel prefisso è $65$, coerente con l’accumulatore.

</div>

## Esercizio 3

La funzione seguente classifica i frammenti letti da `fgets` in righe complete, frammenti di righe troppo lunghe e ultima riga priva di ritorno a capo. Le letture avvengono senza errori. Determinare i tre contatori per i file con contenuto `31\n4`, `123456789\n` e `1234567`, e indicare quale classificazione è sbagliata.

```c
static void classify(FILE *file, size_t *complete, size_t *partial, size_t *last)
{
    char line[8];
    *complete = *partial = *last = 0;
    while (fgets(line, sizeof line, file) != NULL) {
        if (strchr(line, '\n') != NULL) {
            ++*complete;
        } else if (feof(file)) {
            ++*last;
        } else {
            ++*partial;
        }
    }
}
```

| Contenuto del file | `complete` | `partial` | `last` |
|---|---:|---:|---:|
| `31\n4` | $1$ | $0$ | $1$ |
| `123456789\n` | $1$ | $1$ | $0$ |
| `1234567` | $0$ | $1$ | $0$ |

Il terzo file contiene un’unica riga priva di ritorno a capo, che la funzione conta come frammento di una riga lunga.

<div class="spiegazione">

L’indicatore di fine file si accende soltanto quando una lettura tenta di andare oltre l’ultimo carattere. Nel primo file la seconda `fgets` legge `4` e cerca un altro carattere, quindi incontra la fine e accende l’indicatore. Perciò `feof` restituisce un valore diverso da zero e il frammento va in `last`. Nel secondo file la prima `fgets` si ferma dopo sette cifre per il limite di capacità, senza raggiungere la fine. Il frammento `"1234567"` è allora contato in `partial`, mentre la lettura successiva `"89\n"` è una riga completa. Nel terzo file le sette cifre riempiono esattamente lo spazio disponibile. Anche qui `fgets` si ferma per la capacità e non tenta un’ottava lettura, quindi l’indicatore resta spento e la riga finale finisce in `partial`. La chiamata seguente restituisce `NULL` per fine del file e il ciclo termina. Il caso limite è quindi una riga finale priva di separatore con esattamente `sizeof line - 1` caratteri, cioè $7$. Il frammento usa `<stdio.h>`, `<stddef.h>` e `<string.h>`.

</div>
