## Esercizio 1

Il file `misure.txt` contiene le righe `4` e `9`, ciascuna chiusa da un ritorno a capo. Il frammento seguente, interno a `main`, dovrebbe stampare il numero di righe e la somma delle misure. Lo stream `file` è aperto in lettura su `misure.txt` e le letture avvengono senza errori. Determinare l’output, individuare l’errore e scrivere il ciclo corretto.

```c
char line[32];
long sum = 0;
int rows = 0;
while (!feof(file)) {
    fgets(line, sizeof line, file);
    sum += strtol(line, NULL, 10);
    ++rows;
}
printf("%d %ld\n", rows, sum);
```

```text
3 22
```

Il ciclo corretto usa come guardia l’esito della lettura.

```c
while (fgets(line, sizeof line, file) != NULL) {
    sum += strtol(line, NULL, 10);
    ++rows;
}
if (ferror(file)) {
    return EXIT_FAILURE;
}
printf("%d %ld\n", rows, sum);
```

Con il ciclo corretto l’output è `2 13`.

<div class="spiegazione">

La guardia `!feof(file)` descrive lo stato dello stream prima della lettura. Dopo la seconda `fgets` lo stream ha consumato `9` e il ritorno a capo, ma nessuna lettura ha ancora tentato di superare la fine. L’indicatore di fine file è quindi spento e il corpo viene eseguito una terza volta. La terza `fgets` incontra subito la fine del file e restituisce `NULL`. Per il contratto di `fgets`, quando la fine arriva prima di qualsiasi carattere il contenuto dell’array resta invariato, perciò `line` contiene ancora `"9\n"`. La somma riceve una seconda volta $9$ e `rows` arriva a $3$, da cui l’output `3 22`. Nel ciclo corretto il corpo si esegue soltanto dopo una lettura riuscita, quindi ogni riga entra nella somma una sola volta. Dopo il ciclo `ferror` distingue la fine normale del file da una lettura interrotta da un errore, e nel secondo caso `main` restituisce `EXIT_FAILURE` senza stampare. Il frammento usa `<stdio.h>` e `<stdlib.h>`.

</div>

## Esercizio 2

La funzione seguente dovrebbe stampare il numero di righe e la somma delle misure. Lo stream `file` è aperto in lettura su un file con le righe `6`, `10` e `8`, ciascuna chiusa da un ritorno a capo, e le letture avvengono senza errori. Determinare l’output, spiegare l’errore e correggerlo senza riaprire il file.

```c
static int print_rows_and_sum(FILE *file)
{
    char line[32];
    long rows = 0, sum = 0;
    while (fgets(line, sizeof line, file) != NULL) {
        ++rows;
    }
    while (fgets(line, sizeof line, file) != NULL) {
        sum += strtol(line, NULL, 10);
    }
    if (ferror(file)) {
        return 0;
    }
    return printf("%ld %ld\n", rows, sum) >= 0;
}
```

```text
3 0
```

La correzione inserisce fra i due cicli il controllo seguente.

```c
if (ferror(file) || fseek(file, 0L, SEEK_SET) != 0) {
    return 0;
}
```

Con la correzione l’output è `3 24`.

<div class="spiegazione">

La posizione fa parte dello stato dello stream. Il primo ciclo termina quando `fgets` restituisce `NULL` per fine del file, perciò la posizione si trova alla fine e l’indicatore di fine file è acceso. Il secondo ciclo parte da quella posizione, quindi la sua prima chiamata restituisce subito `NULL` e il corpo non si esegue mai. L’output è `3 0`, con il numero di righe esatto e la somma nulla. La correzione riporta lo stream all’inizio con `fseek(file, 0L, SEEK_SET)`, che in caso di successo restituisce zero e azzera l’indicatore di fine file. Il controllo di `ferror` posto prima del riposizionamento esclude il secondo passaggio quando il primo è stato interrotto da un errore. Con la correzione il secondo ciclo legge di nuovo le tre righe, e l’output è `3 24` perché $6+10+8=24$. Lo stesso risultato si ottiene con un solo ciclo che aggiorna `rows` e `sum` a ogni riga letta.

</div>

## Esercizio 3

La funzione seguente dovrebbe contare le righe di un file. Si assume che i puntatori occupino $8$ byte, che le letture riescano e che il file contenga le righe `temperatura` e `21`, ciascuna chiusa da un ritorno a capo. La funzione è chiamata passando un array `char buffer[64]`. Determinare il valore restituito, spiegare l’avviso del compilatore e correggere i due errori.

```c
static size_t count_lines(FILE *file, char line[64])
{
    size_t lines = 0;
    while (fgets(line, sizeof line, file) != NULL) {
        ++lines;
    }
    return lines;
}
```

```text
warning: 'sizeof' on array function parameter 'line' will return size of 'char *' [-Wsizeof-array-argument]
```

La funzione restituisce $3$. La versione corretta riceve la capacità e conta i ritorni a capo.

```c
static int count_lines(FILE *file, char *line, int capacity, size_t *lines)
{
    *lines = 0;
    while (fgets(line, capacity, file) != NULL) {
        if (strchr(line, '\n') != NULL) {
            ++*lines;
        }
    }
    return ferror(file) == 0;
}
```

Con la chiamata `count_lines(file, buffer, (int)sizeof buffer, &n)` si ottiene `n` uguale a $2$ e valore restituito $1$.

<div class="spiegazione">

Un parametro dichiarato come `char line[64]` ha tipo `char *`, perché per la regola di aggiustamento dei parametri il tipo array diventa il tipo puntatore all’elemento. Nel corpo `sizeof line` vale quindi $8$, la dimensione del puntatore, e la lunghezza $64$ scritta nella dichiarazione non ha effetto. Con capacità $8$ ogni `fgets` legge al più sette caratteri. La riga `temperatura` ha undici lettere, perciò produce i frammenti `"tempera"` e `"tura\n"`, seguiti da `"21\n"`. La funzione conta le chiamate riuscite e restituisce $3$. Il secondo errore è proprio questo conteggio, perché una riga fisica può produrre più frammenti. La versione corretta riceve la capacità come parametro e incrementa il contatore solo per un frammento che contiene il ritorno a capo, cioè per la fine di una riga. L’espressione `(int)sizeof buffer` è valutata dove `buffer` è ancora un array, quindi vale $64$. Il conteggio dei separatori dà $2$ anche con capacità $8$, perciò il risultato non dipende più dalla capacità quando ogni riga termina con un ritorno a capo. Il frammento usa `<stdio.h>`, `<stddef.h>` e `<string.h>`.

</div>
