## Esercizio 1

Scrivere una funzione che verifica la precondizione della ricerca dicotomica. Le posizioni da `0` a `n - 1` di `a` sono leggibili quando `n` è positivo; la funzione restituisce `1` se $a_i\leq a_{i+1}$ per ogni coppia adiacente e `0` altrimenti. Contare i confronti fra elementi sul vettore vuoto e sui vettori $(5)$, $(1,3,3,8)$ e $(1,3,2,8)$.
```c
int is_nondecreasing(const int a[], size_t n);
```

```c
int is_nondecreasing(const int a[], size_t n)
{
    for (size_t i = 1; i < n; ++i) {
        if (a[i - 1] > a[i]) {
            return 0;
        }
    }
    return 1;
}
```

| Vettore | `n` | Valore restituito | Confronti |
|---|---:|---:|---:|
| vuoto | 0 | 1 | 0 |
| $(5)$ | 1 | 1 | 0 |
| $(1,3,3,8)$ | 4 | 1 | 3 |
| $(1,3,2,8)$ | 4 | 0 | 2 |

<div class="spiegazione">

Un vettore è non decrescente quando nessuna coppia adiacente ha il primo elemento strettamente maggiore del secondo. La funzione cerca quindi una coppia che violi la condizione e restituisce `0` alla prima che trova. Se il ciclo termina, il test è risultato falso su tutte le $n-1$ coppie, perciò il valore `1` rispetta il contratto. Con $n=0$ e $n=1$ non esistono coppie adiacenti, e infatti la guardia `i < n` è falsa già all’inizio e nessun elemento viene letto. Sul quarto vettore il secondo confronto trova $3>2$ e la funzione termina con `0`.

L’indice parte da `1` e il confronto usa `a[i - 1]`, quindi la sottrazione si calcola solo quando `i` vale almeno $1$.

La guardia `i < n - 1` con `i` che parte da zero ha invece un difetto nel caso vuoto. Con $n=0$ l’espressione `n - 1` vale `SIZE_MAX` fra interi senza segno, quindi la guardia è vera e la funzione legge `a[0]` e `a[1]`, posizioni che il contratto non garantisce. Quelle letture hanno **comportamento non definito**.

</div>

## Esercizio 2

Su un vettore non decrescente di `n` elementi, scrivere una funzione che conta le occorrenze di `key` con due ricerche dicotomiche, usando anche la `lower_bound` della teoria. Calcolare il risultato e il numero di confronti fra chiavi sul vettore $(1,3,4,4,4,7,9)$ per le chiavi $4$, $5$, $0$ e $9$.
```c
size_t count_equal(const int a[], size_t n, int key);
```

```c
size_t upper_bound(const int a[], size_t n, int key)
{
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] <= key) {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    return lo;
}

size_t count_equal(const int a[], size_t n, int key)
{
    return upper_bound(a, n, key) - lower_bound(a, n, key);
}
```

| Chiave | `lower_bound` | `upper_bound` | Occorrenze | Confronti |
|---:|---:|---:|---:|---:|
| 4 | 2 | 5 | 3 | 6 |
| 5 | 5 | 5 | 0 | 6 |
| 0 | 0 | 0 | 0 | 6 |
| 9 | 6 | 7 | 1 | 6 |

<div class="spiegazione">

La funzione `upper_bound` differisce dalla `lower_bound` per il solo test `<=`. Con lo stesso invariante, gli indici di $[0,\mathrm{lo})$ hanno elementi minori o uguali alla chiave e quelli di $[\mathrm{hi},n)$ hanno elementi maggiori. Il risultato è quindi il primo indice con elemento strettamente maggiore della chiave. Poiché il vettore è ordinato, gli elementi uguali a `key` occupano le posizioni da `lower_bound` incluso a `upper_bound` escluso. La differenza dei due confini è perciò il **numero di occorrenze**, e vale zero quando i confini coincidono, come per le chiavi $5$ e $0$. La sottrazione fra `size_t` non scende sotto zero, perché ogni elemento minore della chiave è anche minore o uguale, quindi `upper_bound` non è mai minore di `lower_bound`.

Con $n=7$ il tratto passa a lunghezza $3$ in entrambi i rami, poi a $1$ e a $0$, quindi ciascuna ricerca esegue esattamente $3$ confronti. Il totale è $6$ per ogni chiave, contro i $7$ confronti di una scansione completa. In generale il costo è al più $2\left(1+\lfloor\log_2 n\rfloor\right)$, cioè $O(\log n)$.

</div>

## Esercizio 3

Scrivere una funzione che inserisce `key` in un vettore non decrescente di `n` elementi con capacità `cap`, dove `n <= cap` e le posizioni da `0` a `cap - 1` sono scrivibili. Se `n < cap`, la funzione colloca la chiave dopo gli elementi uguali, mantiene l’ordine e restituisce `n + 1`. Se `n == cap`, lascia il vettore invariato e restituisce `n`. Si può usare la funzione `upper_bound`, che restituisce il primo indice con elemento maggiore della chiave. Dare l’output del programma di prova.
```c
size_t insert_sorted(int a[], size_t n, size_t cap, int key);

int main(void)
{
    int a[7] = {2, 5, 5, 9};
    size_t n = 4;
    const int keys[] = {5, 1, 10, 7};
    for (size_t k = 0; k < 4; ++k) {
        n = insert_sorted(a, n, 7, keys[k]);
        for (size_t i = 0; i < n; ++i) {
            printf("%d ", a[i]);
        }
        printf("| n = %zu\n", n);
    }
    return 0;
}
```

```c
size_t insert_sorted(int a[], size_t n, size_t cap, int key)
{
    if (n >= cap) {
        return n;
    }
    size_t p = upper_bound(a, n, key);
    for (size_t k = n; k > p; --k) {
        a[k] = a[k - 1];
    }
    a[p] = key;
    return n + 1;
}
```

```text
2 5 5 5 9 | n = 5
1 2 5 5 5 9 | n = 6
1 2 5 5 5 9 10 | n = 7
1 2 5 5 5 9 10 | n = 7
```

<div class="spiegazione">

Sia `p` il valore di `upper_bound`. Gli elementi di $[0,p)$ sono minori o uguali a `key` e quelli di $[p,n)$ sono maggiori, quindi la chiave scritta in posizione `p` conserva l’ordine. Poiché `p` segue tutte le copie uguali, l’inserimento è **stabile** come quello dell’insertion sort, e infatti il primo $5$ inserito occupa l’indice $3$, dopo i due $5$ già presenti.

Il ciclo parte dall’ultimo elemento e sposta di una posizione verso destra gli elementi da `n - 1` fino a `p`, perciò ogni elemento viene copiato prima che la sua posizione venga sovrascritta. Gli spostamenti sono $n-p$, cioè uno per la chiave $5$, cinque per la chiave $1$ e nessuno per la chiave $10$, che va in fondo. La guardia `k > p` garantisce che `k` valga almeno $1$, quindi `a[k - 1]` non usa mai l’indice `SIZE_MAX`. La scrittura in `a[n]` rispetta il contratto, perché il controllo iniziale assicura `n < cap`. Alla quarta chiamata `n` vale $7$, uguale alla capacità, e la chiave $7$ non viene inserita.

</div>
