## Esercizio 1

Tracciare i valori di `scale` conservati nei record di `odd_product(3)` e calcolare il valore restituito. Si assume $0\leq n\leq5$.

```c
unsigned odd_product(unsigned n)
{
    if (n == 0u) {
        return 1u;
    }
    unsigned scale = 2u * n + 1u;
    unsigned child = odd_product(n - 1u);
    return scale * child;
}
```

| Argomento | `scale` | Valore restituito |
|---:|---:|---:|
| $3$ | $7$ | $105$ |
| $2$ | $5$ | $15$ |
| $1$ | $3$ | $3$ |
| $0$ | assente dal calcolo | $1$ |

<div class="spiegazione">

Nel record iniziale `scale` vale $7$. La chiamata interna esegue lo stesso corpo su $2$ e crea un valore distinto $5$. Un terzo record usa $3$. Quando la base restituisce $1$, la prima moltiplicazione in risalita è $3\cdot1$. Il suo risultato diventa `child` nel record successivo e viene moltiplicato per $5$. L’ultima moltiplicazione usa il $7$ conservato dal chiamante iniziale.

Il prodotto diretto $3\cdot5\cdot7=105$ conferma il valore. Il massimo del dominio è $10395$, ottenuto aggiungendo i fattori $9$ e $11$, quindi il calcolo è rappresentabile in `unsigned`.

</div>

## Esercizio 2

Determinare le coppie di parametri attive nella discesa per `add_even(3, 4)` e il risultato. Si consideri un dominio con $0\leq n\leq6$ e $d+n(n+1)\leq65535$, dove $d$ è il valore di `done`.

```c
unsigned add_even(unsigned n, unsigned done)
{
    if (n == 0u) {
        return done;
    }
    return add_even(n - 1u, done + 2u * n);
}
```

$$
(3,4)\longrightarrow(2,10)\longrightarrow(1,14)
\longrightarrow(0,16).
$$

Il risultato è $16$.

<div class="spiegazione">

Ogni chiamata forma il nuovo `done` prima di entrare nel record successivo. Al primo passo si aggiunge $2\cdot3=6$, perciò il valore passato è $10$. I passi seguenti aggiungono $4$ e $2$. Quando `n` vale zero, l’accumulatore contiene già il risultato. Il dominio è preservato perché il termine aggiunto è la differenza fra $n(n+1)$ e $(n-1)n$.

Come verifica, la somma iniziale $4$ più il totale dei contributi pari dà $4+6+4+2=16$. I ritorni propagano lo stesso valore poiché nessuna operazione resta sospesa.

</div>

## Esercizio 3

Per `layer(3)`, nel dominio $0\leq n\leq10$, ricostruire in ogni record i valori di `before`, di `got` e del parametro `n` dopo l’assegnamento, poi calcolare il risultato. Stabilire se l’assegnamento a `n` eseguito in un’invocazione interna modifica il parametro del chiamante.

```c
unsigned layer(unsigned n)
{
    if (n == 0u) {
        return 0u;
    }
    unsigned before = n * 10u;
    unsigned got = layer(n - 1u);
    n = n + got;
    return before + n;
}
```

| Argomento | `before` | `got` | `n` dopo l’assegnamento | Valore restituito |
|---:|---:|---:|---:|---:|
| $3$ | $30$ | $33$ | $36$ | $66$ |
| $2$ | $20$ | $11$ | $13$ | $33$ |
| $1$ | $10$ | $0$ | $1$ | $11$ |
| $0$ | assente | assente | $0$ | $0$ |

Ogni assegnamento a `n` modifica soltanto il parametro del proprio record. La chiamata `layer(3)` restituisce $66$.

<div class="spiegazione">

In C gli argomenti si passano **per valore**. Perciò il parametro `n` di ogni invocazione è un oggetto automatico distinto, inizializzato con una copia dell’argomento. Il valore di `before` è calcolato prima della chiamata e resta nel record per tutta la durata della chiamata interna.

Il record con argomento $1$ riceve $0$ dalla base, assegna a `n` il valore $1+0=1$ e restituisce $10+1=11$. Quando il controllo torna al record con argomento $2$, il suo `n` vale ancora $2$, perché l’assegnamento appena eseguito riguardava un altro oggetto. Questo record calcola quindi $2+11=13$ e restituisce $20+13=33$. Allo stesso modo il record iniziale porta il proprio `n` da $3$ a $3+33=36$ e restituisce $30+36=66$.

Come controllo, ogni record restituisce $10n+n$ più il risultato interno, quindi `layer(n)` vale $11\cdot\dfrac{n(n+1)}{2}$. Per $n=3$ si ottiene $11\cdot6=66$. Il valore massimo del dominio è $11\cdot55=605$, perciò tutti i calcoli sono rappresentabili in `unsigned`.

</div>
