## Esercizio 1

Il vettore `a` contiene $-2$, $4$, $0$, $7$, $-1$. Trovare tutti i risultati intermedi e il valore finale di `count_positive(a, 5)`.
```c
#include <stddef.h>

size_t count_positive(const int a[], size_t n)
{
    if (n == 0) {
        return 0;
    }
    return count_positive(a, n - 1) + (a[n - 1] > 0);
}
```

| Lunghezza del prefisso | Positivi |
|---:|---:|
| $0$ | $0$ |
| $1$ | $0$ |
| $2$ | $1$ |
| $3$ | $1$ |
| $4$ | $2$ |
| $5$ | $2$ |

<div class="spiegazione">

Il caso vuoto restituisce zero e precede qualunque accesso. Con un prefisso positivo si aggiunge il risultato del confronto sulla posizione $n-1$. Il confronto vale uno solo per un elemento strettamente positivo. Il conteggio sale quando il prefisso raggiunge $4$ e quando raggiunge $7$. Nei tre altri passi resta uguale. La conversione del risultato del confronto a `size_t` conserva zero o uno, quindi tutte le somme fino a cinque sono rappresentabili.

Una scansione diretta individua i soli positivi negli indici $1$ e $3$. Il numero di quei due indici conferma il risultato.

</div>

## Esercizio 2

Calcolare il risultato di `nondecreasing(a, 5)` per il vettore $(-3,1,1,0,2)$. Individuare il primo prefisso che restituisce zero e spiegare se si valuta il confronto tra le ultime due posizioni.
```c
#include <stddef.h>

int nondecreasing(const int a[], size_t n)
{
    if (n < 2) {
        return 1;
    }
    return nondecreasing(a, n - 1) && (a[n - 2] <= a[n - 1]);
}
```

I prefissi di lunghezza uno, due e tre restituiscono $1$. Quello di lunghezza quattro e quello di lunghezza cinque restituiscono $0$. Il confronto fra $0$ e $2$ non viene valutato.

<div class="spiegazione">

La proprietà vale per un prefisso con un elemento perché manca una coppia adiacente da ordinare. I confronti $-3\leq1$ e $1\leq1$ conservano il valore vero nei due prefissi successivi. Nel prefisso di lunghezza quattro il confronto è $1\leq0$ e risulta falso. Nella chiamata iniziale il primo operando di `&&` riceve quindi zero e l’operatore termina la valutazione con zero.

Come verifica del risultato complessivo, la coppia in posizioni $2$ e $3$ costituisce già una violazione dell’ordine non decrescente. Questo controesempio resta nel vettore anche se l’ultima coppia è in ordine.

</div>

## Esercizio 3

La funzione seguente deve contare le coppie di posizioni adiacenti con valori uguali nel prefisso di lunghezza $n$ del vettore `a`, accessibile nelle posizioni da $0$ a $n-1$, con $0\leq n\leq6$. Individuare l’errore, correggere il caso base e calcolare tutti i risultati intermedi per il vettore $(3,3,5,5,5,1)$.
```c
#include <stddef.h>

size_t equal_pairs(const int a[], size_t n)
{
    if (n == 0) {
        return 0;
    }
    return equal_pairs(a, n - 1) + (a[n - 2] == a[n - 1]);
}
```

La versione corretta cambia soltanto il caso base.

```c
#include <stddef.h>

size_t equal_pairs(const int a[], size_t n)
{
    if (n < 2) {
        return 0;
    }
    return equal_pairs(a, n - 1) + (a[n - 2] == a[n - 1]);
}
```

| Lunghezza del prefisso | Coppia confrontata | Coppie uguali |
|---:|---|---:|
| $0$ | nessuna | $0$ |
| $1$ | nessuna | $0$ |
| $2$ | $(3,3)$ | $1$ |
| $3$ | $(3,5)$ | $1$ |
| $4$ | $(5,5)$ | $2$ |
| $5$ | $(5,5)$ | $3$ |
| $6$ | $(5,1)$ | $3$ |

<div class="spiegazione">

Nella versione data ogni invocazione con $n\geq1$ esegue il passo ricorsivo, compresa quella con $n=1$. In quel record l’espressione `n - 2` è calcolata nel tipo senza segno `size_t`, quindi per l’aritmetica modulare vale `SIZE_MAX`. L’indice `a[n - 2]` cade allora fuori dal vettore e la lettura ha **comportamento non definito**. Con `-fsanitize=address` un programma di prova si arresta proprio in quella lettura, segnalando *stack-buffer-underflow*.

Un prefisso con meno di due elementi contiene zero coppie adiacenti, perciò il caso base corretto è `n < 2` e restituisce zero prima di qualsiasi accesso. Con questa base il passo ricorsivo si esegue solo per $n\geq2$, quindi gli indici $n-2$ e $n-1$ appartengono al prefisso.

In risalita il risultato aumenta di uno quando gli ultimi due elementi del prefisso coincidono. Questo accade per le lunghezze $2$, $4$ e $5$, che confrontano $(3,3)$, $(5,5)$ e $(5,5)$. Per le lunghezze $3$ e $6$ il confronto vale zero, quindi il conteggio resta invariato. La chiamata `equal_pairs(a, 6)` restituisce perciò $3$.

</div>
