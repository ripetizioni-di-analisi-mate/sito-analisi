## Esercizio 1

Scrivere la funzione `digit_sum` con il contratto indicato nel commento, per `unsigned` a 32 bit. Scrivere poi un `main` di prova con asserzioni che copra le classi e i confini della specifica.

```c
/* Pre: none. Post: returns the sum of the decimal digits of n,
   with digit_sum(0u) == 0u. */
unsigned digit_sum(unsigned n);
```

Una funzione che soddisfa il contratto e il relativo programma di prova sono i seguenti.

```c
#include <assert.h>
#include <limits.h>

unsigned digit_sum(unsigned n)
{
    unsigned sum = 0u;
    while (n > 0u) {
        sum += n % 10u;
        n /= 10u;
    }
    return sum;
}

int main(void)
{
    assert(digit_sum(0u) == 0u);
    assert(digit_sum(9u) == 9u);
    assert(digit_sum(10u) == 1u);
    assert(digit_sum(4095u) == 18u);
    assert(digit_sum(UINT_MAX) == 57u);
    return 0;
}
```

| Input | Classe o confine | Atteso |
| --- | --- | --- |
| `0u` | nessuna iterazione, estremo inferiore | $0$ |
| `9u` | ultimo valore con una cifra | $9$ |
| `10u` | primo valore con due cifre | $1$ |
| `4095u` | più cifre, fra cui uno zero | $18$ |
| `UINT_MAX` | estremo superiore, $4294967295$ | $57$ |

Con asserzioni attive il programma termina con codice $0$.

<div class="spiegazione">

Il resto `n % 10u` è l’ultima cifra decimale di `n` e la divisione `n /= 10u` la elimina, quindi ogni iterazione aggiunge una cifra a `sum`. Il ciclo termina, perché a ogni iterazione `n` positivo diminuisce strettamente e quindi vale $0$ dopo un numero finito di iterazioni. Per l’input $0$ il ciclo non esegue iterazioni, perciò la funzione restituisce il valore iniziale di `sum`, come richiede la postcondizione. Il più grande `unsigned` ha dieci cifre, quindi `sum` vale al più $9\cdot10=90$ e ogni addizione dà il valore matematico esatto.

Gli oracoli si ricavano dalla specifica. Per `UINT_MAX` si somma $4+2+9+4+9+6+7+2+9+5=57$. Le classi distinguono il ciclo senza iterazioni, una sola iterazione e più iterazioni. I confini $9$ e $10$ sono i due interi consecutivi in cui il numero di cifre passa da uno a due, mentre $0$ e `UINT_MAX` sono gli estremi del dominio.

</div>

## Esercizio 2

Scrivere la funzione `fits_sum` con il contratto indicato nel commento, in modo che nessuna operazione del corpo provochi overflow, anche quando la somma eccede l’intervallo di `int`. Scegliere poi i casi di test ai confini dei due limiti.

```c
/* Pre: none. Post: returns 1 if the mathematical sum a + b
   lies between INT_MIN and INT_MAX, 0 otherwise. */
int fits_sum(int a, int b);
```

Il corpo seguente confronta `a` con un limite calcolato senza sommare.

```c
#include <limits.h>

int fits_sum(int a, int b)
{
    if (b > 0) {
        return a <= INT_MAX - b;
    }
    return a >= INT_MIN - b;
}
```

| `a` | `b` | Atteso |
| --- | --- | --- |
| `INT_MAX` | $0$ | $1$ |
| `INT_MAX - 1` | $1$ | $1$ |
| `INT_MAX` | $1$ | $0$ |
| `INT_MIN` | $0$ | $1$ |
| `INT_MIN + 1` | $-1$ | $1$ |
| `INT_MIN` | $-1$ | $0$ |
| $0$ | `INT_MIN` | $1$ |
| $-1$ | `INT_MIN` | $0$ |

<div class="spiegazione">

Siano $M$ il valore di `INT_MAX` e $m$ il valore di `INT_MIN`. Con $b>0$ la somma può superare soltanto $M$, e la condizione $a+b\leq M$ equivale a $a\leq M-b$. Poiché $0<b\leq M$, la differenza $M-b$ è compresa fra $0$ e $M-1$, quindi `INT_MAX - b` è rappresentabile. Con $b\leq0$ la somma può scendere soltanto sotto $m$, e la condizione $a+b\geq m$ equivale a $a\geq m-b$. Poiché $m\leq b\leq0$, la differenza $m-b$ è compresa fra $m$ e $0$, quindi anche `INT_MIN - b` è rappresentabile. La funzione perciò non valuta mai la somma `a + b`.

Ogni limite ha due casi di confine, l’ultima coppia ammessa e la prima esclusa. Le ultime due righe mettono `INT_MIN` in `b`, dove `INT_MIN - b` vale $0$. Il programma di prova con queste otto asserzioni, compilato con `-fsanitize=undefined`, termina senza segnalazioni. Il tipo `long long` ha almeno $64$ bit, quindi in quel tipo la somma di due `int` è sempre rappresentabile. Il confronto con la somma calcolata in `long long` su tutte le $81$ coppie formate con `INT_MIN`, `INT_MIN + 1`, `INT_MIN + 2`, $-1$, $0$, $1$, `INT_MAX - 2`, `INT_MAX - 1` e `INT_MAX` non trova differenze.

</div>

## Esercizio 3

Scrivere le due funzioni con i contratti indicati nei commenti, con `days_in_month` che usa `is_leap` per febbraio. Un anno è bisestile se è divisibile per $400$, oppure se è divisibile per $4$ e non per $100$. Scrivere poi un `main` di prova e individuare l’asserzione che fallisce se `is_leap` omette la regola del $400$.

```c
/* Pre: 1583 <= year <= 9999.
   Post: returns 1 if year is a leap year, 0 otherwise. */
int is_leap(int year);

/* Pre: 1 <= month <= 12 and 1583 <= year <= 9999.
   Post: returns the number of days of that month in that year. */
int days_in_month(int month, int year);
```

Una soluzione con il programma di prova è la seguente.

```c
#include <assert.h>

int is_leap(int year)
{
    return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
}

int days_in_month(int month, int year)
{
    if (month == 2) {
        return 28 + is_leap(year);
    }
    if (month == 4 || month == 6 || month == 9 || month == 11) {
        return 30;
    }
    return 31;
}

int main(void)
{
    assert(days_in_month(2, 2023) == 28);
    assert(days_in_month(2, 2024) == 29);
    assert(days_in_month(2, 1900) == 28);
    assert(days_in_month(2, 2000) == 29);
    assert(days_in_month(4, 2023) == 30);
    assert(days_in_month(1, 2023) == 31);
    assert(days_in_month(12, 2023) == 31);
    return 0;
}
```

Senza `|| year % 400 == 0` il programma termina tramite `abort`, e la diagnostica scritta su `stderr` contiene il testo seguente.

```text
Assertion `days_in_month(2, 2000) == 29' failed.
```

<div class="spiegazione">

La precondizione di `days_in_month` contiene quella di `is_leap`, quindi la chiamata interna riceve sempre un anno ammesso. Per la postcondizione di `is_leap` il risultato vale $0$ o $1$, perciò l’espressione `28 + is_leap(year)` vale $28$ o $29$, come richiede il contratto per febbraio.

La regola dei bisestili divide gli anni in quattro classi, cioè non divisibili per $4$ ($2023$), divisibili per $4$ e non per $100$ ($2024$), divisibili per $100$ e non per $400$ ($1900$), divisibili per $400$ ($2000$). Le prime quattro asserzioni hanno un rappresentante per classe. Le altre tre provano i mesi di $30$ e di $31$ giorni, con i mesi $1$ e $12$ agli estremi del dominio. Senza la regola del $400$, l’anno $2000$ risulta divisibile per $100$ e la funzione restituisce $0$, quindi febbraio ha $28$ giorni e la quarta asserzione è falsa. Le prime tre classi danno invece gli stessi risultati della versione corretta.

</div>
