## Esercizio 1

Scrivere il prototipo da porre prima del chiamante per questa definizione di `rate`. Determinare poi il valore e il tipo del risultato di `rate(6, 2)`.

```c
long rate(int units, int band)
{
    return units * (band + 1L);
}
```

Il prototipo è `long rate(int units, int band);`. La chiamata calcola $6(2+1)=18$ e restituisce un `long`.

<div class="spiegazione">

I tipi del prototipo si leggono dalla definizione. Il tipo a sinistra del nome è `long`. Entrambi i parametri sono `int`, quindi gli argomenti $6$ e $2$ arrivano con il tipo già richiesto. Nel corpo il suffisso `L` rende il valore `1L` di tipo `long`, quindi `band + 1L` è calcolato in `long`. Poi anche `units` si converte a `long` per la moltiplicazione. I valori usati sono rappresentabili.

Si può verificare il calcolo come somma di tre addendi uguali a $6$. Per verificare anche il tipo, l’operatore C17 `_Generic` sulla chiamata selezionerebbe l’associazione `long`.

</div>

## Esercizio 2

Determinare il risultato di `classify(-5)`, `classify(0)` e `classify(19)`. Indicare quale `return` si esegue in ciascuna chiamata.

```c
int classify(int x)
{
    if (x < 0) {
        return -1;
    }
    if (x == 0) {
        return 0;
    }
    return 1;
}
```

| `x` | `return` eseguito | Risultato |
| --- | --- | --- |
| $-5$ | `return -1;` | $-1$ |
| $0$ | `return 0;` | $0$ |
| $19$ | `return 1;` | $1$ |

<div class="spiegazione">

Con $-5$ la prima condizione è vera, quindi si torna al chiamante prima di verificare la seconda. Per $0$ il primo confronto è falso e il secondo è vero. Per $19$ entrambi sono falsi, quindi resta l’ultima istruzione. I tre casi coprono tutti gli interi perché ogni intero ha esattamente uno dei segni ammessi dalla classificazione.

Come verifica si usa `(x > 0) - (x < 0)`. I confronti in C producono $0$ oppure $1$. Sui tre argomenti la differenza vale in ordine $-1$, $0$ e $1$, in accordo con i tre percorsi.

</div>

## Esercizio 3

La funzione `grade` riceve un punteggio intero da $0$ a $31$, dove $31$ indica il trenta e lode. La specifica richiede $0$ sotto $18$, $1$ da $18$ a $30$ e $2$ per $31$. Individuare l’input del dominio per cui la definizione seguente raggiunge la graffa finale, stabilire che cosa prevede il C17 per `int g = grade(31);` e correggere la funzione.

```c
int grade(int points)
{
    if (points < 18) {
        return 0;
    }
    if (points <= 30) {
        return 1;
    }
}
```

| `points` | Percorso | Risultato |
| --- | --- | --- |
| da $0$ a $17$ | primo `return` | $0$ |
| da $18$ a $30$ | secondo `return` | $1$ |
| $31$ | graffa finale | comportamento indefinito |

La compilazione con `gcc -std=c11 -Wall` produce questo avviso.

```text
warning: control reaches end of non-void function [-Wreturn-type]
```

La correzione aggiunge l’istruzione `return 2;` subito prima della graffa finale.

<div class="spiegazione">

Per $31$ entrambe le condizioni sono false, perché $31\geq18$ e $31>30$. L’esecuzione arriva quindi alla graffa che chiude il corpo senza eseguire un `return`. Il C17 stabilisce che, se si raggiunge la graffa finale di una funzione con tipo restituito diverso da `void` e il chiamante usa il valore della chiamata, il **comportamento è indefinito**. L’inizializzazione di `g` usa quel valore, perciò il programma non ha un risultato prevedibile per questo input. Il compilatore accetta la definizione e con l’avviso `-Wreturn-type` indica che esiste un percorso privo di `return`.

Dopo la correzione ogni intero del dominio raggiunge un’istruzione `return`. L’ultima istruzione si esegue soltanto quando le due condizioni precedenti sono false, cioè per $31$ nel dominio dato. I punteggi $17$, $18$, $30$ e $31$ sono i valori di confine delle tre fasce e la funzione corretta restituisce nell’ordine $0$, $1$, $1$ e $2$, in accordo con la specifica.

</div>
