## Esercizio 1

Il contratto di `clamp` richiede `lo <= hi`. Il risultato è l’estremo inferiore sotto la fascia, l’estremo superiore sopra la fascia e `x` nella fascia. Verificare precondizione e risultato per `clamp(-1, 0, 4)`, `clamp(4, 0, 4)` e `clamp(3, 5, 5)`.
```c
int clamp(int x, int lo, int hi)
{
    if (x < lo) {
        return lo;
    }
    if (x > hi) {
        return hi;
    }
    return x;
}
```

Le precondizioni sono vere perché $0\leq4$ e $5\leq5$. Nel primo caso vale $-1<0$, quindi il risultato è $0$. Nel secondo $x=4$ è nella fascia, quindi resta $4$. Nel terzo caso $3<5$ e il risultato è $5$.

<div class="spiegazione">

L’implementazione esamina prima se il valore è sotto la fascia. Quando ciò accade, conclude subito con `lo`. Negli altri due rami controlla se si è sopra `hi` e restituisce `x` per un input nella fascia. Con una fascia di ampiezza zero, l’unico intero consentito come risultato dalla postcondizione è l’estremo comune.

Una verifica valuta la formula $\min\{hi,\max\{lo,x\}\}$. I massimi intermedi sono $0$, $4$, $5$. I rispettivi minimi con gli estremi superiori $4$, $4$, $5$ danno $0$, $4$, $5$, in accordo con i rami.

</div>

## Esercizio 2

Su una macchina C17 con `INT_MAX` uguale a $32767$, trovare il massimo `n` non negativo ammesso per valutare `charge(n)` con tutte le operazioni in `int` rappresentabili.
```c
int charge(int n)
{
    return 11 + 7 * n;
}
```

Da $11+7n\leq32767$ segue

$$
n\leq\left\lfloor\frac{32767-11}{7}\right\rfloor=4679 .
$$

Il massimo è $4679$.

<div class="spiegazione">

Poiché `n` è non negativo, anche $7n$ è non negativo. Se la somma è al più $32767$, il prodotto, che è minore della somma, è sicuramente rappresentabile. La funzione matematica cresce con $n$, quindi basta delimitare l’ultimo input ammesso.

Per controllo, $7\cdot4679=32753$ e $11+32753=32764$, entro l’intervallo. Per l’intero successivo, il valore matematico è $32764+7=32771$. Supera il limite, perciò l’espressione C a quell’input non ha un risultato definito sulla macchina ipotizzata.

</div>

## Esercizio 3

Si considera un’implementazione C17 con `int` a 32 bit, quindi con `INT_MAX` uguale a $2147483647$. La funzione calcola l’area di una cornice larga $1$ attorno a un quadrato di lato $w\geq0$. Trovare il massimo `w` per cui tutte le operazioni sono rappresentabili, poi il massimo per la versione con corpo `return 4 * w + 4;`, che ha lo stesso valore matematico.

```c
int frame_area(int w)
{
    return (w + 2) * (w + 2) - w * w;
}
```

Per la prima versione serve $(w+2)^2\leq2147483647$. Poiché $46340^2=2147395600$ e $46341^2=2147488281$, si ottiene

$$
w+2\leq46340 \qquad\Longrightarrow\qquad w\leq46338 .
$$

Per la seconda versione serve $4w+4\leq2147483647$, da cui

$$
w\leq\left\lfloor\frac{2147483647-4}{4}\right\rfloor=536870910 .
$$

<div class="spiegazione">

Il valore matematico di entrambe le espressioni è $(w+2)^2-w^2=4w+4$. La prima versione calcola però il prodotto $(w+2)(w+2)$ prima della sottrazione, quindi il dominio dipende dal più grande risultato intermedio. Con $w\geq0$ i due prodotti sono non negativi e $w^2<(w+2)^2$, perciò basta che sia rappresentabile $(w+2)^2$. La differenza fra due valori non negativi rappresentabili è a sua volta rappresentabile. A $w=46338$ la funzione restituisce $185356$, un valore molto lontano da `INT_MAX`. A $w=46339$ il prodotto $46341\cdot46341$ supera `INT_MAX`, quindi si ha un **overflow con segno**, che è comportamento indefinito. Il programma compilato con `-fsanitize=undefined` segnala a quell’input `signed integer overflow: 46341 * 46341 cannot be represented in type 'int'`.

Nella seconda versione il più grande valore intermedio è il risultato stesso, perché $4w\leq4w+4$. Il limite sale quindi a $536870910$, dove la funzione restituisce $2147483644$. All’intero successivo il valore matematico è $2^{31}=2147483648$, che supera `INT_MAX`.

</div>
