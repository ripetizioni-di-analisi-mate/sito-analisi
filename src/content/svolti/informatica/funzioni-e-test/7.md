## Esercizio 1

Per pesi interi da $1$ a $12$ la consegna costa $5$ quando il peso è al massimo $7$ e $9$ negli altri casi. Usare i due input consecutivi che attraversano la soglia e individuare il difetto nella funzione.
```c
int shipping(int weight)
{
    return weight <= 8 ? 5 : 9;
}
```

| Peso | Atteso | Ottenuto |
| --- | --- | --- |
| $7$ | $5$ | $5$ |
| $8$ | $9$ | $5$ |

La soglia deve essere `weight <= 7`.

<div class="spiegazione">

Il peso $7$ è l’ultimo che soddisfa il requisito del prezzo minore. L’intero successivo è $8$, quindi l’oracolo richiede già $9$. Il corpo usa la disuguaglianza inclusiva con $8$ e sceglie ancora $5$ a quel peso.

Si può verificare l’unicità del difetto isolando gli insiemi che ricevono $5$. La specifica usa gli interi da $1$ a $7$ e il corpo usa quelli da $1$ a $8$. I due insiemi differiscono soltanto a $8$, quindi ogni altro input del dominio riceve il prezzo corretto.

</div>

## Esercizio 2

La funzione `keep` riceve interi da $0$ a $10$. Se `lo > hi` deve restituire $-1$. Altrimenti deve restituire `x` limitato alla fascia chiusa fra `lo` e `hi`. Usare `keep(5, 4, 4)` come caso di confine, poi correggere la condizione.
```c
int keep(int x, int lo, int hi)
{
    if (lo >= hi) {
        return -1;
    }
    if (x < lo) {
        return lo;
    }
    if (x > hi) {
        return hi;
    }
    return x;
}
```

Con `lo == hi` vale $4=4$, perciò la fascia contiene $4$. L’atteso è $4$ e il codice restituisce $-1$. La condizione corretta è `lo > hi`.

<div class="spiegazione">

La fascia è valida perché il contratto esclude soltanto l’ordine strettamente invertito. Poiché $5>4$, la limitazione deve usare l’estremo superiore $4$. Nel codice fornito il controllo iniziale include anche l’uguaglianza. Quel test restituisce $-1$ prima di applicare i rami di limitazione.

Per verificare la correzione si confronta il caso con `keep(5, 5, 4)`. Lì $5>4$ nell’ordine degli estremi e $-1$ è dovuto. Con la condizione `lo > hi` la fascia degenere arriva invece alla limitazione e produce $4$.

</div>

## Esercizio 3

Per una sosta di durata intera da $0$ a $240$ minuti, la specifica richiede $0$ fino a $15$ minuti, $3$ da $16$ a $90$ minuti e $5$ da $91$ a $240$ minuti. Costruire l’insieme dei valori di confine, confrontare gli attesi con i risultati della funzione e correggere tutti i difetti.
```c
int parking(int minutes)
{
    if (minutes < 15) {
        return 0;
    }
    if (minutes <= 91) {
        return 3;
    }
    return 5;
}
```

| Minuti | Atteso | Ottenuto |
| --- | --- | --- |
| $0$ | $0$ | $0$ |
| $15$ | $0$ | $3$ |
| $16$ | $3$ | $3$ |
| $90$ | $3$ | $3$ |
| $91$ | $5$ | $3$ |
| $240$ | $5$ | $5$ |

Le condizioni corrette sono `minutes <= 15` e `minutes <= 90`.

<div class="spiegazione">

La specifica cambia regola fra $15$ e $16$ e fra $90$ e $91$, quindi le due coppie di interi consecutivi sono i confini interni. Gli estremi $0$ e $240$ sono i confini del dominio. Il primo confronto del codice è stretto e lascia $15$ fuori dalla fascia gratuita, perciò a $15$ si ottiene $3$ al posto di $0$. Il secondo confronto include anche $91$ nella fascia intermedia, perciò a $91$ si ottiene $3$ al posto di $5$. I due difetti spostano le soglie in versi opposti e ciascuno è rilevato da un solo caso della tabella.

I rappresentanti di classe $8$, $50$ e $150$ danno $0$, $3$ e $5$, valori che coincidono con gli attesi. Un piano con un solo rappresentante interno per classe non rileva quindi nessuno dei due difetti. Il confronto della funzione originale con l’oracolo su tutti gli interi da $0$ a $240$ trova esattamente due input discordanti, $15$ e $91$.

</div>
