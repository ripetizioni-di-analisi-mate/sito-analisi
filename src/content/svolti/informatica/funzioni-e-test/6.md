## Esercizio 1

Un intero `score` appartiene al dominio da $0$ a $30$. La specifica assegna $2$ fino a $7$, $4$ da $8$ a $20$ e $6$ da $21$ in poi. Costruire una prova per classe e calcolare gli attesi, usando i rappresentanti $3$, $14$ e $24$.
```c
int tier(int score)
{
    if (score <= 7) {
        return 2;
    }
    if (score <= 20) {
        return 4;
    }
    return 6;
}
```

| Interi della classe | Rappresentante | Atteso |
| --- | --- | --- |
| $[0,7]$ | $3$ | $2$ |
| $[8,20]$ | $14$ | $4$ |
| $[21,30]$ | $24$ | $6$ |

<div class="spiegazione">

Le tre fasce sono non vuote, disgiunte e coprono gli interi del dominio. Ciascun rappresentante sta in una fascia distinta, quindi la copertura è completa. Per l’oracolo si legge la fascia a cui appartiene l’input. Per esempio $14$ soddisfa $8\leq14\leq20$, quindi l’atteso è $4$.

Come verifica separata, per $14$ il primo confronto del codice è falso e il secondo è vero, perciò si raggiunge proprio `return 4;`. Per $3$ è vero il primo confronto, mentre per $24$ sono entrambi falsi. I tre rami concordano con gli attesi.

</div>

## Esercizio 2

Due ingressi interi `x` e `y` sono entrambi tra $-10$ e $10$. La specifica distingue il segno negativo dal caso non negativo per ciascun ingresso. Stabilire il minimo numero di prove per coprire le combinazioni e calcolare gli attesi dei quattro casi scelti usando la funzione.
```c
int zone(int x, int y)
{
    return 2 * (x >= 0) + (y >= 0);
}
```

| `x` | `y` | Atteso |
| --- | --- | --- |
| $-2$ | $-3$ | $0$ |
| $-2$ | $3$ | $1$ |
| $2$ | $-3$ | $2$ |
| $2$ | $3$ | $3$ |

Servono $4$ prove.

<div class="spiegazione">

Ogni ingresso ha due classi e tutte le combinazioni sono possibili nel dominio. Le classi delle coppie sono dunque $2\cdot2=4$. Ogni coppia appartiene a una sola classe, quindi meno di $4$ prove lascerebbero una combinazione scoperta. Le quattro mostrate raggiungono il minimo. Per `x` non negativo si aggiunge $2$, per `y` non negativo si aggiunge $1$.

Per controllo si leggono quegli indicatori come due bit. Gli indici dei casi in tabella sono i valori binari $00$, $01$, $10$ e $11$, che corrispondono agli attesi da $0$ a $3$.

</div>

## Esercizio 3

La funzione `fee` riceve un peso intero da $1$ a $30$ e un indicatore `express` uguale a $0$ o a $1$. La tariffa base è $4$ fino a peso $10$ e $7$ da $11$ a $30$. La spedizione espressa aggiunge $5$ alla base fino a peso $20$; con `express` uguale a $1$ e peso maggiore di $20$ la funzione restituisce $-1$. Determinare le classi della specifica, il numero minimo di prove e gli attesi, poi stabilire se bastano le quattro combinazioni di fascia di peso e di `express`.
```c
int fee(int weight, int express)
{
    int base = weight <= 10 ? 4 : 7;
    if (express) {
        if (weight > 20) {
            return -1;
        }
        return base + 5;
    }
    return base;
}
```

| Peso | `express` | Rappresentante | Atteso |
| --- | --- | --- | --- |
| $[1,10]$ | $0$ | $(6,0)$ | $4$ |
| $[11,30]$ | $0$ | $(25,0)$ | $7$ |
| $[1,10]$ | $1$ | $(6,1)$ | $9$ |
| $[11,20]$ | $1$ | $(15,1)$ | $12$ |
| $[21,30]$ | $1$ | $(25,1)$ | $-1$ |

Servono $5$ prove.

<div class="spiegazione">

Con `express` uguale a $0$ conta solo la tariffa base, quindi le classi sono le due fasce di peso. Con `express` uguale a $1$ la soglia $20$ si aggiunge alla soglia $10$, perciò i pesi si dividono in tre fasce. Le cinque classi sono non vuote, disgiunte e coprono il dominio, quindi servono almeno $5$ chiamate. Per esempio, per $(15,1)$ la base è $7$ e la spedizione espressa è ammessa, perciò l’atteso è $7+5=12$.

Le quattro combinazioni di fascia di peso e di `express` formano una partizione meno fine. La combinazione con peso da $11$ a $30$ ed `express` uguale a $1$ contiene due regole diverse, poiché $(15,1)$ richiede $12$ e $(25,1)$ richiede $-1$. Un piano con quattro prove ha un solo rappresentante di quell’insieme, quindi lascia senza prova una delle due regole. Le cinque chiamate della tabella restituiscono $4$, $7$, $9$, $12$ e $-1$, in accordo con gli attesi.

</div>
