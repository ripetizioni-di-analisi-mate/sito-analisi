## Esercizio 1

Calcolare `score(4)`, distinguendo le due entità chiamate `n`.

```c
int score(int n)
{
    int result = n;
    {
        int n = result + 2;
        result += n;
    }
    return result - n;
}
```

All’ingresso `result` vale $4$. Nel blocco interno il nuovo `n` vale $4+2=6$, quindi `result` diventa $4+6=10$. Nel ritorno è visibile il parametro, da cui $10-4=6$.

<div class="spiegazione">

L’inizializzazione di `result` precede il blocco annidato e legge il parametro. La dichiarazione interna introduce un oggetto con visibilità limitata al blocco. Quindi nell’addizione si usa il suo valore $6$. Uscendo dal blocco, l’identificatore `n` torna a designare il parametro di valore $4$.

Per verificare la risoluzione dei nomi, si chiami `local` il solo oggetto interno. Per un argomento $q$ nel dominio delle operazioni, la formula diventa $q+(q+2)-q=q+2$. In particolare a $q=4$ si ottiene $6$.

</div>

## Esercizio 2

In una nuova esecuzione si valutano nell’ordine `stamp(1)`, `stamp(0)` e `stamp(-2)`, in tre istruzioni distinte. Determinare i risultati.

```c
int stamp(int step)
{
    static int total = 2;
    int local = 3;
    local += step;
    total += local;
    return total;
}
```

| `step` | `local` aggiornato | `total` restituito |
| --- | --- | --- |
| $1$ | $4$ | $6$ |
| $0$ | $3$ | $9$ |
| $-2$ | $1$ | $10$ |

<div class="spiegazione">

`total` ha durata statica e parte da $2$ prima della prima chiamata. Ogni chiamata inizializza invece il proprio `local` a $3$, quindi gli incrementi di `total` sono $3+1$, $3+0$ e $3-2$. La seconda chiamata riparte da $6$ e la terza da $9$, perché il solo `total` conserva lo stato.

Il controllo cumulativo dà $2+(4+3+1)=10$ al termine. Le differenze tra risultati consecutivi sono $9-6=3$ e $10-9=1$. Coincidono con gli ultimi due incrementi, quindi la sequenza rispetta l’inizializzazione automatica a ogni chiamata.

</div>

## Esercizio 3

In una nuova esecuzione il programma seguente chiama `next_id` tre volte dentro un ciclo. Determinare l’output e indicare, in ciascuna istruzione, quale oggetto designa il nome `count`.

```c
#include <stdio.h>

int next_id(int base)
{
    static int count = 0;
    int offset = 1;
    count += offset;
    {
        int count = base * 10;
        offset = count;
    }
    return offset + count;
}

int main(void)
{
    for (int i = 1; i <= 3; i++) {
        printf("%d\n", next_id(2 * i - 1));
    }
    return 0;
}
```

| `i` | `base` | `count` statico | `count` interno | Valore restituito |
| --- | --- | --- | --- | --- |
| $1$ | $1$ | $1$ | $10$ | $11$ |
| $2$ | $3$ | $2$ | $30$ | $32$ |
| $3$ | $5$ | $3$ | $50$ | $53$ |

Il programma stampa le tre righe seguenti.

```text
11
32
53
```

<div class="spiegazione">

Il primo `count` è dichiarato `static`, quindi ha durata statica, viene inizializzato a $0$ una sola volta prima dell’avvio e conserva il valore fra le chiamate. La variabile `offset` ha durata automatica, perciò a ogni chiamata riparte da $1$ e l’istruzione `count += offset;` aumenta di $1$ il contatore statico. Nel blocco interno la dichiarazione `int count = base * 10;` introduce un nuovo oggetto, che **oscura** il contatore statico fino alla graffa di chiusura del blocco. L’assegnazione `offset = count;` legge quindi l’oggetto interno e copia in `offset` il valore di `base * 10`. Dopo il blocco il nome `count` designa di nuovo il contatore statico, perciò il `return` somma `base * 10` e il numero d’ordine della chiamata.

Nella chiamata con indice $i$ l’argomento vale $2i-1$ e il contatore statico vale $i$. Il valore restituito è dunque $10(2i-1)+i=21i-10$, che per $i=1,2,3$ dà $11$, $32$ e $53$. Con l’opzione `-Wshadow`, GCC segnala che la dichiarazione interna oscura una variabile locale precedente.

</div>
