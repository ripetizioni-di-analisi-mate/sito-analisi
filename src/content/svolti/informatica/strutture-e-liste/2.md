## Esercizio 1

Calcolare `result`. Tutti i nodi sono oggetti automatici vivi. Il frammento usa `<stddef.h>`.

```c
struct Node { int key; struct Node *next; };
struct Node tail = {4, NULL};
struct Node middle = {13, &tail};
struct Node first = {10, &middle};
struct Node *head = &first;
int result = head->next->key - head->next->next->key;
```

Seguendo la catena da `head` si leggono le chiavi $10$, $13$, $4$. Il primo operando della differenza è $13$ e il secondo è $4$, perciò `result` vale $9$.

<div class="spiegazione">

`head` designa `first`. Nel primo operando si percorre un collegamento, che da `first` porta a `middle`. Il membro intero letto è quindi $13$. Nel secondo operando i collegamenti sono due. Il primo conduce ancora a `middle` e il secondo a `tail`, che contiene $4$. Entrambi i percorsi terminano a nodi vivi e la sottrazione è rappresentabile in `int`.

Per il controllo si parte dalle inizializzazioni dei puntatori e si sostituisce ogni indirizzo. Si ottengono `head->next == &middle` e `head->next->next == &tail`. Sostituendo le chiavi dei due oggetti si ritrova la differenza. Sommando all’esito l’ultima chiave, $9+4=13$ ricostruisce la chiave del nodo intermedio.

</div>

## Esercizio 2

Determinare `count` e `sum`. Il frammento usa `<stddef.h>`.

```c
struct Node { int key; struct Node *next; };
struct Node d = {7, NULL};
struct Node c = {0, &d};
struct Node b = {7, &c};
struct Node a = {-2, &b};
int count = 0, sum = 0;
for (struct Node *p = &a; p != NULL; p = p->next) {
    if (p->key >= 5) {
        ++count;
        sum += p->key;
    }
}
```

| Nodo visitato | Chiave | `count` | `sum` |
|---|---|---|---|
| `a` | $-2$ | $0$ | $0$ |
| `b` | $7$ | $1$ | $7$ |
| `c` | $0$ | $1$ | $7$ |
| `d` | $7$ | $2$ | $14$ |

<div class="spiegazione">

I collegamenti portano nell’ordine al nodo iniziale e poi ai suoi tre successori. La condizione sui dati è controllata nel corpo per ogni nodo vivo. Solo le due chiavi uguali a $7$ soddisfano la soglia. I nodi che le contengono hanno identità distinte e vengono quindi contati in due iterazioni separate. Dopo `d` l’aggiornamento porta il puntatore a nullo e chiude il ciclo.

Come verifica si considera la lista delle chiavi che passano il filtro. Contiene due occorrenze di $7$, quindi la sua lunghezza è $2$ e la sua somma è $2\cdot7=14$. Si possono inoltre contare due visite escluse, a `a` e `c`. Con le due incluse si ricavano tutte e quattro le visite previste.

</div>

## Esercizio 3

Una *discesa* è un nodo la cui chiave supera la chiave del successore. Determinare `drops`, `last` e `pos` alla fine del ciclo; `last` è la posizione dell’ultima discesa, contata da zero. I nodi sono oggetti automatici vivi e il frammento usa `<stddef.h>`.

```c
struct Node { int key; struct Node *next; };
struct Node n5 = {6, NULL};
struct Node n4 = {1, &n5};
struct Node n3 = {4, &n4};
struct Node n2 = {4, &n3};
struct Node n1 = {9, &n2};
struct Node n0 = {5, &n1};
int drops = 0, last = -1, pos = 0;
for (const struct Node *p = &n0; p != NULL; p = p->next) {
    if (p->next != NULL && p->key > p->next->key) {
        ++drops;
        last = pos;
    }
    ++pos;
}
```

| `pos` all’ingresso | Chiave | Chiave del successore | Discesa | `drops` | `last` |
|---|---|---|---|---|---|
| $0$ | $5$ | $9$ | no | $0$ | $-1$ |
| $1$ | $9$ | $4$ | sì | $1$ | $1$ |
| $2$ | $4$ | $4$ | no | $1$ | $1$ |
| $3$ | $4$ | $1$ | sì | $2$ | $3$ |
| $4$ | $1$ | $6$ | no | $2$ | $3$ |
| $5$ | $6$ | nullo | no | $2$ | $3$ |

Alla fine `drops` vale $2$, `last` vale $3$ e `pos` vale $6$.

<div class="spiegazione">

Il ciclo visita i sei nodi da `n0` a `n5`, e `pos` conta le visite già concluse. La condizione legge a ogni iterazione la chiave del nodo corrente e quella del successore. La prima discesa è in posizione $1$, dove $9>4$. I due nodi consecutivi di chiave $4$ non formano una discesa, perché il confronto `>` è stretto. La seconda discesa è in posizione $3$, dal secondo $4$ al nodo di chiave $1$, perciò `last` riceve $3$.

All’ultima iterazione `p` designa `n5` e `p->next` è nullo. Il primo operando di `&&` è falso, quindi per la **valutazione in cortocircuito** il secondo operando non viene valutato. L’espressione `p->next->key` richiederebbe l’indirezione di un puntatore nullo, che ha comportamento non definito. L’ordine dei due operandi esclude perciò quell’accesso, e dopo sei incrementi `pos` coincide con la lunghezza della lista.

</div>
