## Esercizio 1

Un browser riceve `403` dal server a cui ha inviato una richiesta. Stabilire che cosa si può concludere e se il codice permette da solo di conoscere la regola che ha causato il rifiuto.

Il server ha compreso la richiesta e rifiuta di soddisfarla. Lo stato `403` da solo non identifica la regola applicata.

- Classe: la prima cifra è $4$, quindi l'esito riguarda la richiesta del client.
- Fasi concluse: risoluzione del nome, collegamento, invio della richiesta e ricezione della risposta.
- Informazione mancante: la regola del server che ha prodotto il rifiuto.

<div class="spiegazione">

Un esito `403` appartiene al protocollo HTTP. Il browser ha quindi ricevuto una risposta da un interlocutore applicativo. Il significato del codice è il rifiuto di soddisfare una richiesta compresa. Il codice non descrive quale regola il server abbia usato per decidere. Il rifiuto può dipendere, per esempio, dall'indirizzo di provenienza, dai permessi dell'utente o dalla configurazione della risorsa. Se il server richiedesse un'autenticazione non ancora fornita, il codice previsto sarebbe `401 Unauthorized`. Per ricavare quella informazione si possono leggere il corpo della risposta, se presente, o i dati dell'applicazione. Una difficoltà a raggiungere il server a livello IP non produrrebbe, da sola, il codice HTTP osservato.

</div>

## Esercizio 2

Dopo che DNS e TCP sono riusciti, il browser rifiuta un certificato valido per `laboratorio.example` quando l'URL chiede `registro.example`. L'applicazione usa HTTPS su TCP e il browser interrompe lo scambio. Individuare la fase e stabilire se si può osservare uno stato HTTP.

Fallisce la verifica dell'identità TLS. Il browser può interrompere lo scambio prima di inviare la richiesta HTTP e quindi senza ricevere uno stato HTTP.

| Fase | Esito |
| --- | --- |
| DNS | indirizzo ottenuto |
| TCP | connessione aperta |
| TLS | `registro.example` assente fra i nomi del certificato |
| HTTP | richiesta non inviata |

<div class="spiegazione">

L'indirizzo è stato trovato e la connessione TCP è stata aperta, quindi le prime due fasi hanno un esito noto. Per stabilire TLS il browser controlla che il nome richiesto sia compreso fra quelli del certificato. Il certificato disponibile è valido per `laboratorio.example`, che è un nome diverso da `registro.example`. Il controllo del nome fallisce, quindi il browser non considera autenticato il server anche se data di validità e catena fossero corrette. La richiesta HTTP sarebbe inviata sul canale protetto dopo questa verifica. Se il browser chiude lo scambio a questo punto, il server non riceve quella richiesta HTTP e non invia uno stato in risposta.

</div>

## Esercizio 3

Una richiesta `GET /orario` riceve `302` con `Location: /orario-nuovo`. Il browser segue il nuovo percorso sullo stesso host, riusando la connessione. La seconda risposta è `500`. Descrivere le due risposte e indicare dove si manifesta il problema conclusivo.

- `302` indica un reindirizzamento temporaneo a `/orario-nuovo`.
- `500` indica un errore interno del server nel tentativo di elaborare la seconda richiesta.

| Richiesta | Risposta | Classe |
| --- | --- | --- |
| `GET /orario` | `302`, `Location: /orario-nuovo` | 3xx, reindirizzamento |
| `GET /orario-nuovo` | `500` | 5xx, errore del server |

<div class="spiegazione">

Il primo stato e l'intestazione `Location` forniscono un percorso diverso. Poiché il browser segue il reindirizzamento, invia un'altra richiesta per quel percorso. Il valore di `Location` è un percorso relativo, perciò il browser lo completa con lo schema e il nome della pagina originale e ottiene un indirizzo sullo stesso host. Il caso specifica che la connessione rimane disponibile, quindi può usare lo stesso canale già stabilito. Il secondo codice ha prima cifra $5$, quindi è una risposta HTTP della classe 5xx, cioè degli errori del server. In particolare `500` indica una condizione inattesa nell'elaborazione del server. Il reindirizzamento è arrivato e la seconda richiesta ha ricevuto una risposta. Il problema osservato riguarda l'elaborazione della seconda risorsa.

</div>
